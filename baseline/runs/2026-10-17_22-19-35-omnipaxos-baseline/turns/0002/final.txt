Most serious findings:

- **Delta snapshot synchronization corrupts snapshot state.** [internal_storage.rs](/home/nitro/Desktop/consensus-assurance/baseline/runs/2026-10-17_22-19-35-omnipaxos-baseline/work/omnipaxos/src/storage/internal_storage.rs:318) sets the leader’s new decided index before constructing the receiver’s delta-snapshot base, causing obsolete accepted entries to be merged into the snapshot. The deterministic reproduction produced `[1,2,3,6,7,4,5]` instead of `[1,2,3,4,5]`: [audit_sync_delta_snapshot.rs](/home/nitro/Desktop/consensus-assurance/baseline/runs/2026-10-17_22-19-35-omnipaxos-baseline/work/omnipaxos/tests/audit_sync_delta_snapshot.rs).
- **Sparse node IDs permanently block trimming.** Unconfigured leader-state slots remain at zero, so a cluster using IDs `[1,10,20]` cannot trim even after every configured node decides index 3: [audit_sparse_ids_trim.rs](/home/nitro/Desktop/consensus-assurance/baseline/runs/2026-10-17_22-19-35-omnipaxos-baseline/work/omnipaxos/tests/audit_sparse_ids_trim.rs).
- **Epoch ordering and validation are unsafe.** `Ballot::cmp` ignores `config_id`, allowing an older configuration’s Prepare to replace a current promise; reconfiguration also accepts a non-increasing configuration ID.
- **Runtime liveness/cursor defects.** Compacted decided subscriptions repeat entries, and filling the event channel blocks the actor’s entire processing loop.
- **Additional validated defects.** Configuration accepts node ID 0 and later panics with subtraction overflow; `flush_batch_tick_timeout = 0` never flushes; feature unification with `omnipaxos/unicache` breaks `omnipaxos_runtime` compilation.
