Added F6; the audit now contains six confirmed, reproducible findings in [report.md](/home/nitro/Desktop/consensus-assurance/baseline/runs/2026-10-18_11-44-44-openraft-baseline/work/report.md).

| Severity | Finding |
|---|---|
| High | Snapshot install persists the log purge before the state-machine install completes; a crash leaves an unrecoverable state and restart panics. |
| Medium | Documented-valid `PartialSuccess(None)` panics the leader in debug builds. |
| Low/Medium | `purge_batch_size = 0` underflows at `calc_purge_upto()`'s `purge_end - 1`. |
| Medium | `snapshot_max_chunk_size = 0` makes `Chunked::send_snapshot()` send zero-byte chunks forever. |
| Low/Medium | Blocking `add_learner()` returns `Ok` after a leadership change while the learner is still not caught up. |
| Low/Medium | `heartbeat_interval = 0` is accepted and leaves the tick loop unthrottled. |

The new F6 evidence: `Config::build` accepts `--heartbeat-interval=0`, and the tick emitter with a zero interval emitted 77 ticks in 100 ms—about 38 times a normal 50 ms interval—while heartbeat RPCs would use a zero timeout:

```
zero-interval ticks in 100ms: 77
```

The test is `core::tick::tests::audit_zero_interval_busy_loops`, runnable with `cargo test -p openraft --lib audit_zero_interval_busy_loops -- --nocapture`. The report recommends rejecting zero (or clamping it); `enable_heartbeat = false` is the existing way to disable heartbeats.
