**F2 — the admin `snapshot` command's rate limit is 1000× looser than documented.** [Commands.java:766](/home/nitro/Desktop/consensus-assurance/baseline/runs/2026-10-17_01-10-40-zookeeper-baseline/work/zookeeper-server/src/main/java/org/apache/zookeeper/server/admin/Commands.java:766) builds the limiter as `new RateLimiter(1, rateLimiterInterval, TimeUnit.MICROSECONDS)`, while the sibling `RestoreCommand` at line 646 uses `TimeUnit.MILLISECONDS`. `rateLimiterInterval` is read from `zookeeper.admin.rateLimiterIntervalInMS` (default `300000`), and `zookeeperAdmin.md` documents that property as "The time interval for rate limiting admin command to protect the server. Defaults to 5 mins." `RateLimiter` converts via `unit.toMillis(...)`, so the snapshot endpoint effectively allows one request per **300 ms** instead of 5 minutes: an authenticated admin client can force whole-datatree snapshot streaming several times a second, defeating the documented protection. Conditions: admin endpoint enabled, `serializeLastProcessedZxid` enabled, `Perms.ALL` on `/`.
