Root cause of the earlier failure, confirmed: `fuzzy/transport.go`'s `sendRPC` decodes only three request types (`TimeoutNow`, `RequestVote`, `AppendEntries`) and has **no case for `*RequestPreVoteRequest`**, so `rpc.Command` stays nil and `raft.checkRPCHeader` rejects pre-vote RPCs. The log carries 784 `unexpected request type: type="*raft.RequestPreVoteRequest"` warnings. Pre-vote became on-by-default in raft 1.7.0 while this harness module is pinned to raft v1.2.0-era APIs, so the shipped `fuzzy` module cannot drive the shipped library with default settings — a submodule/tooling version mismatch, not a raft correctness defect, and unrelated to my store substitution.

Confirming experiment: setting `config.PreVoteDisabled = true` in the scratch harness makes `TestRaft_NoIssueSanity` pass in 2.4 s with zero dropped RPCs (`audit-evidence/fuzzy_sanity_noprevote.log`), isolating the cause to the missing pre-vote case.
