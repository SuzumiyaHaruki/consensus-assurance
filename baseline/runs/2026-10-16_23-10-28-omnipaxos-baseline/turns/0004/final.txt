**Finding 2 — `subscribe_decided` re-delivers log positions when a subscription starts below `compacted_idx`**

The actor's cursor (`DecidedSub::next_idx`, `push_to_sub`, `push_to_all_subs`) advances once per *delivered item*, but `InternalStorage::read` returns a **single** `LogEntry::Snapshotted`/`Trimmed` item standing for the whole compacted prefix. So a read starting below the compacted index covers more log positions than it has items, the cursor lands behind what it already delivered, and the next tick re-reads from there. Only reads starting at or after `compacted_idx` are unaffected.

Executed evidence ([audit_subscription_compaction_test.rs](/home/nitro/Desktop/consensus-assurance/baseline/runs/2026-10-16_23-10-28-omnipaxos-baseline/work/omnipaxos_runtime/tests/audit_subscription_compaction_test.rs), which hand-drives a two-node *core* cluster with `batch_size = 1` and never calls `append_notify`, then hands the snapshot'ed instance to `spawn_actor`):

- fully compacted (compacted = decided = 6), subscribe from 0: the same `Snapshotted(trimmed_idx=6)` delivered **six times**, once per tick;
- partially compacted (compacted = 3, decided = 6): `Snapshotted(3), Decided(103), Decided(104), Decided(105), Decided(104), Decided(105)` — entries 104 and 105 delivered **twice**.

Bit-identical across runs (`notes/repro_subs_determinism.log`). This also closes the reachability question I had left open last turn: the actor has no trim command, but compaction happens on the core instance *before* `spawn_actor` via the public `OmniPaxos::snapshot(idx, local_only)` (legal on a follower too), so a node that snapshots its recovered log and then starts its actor is an ordinary use — and its subscribers see duplicates. Distinct from finding 1: different subsystem and symptom, and it reproduces with no batching and no `append_notify`.

Checked alternatives: not the core log (the harness asserts both nodes decided exactly the six entries once, and the duplicates are re-reads of consumed positions); not the collapsed prefix item by itself (that is `read`'s documented shape — the defect is the actor counting it as one position).
