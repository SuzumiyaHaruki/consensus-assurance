# Source-grounded consensus investigation

Use the authoritative activity_roles in research.json: two core relationships, supported by five implementation mechanisms. A question may concern either core relationship. Never infer relevance from a filename, protocol label or an Activity tag. Establish actual ownership, context, support and consumption from source; protocols need not have a leader, log, global term, self-vote or fixed majority.

Start with the smallest useful target profile and partial Behavior/Fact map. A Behavior describes an actual owner and trigger, guards, reads/writes, effects, asynchronous boundaries and alternatives. A Fact states the weakest assertion the implementation actually establishes for an identified object and context. Produces/consumes edges are authoritative; reverse indexes are derived. Unread producers, consumers and unmapped Surfaces may remain unknown. Exploratory reading and execution require neither a fabricated Fact nor an obligation.

Select one principal Fact lifecycle and a concrete A1/A2 relationship. question.behavior_ids names direct establish/consume/invalidate/reinterpret roles. supporting_behavior_ids separately names sourced prehistory, context or consequence support and why it matters. An A6 implementation can support A1 through a concrete cross_activity_effects explanation; do not relabel it. Keep normative statements, code observations, test assertions, assumptions and hypotheses separate. Source identity does not prove meaning.

Distinguish five gaps using existing question, grounding, scope and feedback: applicable requirement; actual producer; initial prefix; same-execution history and permitted faults; observed endpoint. Say which affects the current proposition. A constructor call or validated configuration alone does not prove the relevant initial state. Separate calls from reply production, delivery, registration and consumption. Two independent executions are not one history. Explain whether protective workers, negative responses and alternate paths run, are finitely delayed, or are omitted with a scoped noninterference argument.

Source explanation can close the stated suspicion without execution Evidence. Derive an obligation only from an applicable source expectation and a discriminating comparison, not from the observed difference itself. Local obligations can precede broader history or consequence checks when their conditional scope is explicit. An API violation need not imply an application failure; an incorrect-decision question cannot be completed by an unrelated interface mismatch.

Continue the same Candidate and Unit when the proposition is unchanged. Choose the one assumption most limiting that proposition and explain how the next check replaces or bounds it: real producer, actual context transition, public completion, or a justified startup prefix. Preserve each old artifact and condition. New independent scenarios can share a Unit; changed normative meaning uses F2, changed behavioral scope uses F3, and a changed executed checker requires an encoding revision, fresh execution and review. Do not replace the next discriminator with more disclaimers or manufacture a new source ID to show progress.

Use feedback.answered and its accepted references to update current unknowns or answer contrary evidence; history retains the old wording. Explain the evidence, answered portion and remaining gap once. Existing execution, review or decision ownership can supply sources. A wording edit alone is not research progress. Knowledge about another consumer need not invalidate an old local witness; a newly discovered interfering writer, invalidator or changed Fact meaning must state its impact and reconnect affected current scope. Do not silently treat every new producer as harmless.

Use native search, reading, editing and permitted local feedback freely inside the authorized snapshot/draft boundary. Submit complete products when ready. Direct experiments serve controllable local comparisons; optional models serve legal prefixes, critical interleavings or distinguishing assumptions. Tool choice follows the discriminator, never a quota. Prefer repairing a concrete current check over unrelated inventory work, but explain a necessary switch without repeating all saved work.

Evidence of one complete violation and completion of all required scenarios are different quantifiers. Independent partial operations remain visible without erasing a valid witness; ambiguity affecting its own identity or history still blocks it. A passing process, model holds, provisional review, absent issues or locally checked Unit is not overall correctness. Stop honestly within authorization and budgets; the controller records pending work even if the last explanation is incomplete.

Keep Activity → Behavior → Fact → Candidate → Obligation → execution/review → understanding feedback as the research architecture. A finite execution witness is validation, not a replacement map. At natural handoffs, put reusable sourced support knowledge in AuditSpec and retain candidate-specific hypotheses separately. A1/A2 lead selection; recovery, membership, application, history and interface responsibilities remain substantive support.

A constructed test can establish reachability when legal inputs and real implementation workers generate the relevant prefix and correlated result. Directly assigning a critical protocol state supplies only a conditional premise; ValidateConfig is not an election or recovery history. Replace a specific tractable assumption using a real producer, allowed prefix, context transition or public completion. A prefix need not start at process birth when its validity and noninterference are justified. Preserve protective paths; do not stop at another generic reachability disclaimer.

Consensus safety has priority, with liveness under explicit environment/fault/scheduling or deadline assumptions. A sourced related implementation-contract violation can be complete in its own scope without inventing a stronger consensus consequence. General code issues stay secondary. Finite tool timeout alone proves neither holds nor general liveness failure.

After each local disposition return to the current map/frontier: unresolved valuable family discriminator, a new independent question, actual mapped relationships not covered by this result, or sourced unexpanded core/support surfaces. Compare value, protective alternatives, required evidence and how each outcome changes understanding. No activity rotation, discovery quota or exhaustive lifecycle cross-product is required. Local pause is a handoff, not run termination. Independent new runs need not import previous discoveries; directed historical capability cases never become default answers.
