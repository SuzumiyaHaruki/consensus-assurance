EXPERIMENT AND OBSERVATION METHOD Locate observation points at actual implementation effects, distinguishing operation start, internal completion, and externally effective return. Emit actual fields at those points. Associate prerequisites by participant, operation and context, not just event names. State what legal inputs and dependency contracts make the schedule admissible. A replay plan may add observation mapping and monitors without changing model behavior or properties. Missing fields remain missing. A compatible partial trace is not a violation. For model replay, the same finite property description must generate the model checker and monitor before automatic confirmation is possible; an arbitrary matching ID is insufficient. A direct check has no model checker or calibration: its saved shared property must match the monitor, and actual oracle code must be reviewed against the selected obligation and sources. Unreviewed or disputed correspondence cannot confirm a defect. Use the bounded observable property forms advertised in the schema. Unsupported direct properties require an explicit gap or local_model fallback. Unsupported model properties may still be searched, but require further correspondence investigation before implementation-level confirmation. For stable support, compare ordered effective events for the same identity/context; changing context is not automatically a violation. Complete accumulated history must correspond to the observed events. Report instrumentation differences. Only independently checked observation-only edits may continue to confirmation; protocol mutations or unreviewed changes do not represent the original implementation. Do not claim a review happened merely by returning a flag. After replay: unreached prerequisites permit F4; incompatible behavior requires F1; disputed applicability requires F2; missing boundary producers require F3. Missing tools, compilation errors and budgets are technical limitations, not semantic classifications.
