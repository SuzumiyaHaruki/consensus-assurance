EXECUTION Observe actual implementation effects under explicit inputs, caller policy and authorized isolation. Contract applicability may remain unresolved during exploration; execution permission may not. Preserve producer history, substitutions and observed completion. A changed value or tests_passed is not a violation oracle. Exploration remains construction knowledge: a later requirement needs a separately fixed check, fresh execution and correspondence review, not retroactive relabelling. Missing capability, compilation failure, timeout, panic and a completed property comparison remain distinct. Retain failures; never precompute expected observations or alter protocol behavior to create a finding.

COMPLETION Initialization, driver compliance and observation validity belong in prerequisites, controls or diagnostics, not duplicate properties. A diagnostic control need not satisfy the principal scenario's premises or acquire a separate obligation: select formal applicability using independently declared input/policy fields before execution, retaining control output for explanation. If formally comparing distinct scenarios, express each one's actual admission and premises; incompatible histories may need separate checks. Never select scenarios by the observed result, whether reproduction succeeded, or a missing premise after execution. Role or phase readiness does not imply that earlier work has drained. Across preparation, policy changes and delivery, preserve the selected caller/transport contract; prefer one delivery path with policy-selected deferral and record only the identity, provenance and order needed for attribution. Distinguish network receipt, per-message-type queueing and handler dispatch; identify which layer the driver replaces and preserve its ordering constraints, without assuming global FIFO or arbitrary reordering. Legal in-flight work need not be emptied and does not itself invalidate an otherwise supported check. End controlled work independently of the forbidden behavior. Observe admission, completion and final state for the same operation before treating absence as bounded holds. Missing completion, identity, result events and tool timeout remain unknown. A finite tick/wait window records non-completion, not a deadline violation or infinite stalling. For a repeatable suffix, account for behavior-determining state, external schedule, queues, timers and callbacks; equal selected business fields do not close the execution. A later operation restoring progress helps locate a trigger, but may itself be required caller work.

CORRELATION Monitor.admission_alias explicitly selects the declared harness prerequisite admitting operations whose completion is owed. It is not the first prerequisite by array order. Harness.prerequisites contains prerequisite events only; monitors select independent result events. ObservableProperty.identity_fields declares the stable operation identity once, using fields present at the relevant observation points. Do not repeat a result as a prerequisite or duplicate each identity equality as a Comparison. Reference conditions declare necessary predecessor relationships; unrelated prerequisites have no implicit list order. Assertions may refer to any declared prerequisite alias that actually precedes the result. Missing identity/reference fields or nonunique associations remain unknown. Independent applicability is checked before requiring unrelated history. Alias-dependent applicability follows correlation. Each operation is matched separately. A complete violating witness survives missing results in demonstrably independent operations, while coverage remains partial. Same-witness ambiguity and potentially global parse loss still block attribution. Use independent identity, not the compared value, to associate an input and output. A context expected to change cannot also be an equality filter. More complex histories need actual correlated prerequisites and results; unsupported general temporal expressions remain a stated limitation.

MEANING Record comparisons in properties/outcome and scope/applicability limits separately. Identify whether decisive observations read a live object, copy, cache or caller-maintained state; an export discrepancy need not mean the active protocol state changed. Verify the observation path as required by the claim, without mandatory dual observation or private-state access. Keep unresolved contracts, counterevidence, input legality and observation differences explicit; CheckRun owns execution status. An implementation/requirement discrepancy is the investigation subject, not a conflict between requirement sources. Real contradictions remain conflicts.

CONFIRMATION Review a direct check as a whole against its accepted obligation, actual calls, adaptations, event parsing, correlated prerequisites and independent oracle. A completed measured comparison survives wider-history and excluded-consequence limits, but cannot establish a broader consequence; missing correspondence keeps attribution pending without erasing the measurement. Judge instrumentation and substitutes from the supplied code and stopping point instead of a language-specific syntax rule. Construct a direct check with actual observations; equal checker IDs alone are insufficient. Unsupported expressions or incomplete histories remain gaps. Preserve unresolved semantic disputes. Newly recovered implementation knowledge may first be saved with a specific applicability issue, without automatically changing the requirement or scope.
REACHABILITY Separate the requirement's source and applicability, the consumer effect under controlled input, actual producer execution and same-history correlation, and the observed system endpoint. A call edge or constructible input does not execute its producer. Two isolated fragments do not establish one legal protocol history. Name substituted edges, fault assumptions and identity/context/generation continuity. Retain wider consequences as limits unless their endpoint is observed. A permitted pending path cannot be called a safety violation merely because an equality oracle expected success.
NECESSITY For a sourced safety condition S implies E, compare observed S only when independently established E is false, or use an equivalent supported implication encoding. Do not silently strengthen it to S equals E, suppress the result field through applicability, or infer eventual success from a permitted pending control.
