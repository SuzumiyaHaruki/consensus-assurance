SEMANTIC REVERSE REVIEW Review actual materials, not just the generator's rationale. Separately examine (1) applicability of the obligation to the current API/configuration/fault contract; (2) necessity, sufficiency, alternatives and conditions of the obligation and support relation; (3) correspondence of the formal checker to the intended responsibility when a model is supplied. For each target cite the actual source IDs, explain the relevant expectation or dependency, seek contrary or weaker/stronger contracts, and state alternative mechanisms. Ask whether the obligation's bad outcome could still occur while the current obligations all hold. A successful model check does not answer that question. For checker correspondence inspect the actual predicate, trigger, context/identity comparisons, allowed initial states, excluded branches and observed events. Can the antecedent occur? Does the scope contain the relevant event? Do not claim nonvacuity or behavioral equivalence without an executed check; state missing evidence and request discriminating material or exploration. No issue found is a provisional scoped interpretation, not a proof or an independent consensus vote. A new invocation of the same backend can share the same mistakes. Do not strengthen or weaken a property solely to match the current code or a passing test.

SCOPED DISPOSITION AND REVISION Review the saved artifact version and its actual execution, not a remembered draft. Classify each aspect once: no_issue_found has no counterevidence; explained alternatives go in rationale, independent scope in limitations, and sourced challenges in disputed/revision_needed. If an issue requires more evidence, name the exact reading, experiment or correction. If no action is supported, leave it visibly unresolved. A completed invocation does not resolve an issue. Name each resolved issue explicitly, address its original question and source basis, retain independent limits, and give a substantive resolution rationale. A partial review cannot clear other issues. Harness-only changes do not resolve semantic disputes.

For checker corrections, compare the prior artifact with the current version and its actual recheck. Resolve the old issue against the corrected current artifact without declaring the old checker correct. A changed obligation meaning requires an attributed semantic revision; unchanged meaning with different encoding needs an attributed encoding_revision and correspondence review.
