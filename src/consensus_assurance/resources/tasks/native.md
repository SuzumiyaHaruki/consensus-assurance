# Native investigation products

Investigate with native search, reads, draft editing and local tool feedback. Source and retained evidence are read-only; drafts are writable. Local exploration is not formal evidence. Use the current research.json index for accepted units, claims, bindings, tool versions, product schemas, artifact paths and actual review contracts. Read full logs and prior artifacts directly. State history is available without repeating it in every turn.

Write one complete submission.json using native-submission.schema.json. Metadata product schemas are in product-schemas.json. Cite actual authorized source ranges through sources; preserve the distinctions between expectations, observations, assertions and hypotheses. Correct rejected products against their archived raw bytes and diagnostics, never one guessed field at a time.

- continue, pause, explained, obligation: use a complete current question. candidate_id continues a saved candidate; parent_candidate_id forks a distinct local question. Do not combine them. Pause needs resume_conditions. Explain any source-grounded removal of previous counterevidence; preserve unresolved unknowns. Explained needs sourced protection and explicit scoped disposition, and creates no Evidence. obligation accepts the claim, bindings and unit without requiring a completed test.
- check: select unit_id and submit plan_path plus harness_path. Optionally create one obligation through candidate instead of unit_id. Plan JSON has empty harness.source/files; executable files are separate. files maps helper destinations to draft paths. No helper may replace target code or dependency definitions.
- revise_check: name unit_id and previous_check_id. Ordinary compilation, fixture and prerequisite execution repairs preserve the claim, oracle, prerequisite definitions and legality; they need no checker issue. If the oracle actually changes, supply an attributed encoding_revision naming its specific open issue. Every accepted version is formally executed; review resolves only expressly answered issues.
- model: select unit_id, model_path metadata, behavior_path and properties_path. ModelDraft records missing implementation components and permits syntax/search when its core is complete. Bundle adds harness_path and observation mapping. Name previous_model_id for continuation. Declare F1 for changed behavior/mapping, F4 for harness-only work, or technical for syntax repair preserving Properties and shared descriptions. An encoding_revision corrects the formal predicate with source rationale while preserving its claim and behavior. replay_finding_id links a harness adaptation to a preceding actual model counterexample; search inputs stay identical, calibration and implementation assessment use the new actual execution.
- research: save one partial map_path (ConsensusAuditSpec), additive graph_path (GraphPatch), or attributed scope_path (ScopeUpdate). All referenced Behavior/Fact objects must exist; a complete seven-class map is not required. Source review and exploratory experiments may precede obligations. Descriptive corrections are not normative revisions.
- semantic_revision: submit unit_id and feedback_path with a complete attributed F2 or F3. Declare every changed existing semantic field. Preserve history, negative evidence and fault/configuration scope; new support code is not a checked obligation.
- review: name artifact_id and answer the actual review_contract from research.json. The mandatory whole-artifact correspondence review can identify separate applicability/decomposition issues. no_issue_found cannot carry counterevidence. resolutions must answer exact stored issue IDs/questions; same-version evidence can resolve reading or applicability questions. An encoding dispute needs a changed checker, actual reexecution and review. Independent issues remain open across intermediate versions.
- explore: submit a harness_path, optional files and question for a controlled clean-copy execution before any obligation. Logs guide research but create no formal property Evidence.
- stop: name scope (candidate, family, focus, run), reason, ref_ids and sourced rationale. Reasons are bounded_completed, insufficient_basis, tool_gap, resource_limit, user_stop, no_actionable_direction. Remaining work is derived; use deferred_work to explain why unfinished local checks/issues are being left and their resume conditions. Resource, capability and user stops require no further reasoning or map completion. A bounded family result is not focus exhaustion. A focus no_actionable_direction needs registered Surfaces, frontier_comparison and the recorded remaining resources; this is a finite selection, never a coverage claim.

Every formal question names audit_spec_version, actual activity_classes, related behavior_ids, exactly one fact_ids entry, obligation_relation_kind, contexts, event_paths, sources, importance and trigger_rationale. For an initial map use version 1; after an actual update use the resulting accepted version (current + 1). A no-op retains the current version. Unmapped exploration needs none of these formal Candidate objects. A6 may support an A1 question through actual Fact edges and attributed cross_activity_effects; labels alone are insufficient. The configured focus is a peer research orientation, not a quota or a reason to invent context fields.

Candidate may include map_path; combined check uses its nested Candidate's map. Research may pair map_path with one graph_path or scope_path. Semantic_revision may pair a map with its F2. Map files are complete replacements; for every modified/deleted existing object, map_changes names its ID (surfaces use surface:<entry_point>), impact (clarification, meaning, dependency), rationale and acquired source_ids. New objects need no change entry. Preserve unrelated objects and unknowns. Clarification describes the same responsibility, never removed identities, changed context or new edges. Meaning changes affecting an accepted obligation require an attributed F2 Unit/question reconnection in that submission; dependency expansions use ScopeUpdate/F3. Include the resulting audit_spec_version in the explicit Unit patch. Old evidence stays recorded; new semantic inputs need fresh execution and review. Unrelated map additions do not supersede accepted checks. Graph additions cannot invent unowned executable Units; each Unit has its accepted candidate_id.

feedback may accompany existing submissions: ref_ids identify the actual disposition/check/review or its reviewed artifact; answered states the discriminator answered, remaining names unresolved inferences, understanding is updated/unchanged/deferred, and rationale explains reusable source-grounded understanding or why the map already suffices. After explained/pause or a whole-artifact review, provide this linkage with the next decision (or with that review). A map update must match understanding=updated. Controlled instance observations remain attached to execution, not general Facts. Before switching away from unfinished local work, supply deferred_work entries with target_id, rationale and resume_conditions. Continue ordinary construction without submitting a map after every read.

A child supplies result_implications for holds, violated and incomplete, explaining each result's effect and remaining inference limits on the parent. Retain stable Candidate identity for new sources or results on the same question. Wording alone is not progress. Removed counterevidence needs a source-linked feedback answer as well as counterevidence_resolution; presence of text is not proof that the answer is correct. Required normative applicability, actual/injected prehistory, independent oracle, observation endpoint and excluded consequences belong in the existing question, grounding, scope, harness prerequisites and monitor fields.

When several saved Candidates share changed map objects, reconnect_questions maps their IDs to complete updated questions within that map submission. This preserves their status/history and unresolved counterevidence; it cannot bypass Unit F2/F3. Each Candidate has one current Unit (scoped predecessors stay historical); independent check/model scenarios share that Unit, and distinct discriminators use distinct Candidates.

A raw successful process, model counterexample and calibrated implementation trace are different observations. Compare correlated actual prehistory, legality, completion and an independent oracle before attributing a local violation. Do not promote it to its parent's system consequence. Continue the same session after accepted execution errors and whole-product rejection; authorization/authentication/quota failures remain explicit stops.
