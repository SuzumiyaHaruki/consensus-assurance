# File submissions

Read research.json for authorized source/draft locations, current work, capacity and record locators. Materials and CheckRuns resolve in state.json. Artifacts retain graph_versions and historical basis locators; never substitute a newer same-ID claim. Continuation summaries retain actual results and current gaps across review/research handoffs; use the full records for detail.

Write a complete submission matching submission.schema.json and return its draft-relative path and summary. No need to read every definition before exploring. Minimal exploration (write probe.py first):
```json
{"action":"explore","question":"What does the actual call return for this supplied input?","harness_path":"probe.py","rationale":"Observe the local branch before investigating its producer."}
```
Use the relevant generated definition in submission.schema.json or product-schemas.json for additional fields. All submissions may include sources, feedback, map_path/map_changes and one review; at most one target execution per submission. Optional validation.command preflight reads the draft filename without reserving budget or granting acceptance. Acceptance revalidates fixed bytes.

- continue / pause / explained / obligation: a new question needs question text and captured source_ids. With candidate_id, omit question or supply only changed fields. parent_candidate_id links a distinct child without settling the parent. Pause names concrete resume_conditions. Explained retains sourced counterevidence and explained_by_existing_mechanism. Obligation adds a sourced claim and physical bindings; omitted binding associations derive from that claim, not inferred source meaning.
- check / revise_check: select unit_id or its Candidate alias, or supply candidate with action=obligation for combined creation/execution. Provide plan_path, harness_path and optional files mapping workspace destinations to drafts. Leave plan.harness.source/files empty; the controller fixes bytes. Omitted claim_id/binding_ids select the accepted Unit inputs. Revisions name previous_check_id and rationale; optional revision changes that check's claim/bindings/Unit with expected_versions. Actual differences, fresh execution and review replace repair classifications.
- explore: question, harness_path, optional files and execution_package use the same clean-copy boundary without a formal verdict. Retain incomplete outputs and supplied-state/history gaps.
- research: feedback, partial map and/or review without a preliminary Candidate. Feedback uses ref_ids, answered, remaining and rationale; explicitly cite each CheckRun explained. A separate producer probe needs an accepted feedback association naming that CheckRun and the relevant Candidate/artifact/claim, with joint-history reasoning. Shared sources alone are not execution associations. Optional question_updates changes unknowns/resume_conditions while retaining history. Identical adjacent handoffs can receive informational duplicate_of, never a penalty or forced test.
- stop: local candidate/family/focus disposition retains unresolved work. Only a configured directed_question permits run/bounded_completed after its task is disposed. Actual cancellation, refusal, permission loss and exhausted resources belong to the controller. Open runs continue useful investigation within limits, without quotas or closing calls.

review supplies artifact_id, review_items and optional resolutions. Item target_id inherits artifact_id. Direct checks require checker_correspondence; applicability/decomposition are optional unless answering their issue. Candidate applicability requires no execution. A resolution names issue_id, source_ids and rationale once; existing condition provenance stays with the issue. executions maps actual target CheckRun IDs to decisive zero-based parsed event indices; fixed inputs resolve through those records. Source-only correction may omit executions. Do not cite Agent/review/artifact IDs as empirical observations. Retain independent boundaries in review limitations, not duplicate disposition tables. See evidence-review for substantive criteria.

Optional map references must exist at the recorded version. Submit the accepted map base (initially 1); the controller assigns successors. For changed premises actually used by saved questions, map_changes gives sources/rationale plus preserves or specific Candidate challenges. Independent additions need no declarations; no-op maps create no version. Reverse indexes are derived.

Go execution_package selects a captured local package with the configured basename; Rust selects a crate and tests/<basename>.rs. Helpers are workspace-relative; Python has no package override. Follow research.build_inputs/backend instructions for fixed locks, features, tools and caches. Declared source does not prove active cfg. Target code, dependencies and build configuration stay protected. Setup repair uses the same successor path.

Repair rejected complete drafts using repair_of; other questions remain unaffected. Deliver useful sourced answers or executable evidence without waiting for a map or extra review-only turn. Current turn allocation and CheckRun establish timing; preflight time is a checkpoint. Receipts fix files; unfinished drafts are not evidence. Expiry needs no wrap-up.
