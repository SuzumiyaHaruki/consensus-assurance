# One file-backed update

Read research.json for source/draft paths, questions, actual results and locators, necessary gaps, changed knowledge, backend/build inputs and allocation. Detailed history lives in state.json and referenced receipts. Start with the small update example; consult only needed $defs in submission.schema.json, not the whole schema.

Write JSON in draft and return its relative path plus a short summary. Optional validation.command checks those bytes read-only and reserves no capacity. Acceptance reads retained bytes. Rejected whole drafts and diagnostics return for ordinary repair in this session; editable drafts never override receipts.

The envelope requires rationale; sources, investigations, knowledge, gaps, interpretations, experiment and stop are optional. Existing records use explicit IDs. Unique @names may refer to new questions/knowledge within a batch. The controller assigns IDs, revisions and comparison indices. Source IDs identify acquired file/ranges; do not create aliases merely to count handoffs.

- investigations: create a sourced question or update specified fields of id. Hypothesis/discriminator may be provisional. parent_id links a child without closing its parent. paused needs resume_conditions; explained/closed retain unresolved boundaries and grounded interpretations.
- knowledge: behavior/fact statement, conditions and sources, optionally execution indices. Correct an existing id using changed_premise and affected_uses from recorded dependencies. References specify entry_id/revision and optionally the assertion used. Old bases remain available.
- gaps: necessary question under investigation_id; optional experiment_id limits it to that experiment and successors. Put broader directions in discriminator or limitations. answers maps exact gap IDs to sourced/observed explanations. Identical updates do not duplicate gaps.
- interpretations: investigation_id, optional experiment_id, source_ids, rationale and conclusion (explained, conditional, violated, holds, unresolved). executions maps target receipt IDs to decisive parsed indices; an experiment interpretation needs its own receipt. Separate producer receipts need joint_history. Unresolved/conditional accounts may retain failed receipts with no decisive events. Preserve knowledge uses, counterevidence and limitations. Optional report_title/report_answer are Chinese presentation, never verdicts.
- experiment: one invocation with investigation_id, harness_path, optional files (workspace destination → draft path), source_ids, scope and prefix, including supplied assumptions. requirement/responsibility and comparisons are optional; requirements need verified source anchors, which do not prove source meaning. A comparison owns event, identity_fields, admission_alias, assertion and optional antecedent/applicability_conditions. prerequisites use explicit alias dependencies, not array order. Cases/controls can share execution. Changed basis uses previous_id/revision_reason and receives fresh execution.
- stop: bounded_completed only for a preconfigured finite directed task with no necessary unfinished work. Cancellation, service refusal, permission loss and exhausted resources are controller boundaries, not model declarations.

Go execution_package selects one captured local package; Rust selects a crate and tests/<basename>.rs; Python has no package override. Follow backend instructions for protected source, dependencies, locks, features, support and caches. Exploration and specified checks use identical fixed-input isolation. Agent shell networking is disabled; executor communication is confined to its private namespace.

Exact unchanged updates receive no_change, retained raw cost and useful current work, without duplicate semantic revisions or automatic stopping. Turn allocation and its CheckRun establish timing; preflight elapsed time is a checkpoint. Expiry requires no closing submission.
