MODELING METHOD
Before generating actions, trace the selected obligation through concrete control flow. For each relevant state read/write, identify its source binding, owner, and persistence or recovery contract.
Split actions at actual interruptible boundaries: blocking calls, channel operations, callbacks, lock release, and storage completion. Compare checks at start with checks at completion; ask whether identity, context, configuration, or inputs can change in between. Do not combine separated effects into an atomic action without evidence.
For each action enumerate changed variables, unchanged variables, permitted failures, and observable effects. Retain error branches and reachable boundary values. Derive scheduling and fault assumptions from the selected scope, not from the property being tested.
Separately define the property trigger and consequence. Map each checker to its claim and scope. Every configured invariant must exist and must not be smuggled into Init/Next as an assumption. State which selected obligations this model checks and which remain pending. Properties can fail.
Bound participants, contexts, outstanding operations and failures explicitly. Bounds must preserve the candidate violation and be recorded in scope/constants. Calibration establishes only that finite actual observations have an explaining model path.
For ordinary technical repair, preserve the entire Properties module and observable property descriptions byte-for-byte. If property syntax itself is invalid and semantic preservation cannot be established, report a gap for explicit semantic investigation; do not replace the predicate with TRUE or weaken its trigger.
