# 第四轮：持续覆盖探索与语义复核

本轮基于 `49c2dc936606aeb39b9fdc1a69bf9a6c0c46057e` 增量修改。目标是尽量扩大有依据的 goal/义务覆盖，并通过持续反馈纠正问题本身。没有把“最终正确”实现为一个自动批准状态：真实语义判断仍可能错误，复核也可能与生成共享偏差。

本轮只执行本地框架、mock 回归和真实 TLC 样例。没有运行新的 HashiCorp 自主实验，没有发送目标材料，也没有提交或推送代码。

## 一条流程，三类工作

默认流程为：跨区域初始阅读 → 有来源的职责概览和候选图 → 交替选择职责探索、语义复核、局部检查 → 根据新材料、语义问题及工具结果继续安排工作。不是三个产品模式，也没有三个常驻 agent。

- 覆盖探索不依赖反例。职责即使还没有 goal，也能进入任务队列；每段局部搜索后还会产生一次查漏机会。
- 语义复核在首次建模前、新材料或图更新后、局部搜索后执行。局部模型无反例不免除复核。
- 局部检查仍使用原来的 G—O—C、模型、轨迹校准、TLC、实现实验和 F1—F4。单个模型可以很小，但系统认识不应永久停在第一个方向。

`initial_materials()` 先取少量实际文档，再混合不同实际目录的材料前缀，避免把全部初始槽位交给最短文档；这仍是有预算的采样，不声称系统概览已经完整。阅读 prompt 明确区分概览与局部选题。后续探索可根据真实 catalogue 请求新的精确范围。

## 职责概览与材料覆盖

新增轻量 `Responsibility`：描述、实际材料引用、入口提示、关联 claims、待解释问题、适用性，以及有材料依据的 handoff。概览可修订并保留旧版本。职责跨文件、文件参与多个职责均允许。

`unread_ranges` 表示文本未读范围；职责与 goal/义务关联表示当前认识；模型和 checker 表示实际检查范围。三者不混用。概览来自系统自己的发现，不作为完备分母，因此没有“系统覆盖 100%”。

一次 discovery 同时返回 units 和 reading_requests 时，补读会登记为独立探索任务。`ExplorationReply` 只返回小批次 GraphPatch 和概览增量。新增无关职责不强制归类为 F3，F3 继续用于当前单元的依赖扩展。

## 语义复核与纠错

`ReviewReply` 对每个目标对象提供有材料引用的判断，不接受只给分数。要求：goal/假设检查适用性；义务检查适用性及分解；关系检查分解意义；模型检查 checker 对应。实际请求包含原始材料、对象版本，存在模型时还包含 Bundle 和真实 checker 输出。

方法要求反向检查：是否误读配置或责任边界？义务是否过强、过弱或仅是一种替代机制？所有当前义务成立时，目标的坏结果是否仍可能发生？checker 的前件能否触发，身份/上下文是否对应，关键分支是否被范围排除？没有执行证据时不能声称已证明非空洞性。

结果分别为暂未发现语义问题、需要补读、存在争议、需要修订。补读和新职责调查成为后续任务；依据充分时通过 F2 修订，并对新版本再次复核。缺少可执行的区分方法或预算时保留限制，而不是假装解释已解决。

F2 不再要求先有 Bundle 或反例，也不要求只改关系时顺带改 claim 文字。`JudgmentChange` 可记录语义字段的精确前后值，覆盖关系类型、端点、条件分组、范围、grounding 等。普通 patch 不能改这些语义，也不能直接清除未决条件。旧版本、依据和受影响模型继续保留。

结构校验只确认来源存在，不判定推导真伪。取消了“无直接预期材料时必须恰好有两个以上 binding”的粗糙充分性暗示：有实际绑定的单点职责推导也可作为候选，仍由语义复核检查其含义。没有来源、绑定或推导的对象仍会拒绝。

语义复核意见不是正确性证据。已记录的争议、相关未完成复核会限制实现级确认；仅生成新重放模型版本不能清除旧 checker 的语义争议。

## 调度、预算与恢复

`InquiryTask` 保存类型、原因、触发点、职责/目标引用、请求范围、阶段、执行引用和受阻原因。队列在探索、复核及局部段之间交替。局部反复受阻时，保存续接信息并考虑其他任务；显式 resume 可在原预算允许时重试，自动调度不对同一阻塞无限重试。

新增预算：`exploration_rounds`、`semantic_reviews`、`graph_objects`、`outer_reserve_seconds`。全局 agent 次数、总时间、读取、修订和模型工具预算仍生效；局部动作会给已排队且预算允许的探索/复核保留至多两个 agent 调用和配置的时间余量。这是简单可解释的预留，不是固定百分比分配。

`audit_units: 0` 可用于只做概览和语义调查。两个 inquiry 预算都为 0 时，仍可执行原局部链，但报告明确没有执行外层复核；历史固定夹具显式使用该预算设置。mock 并不自动绕过外层流程。

探索轮数和复核次数不是已覆盖职责数量。一项任务可能需要读取后再次分析，所有 agent 请求仍计入全局上限。工具不可用、认证或额度阻塞会停止相关调用；不切换账户或付费后端。

`GraphDraft` 负责累计图的一致性，Discovery/GraphPatch 保留单次小批次限制；累计图只受独立 `graph_objects` 资源预算影响。不会因为已有超过 15 个 claim 或 5 个 unit 而拒绝后续小批次增量。

## 修改位置

- `core/types.py`、`core/proposals.py`：概览、任务、复核记录、统一读取请求、语义字段变化及累计图结构。
- `workflow/inquiry.py`：外层任务受理、调度、来源检查、复核与 F2 连接、暂停恢复、确认限制。
- `workflow/discovery.py`、`engine.py`：登记初次补读，插入前置和事后复核，在局部段后返回调度。
- `workflow/graph.py`、`feedback.py`：解除累计图的小批次上限，保护关系语义，允许建模前和关系单独 F2。
- `workflow/materials.py`、`budget.py`：跨目录初始采样、有限预算预留。
- `resources/prompts/en/`：宽度探索与语义反向复核方法，保留英文机器指令。
- `reporting/chinese.py`：职责、交接、未形成 goal 的区域、各层复核结论和待办分开展示。

## 验收边界

受控 backend 根据测试材料返回预定解释，验证调度、纠错和证据连接的执行机制，不能证明真实 LLM 的覆盖率、语义判断质量或最终收敛。真实目标质量还需用户审阅实际材料和后续受限运行。

本轮没有穷举职责、自动证明目标分解充分性、通用非空洞性证明或参考规范推导引擎。没有可定位到字段的生成错误仍可能停止相关任务；有争议而缺少区分材料时可能继续保持不确定。系统提供的是可追溯、可继续的覆盖和纠错过程，不是“所有目标最终必然正确”的保证。
