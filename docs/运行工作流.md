# 运行工作流

本项目使用 Codex 完成共识实现审计。搜索、阅读、编辑、工具反馈和调查续写交给原生会话；本项目提供领域方法、研究产物校验、隔离的正式执行以及有来源和边界的证据记录。生产树只有这一条调查主线，离线回复替身也经过同一个提交入口。

## 调查与产物

每次 `run` 使用新目录、空研究状态和新 Codex 会话，显式关闭跨会话记忆读取和生成；其他运行的报告、草稿和结论不作为输入。`resume --run` 只延续明确指定的同一次运行。新开始拒绝使用非空实验目录。选题和检查依照 Activity → Behavior → Fact → Candidate → Obligation → Evidence 的依赖关系从当前源码推进，不预设某个历史场景。

`native-source` 只公开获准的目标快照文件，`native-draft` 可写。目标 AGENTS.md、SKILL.md、凭据和范围外文件被排除；本次运行的源码和保留证据只读，其他运行目录不可读。可信方法由 `resources/task-skills.json` 加载并记录路径、版本，保存为 `native-method.md`。Codex 读取本次 `research.json`、`state.json` 和产物续写；引用仍校验路径、行范围和快照版本，定位有效不意味着语义判断成立。

默认先在 AuditSpec.core_overview 解释共识形成与推进、上下文／权威转换及二者连接。部分地图仍可受理；概览有核心断点时，`research.json.next_objective` 指向补齐主干；概览可用后指向集中调查与回流。仅用户配置的定向问题可采用局部边界。保存概览和首个问题可以合并为一次提交，控制器不另设调查阶段或阅读审批。

随后选择有来源的 AuditQuestion，再决定继续、解释、暂停、分出局部问题或形成义务。正式问题引用地图版本、相关 Activity、实际 Behavior、一个 principal Fact 及 lifecycle，并说明上下文、路径和选题理由；单题不必同时覆盖 A1/A2。父问题的反证和未知不会随子问题检查完成而消失。普通细节未知、未映射 Surface 和前置探索均可保留；解释性结论不是执行 Evidence。

提交入口按产物区分，完整字段以运行目录中的 schema 为准：

| 产物 | 作用与继续方式 |
| --- | --- |
| `continue/pause/explained/obligation` | 保存当前完整问题；义务可先于测试受理。`candidate_id` 续写，`parent_candidate_id` 分出不同问题。 |
| `check/revise_check` | 为已有 `unit_id` 提交计划和独立 harness，可携带固定辅助文件；也支持同次提交一个新义务。普通编译、fixture 或未触达修复无需 checker issue。 |
| `model` | 分别提交元数据、Behavior、Properties。可归属 Candidate/Surface 或已受理 Unit；核心完成的 ModelDraft 做 SANY/TLC，F1 与编码修订保留前版。实现见证另走 check，不再自动装配 Bundle／实验／校准／重放归因链。 |
| `research` | 保存部分 AuditSpec、增量关系图或来源化 ScopeUpdate；地图可与一个图操作同次提交，新背景代码不计作已检查义务。 |
| `semantic_revision` | 通过已有 F2/F3 校验修改语义或扩展依赖范围，明确声明改动并保存历史。 |
| `review` | 使用 `review_contract.py` 的实际要求复核制品。复核栏目与被挑战组件分开；输入修复保留 oracle，编码修复改变相应观测或判据，均需新制品、新执行及针对原 issue 的回答。纯补源可解决同版本争议。 |
| `explore` | 无义务时也可提交隔离探索程序，保留日志，但不生成性质证据。 |
| `stop` | 区分 Candidate、问题家族、配置重点和本次运行；记录理由与相关对象。剩余工作从状态派生，局部 checked 不代表重点已穷尽。 |

Candidate 可携带完整地图文件，合并 check 也复用这一入口：来源、地图、问题、义务与绑定、制品依次校验，通过后一次受理并执行。任何部分无效，本次新增对象均不受理；此前独立受理的义务保留。所有可执行 Unit 必须接到已有 Candidate，包括 graph/scope/F2 入口。

地图更新按对象 ID 比较完整差异；修改或删除旧对象必须声明来源、理由和影响类型，空更新不产生版本。无关 Surface 或独立消费者的添加不重跑旧检查；新 producer／失效路径须解释对当前见证的影响，不能统一当作背景。地图与组合提交都填写当前基准版本，由控制器归一化结果版本和反向索引。影响所用 Fact 含义的更新需通过 F2 接回问题和 Unit；依赖扩展走 ScopeUpdate/F3。旧输出保留，新语义输入不沿用旧确认。纯措辞澄清的声明仍是来源化判断，不是自动证明。

解释、暂停或检查复核后的下一决定，用 `feedback` 关联实际结果、已回答判别、剩余问题及理解变化，可与原有提交合并。控制器派生当前提交是否改地图；`understanding` 若填写，表达此前研究对理解的影响。`question_updates` 显式按 Candidate ID 更新当前未知与恢复条件，需 `answered` 和有来源的引用；保留旧问题、反证和反馈历史，不通过关键词自动清空未知。实际执行进度从 CheckRun 派生；切换选题不再把“尚未执行”等旧未知机械抄成恢复条件。无关历史反馈不阻塞当前检查。待办和版本由控制器派生，不要求复制精确集合。

Candidate／family 处置只影响显式列出的 Candidate，不按 Fact／context 元组或父子关系扩散；focus 的局部退出返回同一原生入口。未受理地图／问题用既有 operation 归档和 `repair_of` 串联，不制造已受理 Candidate。独立诊断改变会记录为修复进展，同一诊断反复出现可暂停该草稿，保留原稿、pending Unit 和 issue，不终止其他调查。正常 run／focus 停止要比较已有方向与剩余能力。用户停止、全局资源耗尽或权限／认证障碍可靠终止；这类强制退出即使元数据无效也保存原稿和诊断，不应用附带语义修改。

`research.json` 和中文报告从同一状态派生研究链、所有 Surface、实际 Fact 关系、暂停问题和当前待办。mapped 表示已有描述；出现过 A1/A2 标签或检查过一个 Unit 不表示该区域穷尽。按逻辑义务归并当前制品版本，分别表达核心安全性、有界活性或相关实现语义，以及范围内确认／有限未见违反／调查线索。保留更广后果的具体缺口，不建立第二套调度或发现晋升系统。

## 执行、修复与恢复

原始提交在 JSON 解析前保存。先拒绝草稿路径逃逸和 symlink，再读取并保存所引用文件的固定字节。正式 runner 从这些字节和干净源码副本装配；后续编辑草稿不影响已受理输入，辅助文件不能覆盖目标代码或依赖定义。无效提交不修改已接受研究；已受理后的执行失败单独记录，不伪装成提交被拒。

模型搜索、实际程序执行、轨迹校准和归因是不同结果。正式执行之后刷新 Unit 的检查记录与未完成义务；多个独立场景不能被最后一个成功场景覆盖。复核可改变当前解释，但原始日志、失败版本和旧判据仍保留。必要条件按实际成功事件约束合格性，不把缺少成功当成已经观察到一条成功路径。

直接检查显式指定 `EventMonitor.admission_alias`，指向该操作准入的前提事件；准入、其他前提、结果及适用性分别匹配。结果适用条件不用于过滤准入，即使二者字段同名、值不同。无依赖前提的声明顺序不改变判定；真实因果依赖通过 alias 引用表达。缺少完成、空轨迹或工具超时不能得到 holds，也不能单独宣称一般活性违反。

`revision_needed` 标明 `challenged_components`：配置、初始化、驱动、观测、oracle、规范或范围。issue ID 定位原版本和原文；回答以 `source_ids` 引用 Materials，以 `evidence_ids` 引用实际执行、制品、证据或复核，不必抄回旧问题和所有旧来源。配置修复保留正确 oracle；真正 oracle 错误不能靠只改 harness 关闭。改变规范或范围仍走既有 F2/F3，旧反证和无关争议保留。

CLI 调用结果、完整原稿、受理事务和正式操作身份分别持久化。恢复先处理已保存回执和已受理执行，再考虑新模型调用；模型调用额度为零不会丢掉这部分工作。已有可靠完成回执不重复执行；没有可靠结果的中断记录为未知，并在剩余工具预算内使用新副本。恢复不重置已用预算，工具版本变化仍要求新运行。会话明确丢失时保留中断记录，从保存的研究继续新会话；认证和额度错误停止模型工作。

`agent_calls` 是 CLI turn 数；内部工具数按完成事件中的唯一工具 item 计数，usage 有则原样保存。`native_turn_timeout`、`action_timeout`、`total_seconds` 分别限制单次原生调查、正式动作和整次运行。正式实验、模型工具、修订和复核仍受工具额度限制；实际生效的总时间／turn／动作超时分别记录。当前剩余能力从配置和 usage 派生，没有执行能力时拒绝新的占位 Unit，但仍可做有预算的源码调查。总时间到期后，已受理未执行的制品保持精确恢复位置，不暗中执行。退稿调用耗时与正式执行耗时分开，退稿不全是浪费。旧材料字符、packet 与 breadth/depth 配额已删除，不能据调用次数或字符数推算 token 或费用。

## 验证和兼容边界

新资源版本是 `native-products-v26`。实际加载清单仍由 `resources/task-skills.json` 唯一确定，默认加载共识分析、证据审阅和 native 产品合同；模型方法仅在配置 verifier 时加入。旧运行通过其原始 `report.md` 和 JSON 只读查看，不自动改写 state 或恢复旧阶段。没有另设预检器、草稿管理器或研究调度器；受理复用现有验证函数，尽量一次列明独立的地图、Activity、来源和 grounding 错误。

本轮验证使用脚本化产品、小型按实例上下文的源码、隔离 Python 执行及事件判定回归，只证明所测工程行为。没有调用真实 Agent、执行 HashiCorp、运行 TLC 或重评历史日志；删去 `tests/fixtures/v23-verification` 及其专属回放，事件回归使用通用输入。

真实效果需分别授权：自主验收使用新目录、空研究状态及 `directed_question: null`，检查六项核心路径解释及后续回流；定向 producer 验收通过显式 HashiCorp 后端与用户定向问题选择已有 `NewAssuranceClusterWithSuffrage` 辅助入口（`plugins/targets/hashicorp_raft/assurance_support_test.go`）。后者仍须真实请求／回复、同次 verification 的登记、通知与结果关联，以及独立成员资格依据；辅助层存在不表示已经使用或验证。两类验收均不导入旧运行答案。TLC 保留为可选工具，本轮未测其增益。
