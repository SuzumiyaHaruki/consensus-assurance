# 运行工作流

本项目使用 Codex 完成共识实现审计。搜索、阅读、编辑、工具反馈和调查续写交给原生会话；本项目提供领域方法、研究产物校验、隔离的正式执行以及有来源和边界的证据记录。生产树只有这一条调查主线，离线回复替身也经过同一个提交入口。

## 调查与产物

捕获目标源码后，`native-source` 只公开配置允许阅读的文件；`native-draft` 可写。目标中的 AGENTS.md、SKILL.md、凭据样式文件和分析范围外文件不会成为可读指令。源码、日志、模型、已保存 checker 和历史记录对模型控制的命令只读。可信运行方法由 `resources/task-skills.json` 实际加载，记录资源路径和框架版本，同时保存为可读的 `native-method.md`。

Codex 从 `research.json` 获取当前 Unit、claim、Candidate、制品、工具版本、原始结果路径和复核要求；需要历史时直接读取 `state.json` 及具体产物。正常源码阅读不再经过 ReadRequest、packet 或控制器逐片供给。来源提交仍校验获准路径、实际行范围和快照版本；定位有效不意味着规范判断成立。

先选择有来源的 AuditQuestion，再决定继续、解释、暂停、分出局部问题或形成义务。正式问题必须引用已受理地图版本、相关 Activity、实际 Behavior、一个 principal Fact 及 lifecycle，并说明上下文、事件路径和选题理由。父问题的反证和未知不会随子问题检查完成而消失。地图可以只覆盖必要的局部关系，缺失的 producer/consumer 明确保留为未知；未映射 Surface 和前置探索无需虚构 Fact。解释性结论是来源化分析，不是执行 Evidence。

提交入口按产物区分，完整字段以运行目录中的 schema 为准：

| 产物 | 作用与继续方式 |
| --- | --- |
| `continue/pause/explained/obligation` | 保存当前完整问题；义务可先于测试受理。`candidate_id` 续写，`parent_candidate_id` 分出不同问题。 |
| `check/revise_check` | 为已有 `unit_id` 提交计划和独立 harness，可携带固定辅助文件；也支持同次提交一个新义务。普通编译、fixture 或未触达修复无需 checker issue。 |
| `model` | 分别提交元数据、Behavior、Properties。可归属 Candidate/Surface 或已受理 Unit；核心完成的 ModelDraft 做 SANY/TLC，F1 与编码修订保留前版。实现见证另走 check，不再自动装配 Bundle／实验／校准／重放归因链。 |
| `research` | 保存部分 AuditSpec、增量关系图或来源化 ScopeUpdate；地图可与一个图操作同次提交，新背景代码不计作已检查义务。 |
| `semantic_revision` | 通过已有 F2/F3 校验修改语义或扩展依赖范围，明确声明改动并保存历史。 |
| `review` | 使用 `review_contract.py` 的实际要求复核制品。补源可解决同版本问题；编码争议需要新 checker、实际重跑和明确回答原 issue。其他争议继续保留。 |
| `explore` | 无义务时也可提交隔离探索程序，保留日志，但不生成性质证据。 |
| `stop` | 区分 Candidate、问题家族、配置重点和本次运行；记录理由与相关对象。剩余工作从状态派生，局部 checked 不代表重点已穷尽。 |

Candidate 可携带完整地图文件，合并 check 也复用这一入口：来源、地图、问题、义务与绑定、制品依次校验，通过后一次受理并执行。任何部分无效，本次新增对象均不受理；此前独立受理的义务保留。所有可执行 Unit 必须接到已有 Candidate，包括 graph/scope/F2 入口。

地图更新按对象 ID 比较完整差异；修改或删除旧对象必须声明来源、理由和影响类型，空更新不产生版本。无关 Surface 或独立消费者的添加不重跑旧检查；新 producer／失效路径须解释对当前见证的影响，不能统一当作背景。地图与组合提交都填写当前基准版本，由控制器归一化结果版本和反向索引。影响所用 Fact 含义的更新需通过 F2 接回问题和 Unit；依赖扩展走 ScopeUpdate/F3。旧输出保留，新语义输入不沿用旧确认。纯措辞澄清的声明仍是来源化判断，不是自动证明。

解释、暂停或检查复核后的下一决定，用 `feedback` 关联实际结果、已回答判别、剩余问题及地图更新／无需更新／延期理由，可与原有提交合并。当前未知可由一次来源化 `feedback.answered` 回答，旧描述保留在历史中；无关历史反馈不阻塞当前检查。待办和版本由控制器派生，删除 `deferred_work` 精确集合合同。资源、用户和工具中断即使附带无效元数据也保存原稿和诊断后停止，不应用附带语义修改。`research.json` 和中文报告从同一状态派生研究链、未展开 Surface、暂停问题和当前待办，不建立第二套调度器。

## 执行、修复与恢复

原始提交在 JSON 解析前保存。先拒绝草稿路径逃逸和 symlink，再读取并保存所引用文件的固定字节。正式 runner 从这些字节和干净源码副本装配；后续编辑草稿不影响已受理输入，辅助文件不能覆盖目标代码或依赖定义。无效提交不修改已接受研究；已受理后的执行失败单独记录，不伪装成提交被拒。

模型搜索、实际程序执行、轨迹校准和归因是不同结果。正式执行之后刷新 Unit 的检查记录与未完成义务；多个独立场景不能被最后一个成功场景覆盖。复核可改变当前解释，但原始日志、失败版本和旧判据仍保留。必要条件按实际成功事件约束合格性，不把缺少成功当成已经观察到一条成功路径。

CLI 调用结果、完整原稿、受理事务和正式操作身份分别持久化。恢复先处理已保存回执和已受理执行，再考虑新模型调用；模型调用额度为零不会丢掉这部分工作。已有可靠完成回执不重复执行；没有可靠结果的中断记录为未知，并在剩余工具预算内使用新副本。恢复不重置已用预算，工具版本变化仍要求新运行。会话明确丢失时保留中断记录，从保存的研究继续新会话；认证和额度错误停止模型工作。

`agent_calls` 是 CLI turn 数；内部工具数按完成事件中的唯一工具 item 计数，usage 有则原样保存。`native_turn_timeout`、`action_timeout`、`total_seconds` 分别限制单次原生调查、正式动作和整次运行。正式实验、模型工具、修订和复核仍受工具额度限制；实际生效的总时间／turn／动作超时分别记录。旧材料字符、packet 与 breadth/depth 配额已删除，不能据原生调用次数推算 token 或费用。

## 验证和兼容边界

新资源版本是 `native-products-v24`。旧运行通过其原始 `report.md` 和 JSON 只读查看，不自动改写 state 或恢复旧阶段。已删除旧在线读取、packet、指针修复、研究调度及其仅供阶段播放的记录和接口；没有保留 mock 专用的第二套生产运行时。本轮验证与适用边界见 [合法执行见证改造](合法执行见证改造.md)。旧模型校准工具保留为显式离线分析接口，不能恢复为另一条原生调查主线。

本轮本地验证使用脚本化回复及真实 Python、Go、SANY/TLC 工具，只证明所测接口、事件语义和执行链。HashiCorp 辅助层及两个复用判别仅做编译检查，未运行目标；真实 Agent 构造和方法比较未评估，均需另行授权。
