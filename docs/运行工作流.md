# 运行工作流

默认真实运行先捕获目标源码版本，再从配置允许阅读的文件构造 `native-source` 视图。Codex 在这个视图内自行搜索，在 `native-draft` 编辑检查源文件；同一研究跨 turn 使用保存的精确 session ID 继续。源码、正式检查产物和历史运行对模型控制的命令只读，草稿可写；每次发送任务前用本机 Codex 沙箱做读、拒读和写入探针。目标 AGENTS.md、SKILL.md、敏感文件和分析范围外文件不会进入可读视图。探针失败或权限未打开时停止，不发送模型任务。

研究方法由 `resources/task-skills.json` 选取 `resources/system.md`、领域方法和原生提交合同。Agent 先选有来源的 AuditQuestion，可继续、解释、暂停或明确建立 child；不强制每个疑问形成义务。Parent 的未知与反证不会被 child 局部检查覆盖。需要可执行判别时，Agent 提交有来源的义务、物理绑定和检查。关键引用由控制器验证路径、行范围与快照内容；源码能定位不等于规范判断成立。

直接检查把元数据、测试源文件分开提交。局部模型把元数据、Behavior.tla、Properties.tla 和可选实现 harness 分开提交；缺实现装配时保留 ModelDraft。控制器先在副本校验完整提交，再固定已受理版本，从未修改的源码快照装配干净执行副本。编译探测、SANY 语法、TLC 搜索、实际目标实验、轨迹校准和语义归因分别记录。原生 Agent 可利用错误输出继续改草稿，但不能自己写正式 CheckRun、Evidence 或 Assessment。

未受理的草稿保留完整原稿和所有错误，同一会话看到相关 Candidate 与制品后整体修订。父子关系需要明确表示：`candidate_id` 继续旧疑问，`parent_candidate_id` 建立不同的局部 child，不能同时提交。已执行检查的 checker 或 harness 改动不能覆盖旧制品；编码修订须指向原问题和前版，重新执行、复核后才能逐条解决争议。C3 类必要条件应写作“成功蕴含合格支持”，并以完成的实际结果事件和相关前提比较；没观察到成功不自动算通过。

报告从已保存的 Candidate、产物版本、CheckRun、机械评估、复核问题和原始日志导出。局部 property holds 只表示指定有界场景内比较完成；违反也只归因到被检查的义务。未完成前提、合法历史、producer 或消费者终点继续列为边界。真实 Agent 自主发现、定向离线构造、旧 harness 重放与 mock 回复分开标记，不能互相替代。

`agent_calls` 是 Codex CLI turn 数；内部工具事件按 JSONL 记录，可用 token usage 原样保存。正式实验、模型搜索、总时长分别受预算约束。`native_turn_timeout` 与正式动作 `action_timeout` 分开。旧 `material_chars`、`context_chars`、分片与 breadth/depth 配额只用于离线旧阶段，不表示原生会话的实际源码读取量或费用。恢复不会清空已用预算或重登旧证据；会话不可用时可以由持久研究记录开启新会话，并明确标记连续性中断。跨框架旧归档只读。

主要入口为 `workflow/native.py`、`adapters/agents/backend.py`、`workflow/direct_checks.py`、`workflow/artifacts.py`、`workflow/transactions.py` 和 `reporting/chinese.py`。旧 `discovery.py`、`agent_tasks.py`、`task_packet.py`、`output_repair.py` 仍为离线 mock 阶段回归服务，不进入默认真实 Codex 路径；历史运行靠 Git 与只读归档保存。

v16 的 C2 和 C3 是定向能力参照。C2 的隔离复跑仍只观察到“注入写失败后的后续 handler 返回”，没有证明生产适配器故障或合法 sender 历史。C3 的隔离复跑观察到 nonvoter 输入下内部 verification 成功；修正必要条件的 checker 仍指出该局部不匹配，但原 harness 直接调用 `notifyAll(true)`，没有复现真实 heartbeat producer。后续 producer、公共 API 与更广后果需另行验证。
