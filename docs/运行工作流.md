# 当前运行工作流

系统采用一条 Domain-assisted、implementation-grounded 路线：自主认识职责与发现 义务与代码工作集，交替探索、复核及局部检查。代码决定可执行行为；义务及问题重要性决定检查意义；证据只支持实际范围，不推导系统正确或覆盖百分比。

## 任务与材料

`Material` 的文件、内容版本和闭区间就是来源引用；引用 ID 用于记录，不决定物理范围是否已提供。`workflow/sources.py` 统一范围包含、对象依赖闭包及真实包中的来源提取。取得、缓存重附加、实际发送和回复引用分别记录。引用可覆盖同版本的相邻片段并集；不同版本或仅同文件名不足以算已提供。

当前的 `targeted_reads` 是取得任何新增源范围的逻辑计划数；同一计划恢复不重复扣额，纯缓存和全延期计划不扣新源配额。总 agent 调用、时间、上下文上限仍有效，重复无进展受修复循环上限约束。历史控制器已有使用量保持原值，不追溯重算；跨版本使用新的运行或明确的离线导入。

`material_chars/material_chunks` 限制唯一取得的源行并集；`context_chars` 限制实际 prompt 字符；schema 单独计量。它们都不是 token 或费用。修复诊断/目标字段仍按 `error_context_chars` 控制；显式请求的来源可重新分配到现有总上下文预算中，最多占其一半。放不下则保存受阻会话，不重复发送等价不足的包。没有新增总预算。

## 修复与语义

已取得但未发送的来源先重附加；未知来源需纠正身份或实际补读；引用不完整先修引用字段。旧缺口使用的所有来源不必机械重复引用，但原问题、理由、反证及剩余条件必须保留。合法引用不等于语义成立。

负面 item 的 aspect 或来源 ID 可受诊断约束地修正；判断、解释、替代机制、反证和限制不能悄悄删除。`condition_dispositions` 对每条原文条件说明它影响旧判断、当前判断或独立范围，并提供依据；未解释或仍影响当前判断的条件继续阻塞相应解除。其语义判断是可复核的候选，不是控制器完成了证明。

未接受且跨声明的 binding 可通过 `binding_splits` 保全拆分：相同文件版本、全部有效代码行、职责关联及单元用途必须保留，每个新定位经过源码校验。它不能改已接受 binding，不能删除行为，涉及物理关系端点的拆分仍需明确联合范围提案。非机械定位可提交显式 draft_patch，再经过同一 ScopeUpdate 与复核；不能修改主张、依赖含义、已选义务或故障范围。输入/类型背景若已关联当前单元主张，不必虚构外部义务；真正外部保证仍须选定的有向依赖路径。

新增候选、ScopeUpdate 和 F2 使用既有写集合、版本和事务。范围接回保留原目标/义务/问题/故障范围，新增支撑不自动增加待检查义务。含义、配置或故障契约变化仍须 F2。无法安全分类的混合改变保留待办，不能靠机械修复放行。

## 模型与上下文

局部包提供从当前 义务与代码工作集 派生的 modeling brief，不建立另一份规范真值。技能要求区分对象、参与者、配置、操作和适用的轮/阶段；旧操作可能在原对象上合法完成，不默认清空旧消息或同步所有节点。

Bundle 的 `context_analysis` 将所声称场景关联到代码 binding、实际动作/变量、checker 和 reachability。跨上下文覆盖需要同一历史和身份的联合触发；单点可达不充数。局部算术可说明跨轮网络不适用。旧 Bundle 没有该描述仍可导入，但报告标明上下文对应性未提供。控制器验证关联与实际配置；任意 TLA+ 与自然语言之间的语义等价仍需复核，不宣称自动证明。

辅助触发搜索采用不与原模型变量重名的状态，避免修改原模型的初始状态含义。TLC 的触发见证、性质反例、校准兼容、真实实现违反是不同层级。模型搜索成功不能补足未知外部契约或缺失实际观测。

## 恢复、权限与后续

修复会话保留原候选、合并版本、patch、诊断、请求来源和有限计数；控制器只消费当前会话结果。读取及 scope 的原子提交、动作复用和模型 commit 机制继续适用。控制器版本变更需要新运行或明确离线子运行；不会重写旧实验。

默认目标原仓库只读，实验隔离；未获授权不发送材料或执行目标，不改变认证或自动增加总调用额度。受控样例、录制回复回放和真实自主运行分别标记。未来大制品的归档方式需要单独授权，归档保留与清理由用户明确指定，不能在分析过程中自行删除失败记录。

## 工作输入与连续交付

建模包包括紧凑职责索引、当前单元及选定 义务与代码工作集、实际源码、有效意见/反证和待办。模型 brief 通过 ID 引用同包对象，不再重复完整历史。receipt 的 `sections` 分别记录源码、当前对象、语义视图、目录、指令和 wire schema 的字符/字节；分组各自序列化统计，不直接相加当作 token。必要源码超限仍受阻，不截断或只发送路径。

复核补读的材料只移交给对应 unit/version。范围后继继承附件；其他单元不会自动收到。暂停单元只有在相关版本、物理源码范围或未决问题发生变化时才唤醒，已消耗预算保持不变。

具体条件优先使用控制器提供的 condition ID。原文本保留；历史精确文本格式仍可读取。缺少、多出、重复的处置有不同诊断，修复包携带当前 item/issue/expected 条件。某个来源缺口的解决不解除独立持久性或历史条件；补读跟进只检查受影响的 target/aspect。

分阶段路径为 `build → model_syntax → model_explore → harness → experiment → calibrate → search/后续队列`。完整 Bundle 仍可一次生成；不强制所有运行多一次调用。搜索前核心依赖缺失则继续补读或保持受阻。SANY 只解析模块，TLC 才检查实际配置；完整搜索的模型层结果和未校准限制同时保留。harness-only 完成会记录新组件版本及显式搜索复用，不伪称又执行了一次 TLC。

## 行为推导方法

三个技能入口继续由 `task-skills.json` 装配。职责参考用决议形成、参与/控制、历史状态、服务效果四个覆盖视角和行为族帮助下钻；不是四个执行阶段，也不要求填满表才建模。具体行为卡通过现有 audit question/brief 表达目的、生产者与消费者、实际效果、跨上下文持续约束、交错和模型计划。被选场景必须映射到真实动作、checker 和触发配置；格式完整本身不证明正确。

## 七类规格与问题续接

当前 framework revision 为 `selected-question-v8`，与 task manifest 共用版本。调度优先完成活跃候选、选中语义修正和可执行 AuditUnit，再选择一个尚未实际尝试的高后果 Surface，随后才开启新候选。新候选和未读 Surface 至少需要两次剩余调用；只剩一次 Agent 调用时，有已取得的当前源码且无必需修正则直接判断，否则暂停并保留材料与恢复条件。`exploration_rounds` 仅计通用 Surface 实际语义尝试，选中/诊断修正受全局调用、时间、补读与停滞预算约束。

工作集由 `task_packet.prepare()` 投影，`inquiry.task_context()` 只传种子和显式来源 ID。源码正文限于显式附件、当前问题依据、新补读与精确诊断材料；全局来源只表示 provenance。保留文件名/行数索引，声明提示按焦点词匹配。Surface 先返回 exact ReadRequest，补读后同任务解释为 delta 或具体 deferred 限制。超限时 L1 删除非必要方向和 README，L2 退到同一 Surface 的导航包；新获得的必需源码不被缩减掉。准备耗尽单独记录，未发送不算已调查。

对象地址统一为 `target_profile`、`A1`–`A7`、Behavior/Fact ID 和 `surface:<entry_point>`。profile 修订依赖焦点和当前来源，不使用字段白名单；局部知识应留在局部对象。语义拒绝带原值、拟值、路径、焦点和来源回到原 `spec_refine`，不进入机械 OutputRepair。格式/引用表示错误仍走原修复路径。报告区分 evidence/workflow/resource 受阻；旧 v5 归档只读，不可原地 resume。

初选或 continue-read 的 source_ids 可以为空，但必须保留合法身份、source_review 和精确阅读请求。terminal explained/blocked_evidence/escalate 必须具备当前来源。回流明确区分 requires_recheck 与 independent_enrichment；后者即使预算耗尽也只留下 pending，不把已解释候选保持为 active。同 Fact/lifecycle 的另一问题须明确改变对象、上下文、事件关系或取得新的相关证据，并说明理由；活跃问题分流时原问题暂停并保留。新候选准入仍为两次调用，没有扩大生产预算。补读预检同时检查唯一源码额度和新逻辑计划次数；纯缓存、部分回执和同计划续做沿用原计费。

没有 execution_backend 时使用源码与本地模型路径；需要直接执行或校准时报告 unavailable，保留已有模型结果。多变体目标的 inspect 与运行采用同一 analysis_roots。先用 inspect 核实边界与安全过滤，再在隔离副本验证工具链；工具 smoke 不创建 Evidence，也不是自主审计。
