# 运行工作流

## 理解与选择

默认读取实际仓库并恢复不完整但一致的 AuditSpec。声明索引、目录和方向摘要只供导航；当前语义判断需要实际源码。候选形成前即可使用 depth 阅读，普通背景扩展使用 breadth。每次取得、缓存重附及延期都有回执；源码区间并集与实际发送包分别计量。

配置可用一个 `activity_focus` 列表声明研究重点。该列表进入首轮 read、discover、候选选择、Surface 补读、fork／重选上下文和报告；它与 `directed_question` 分开。重点中的 Activity 同级，选择依据是具体责任关系的判别价值。未映射 Surface 即使没有 Behavior ID，也能由选题回复显式选作下一项补读；控制器不会按名称另选一个 Surface。导航依据只决定读什么，不能证明规范结论。选题包保留相关错误分支、guards、保护、消费者和未知，不恢复整个全局规格。

候选按原 ID 继续，可解释关闭、证据不足延期、普通暂停、fork，或形成有界义务。普通暂停保存原因和恢复判别，可在同一回复切换到独立问题；它不要求先建 child。已有可执行单元和已受理产物的本地执行、评估优先；活动候选在合同变化、child 完成或关键判别无进展时可以让出调度。合同不足和有反证不能靠重复阅读解决，暂停／恢复不会重置原停滞和预算。

Parent 的更广后果仍未决时，能改变其必要判别且有来源、合同和独立 oracle 的局部关系可以作为 child fork；同一 Derivation 可同时建立 child 与 Obligation，Parent 保持 paused 且不丢失未知。child 的局部检查结论不覆盖或自动恢复 Parent。完成或受阻的 child 会把当前结果、Check/Evidence 关联、范围和剩余判别送入下一次相关选择；已有 Parent 承接同一后续问题时，不再并行建立等价的后果任务。

描述性遗漏通过 descriptive_issues 进入已有 spec_refine。同区域待处理意见合并，在候选处置或检查后集中处理；语义复核从已附带源码得到稳定的 Behavior、Fact 或 Surface 知识时，可在同一回复携带聚焦 AuditSpecDelta，避免另开调用。独立补全不抢占当前检查。相同反馈在对象未变时不重新调用，实际新来源或新问题仍可调查。已被当前理解覆盖的意见可以用空 delta 结束，空更新不制造新的规格版本。

执行 pending inquiry 前会按当前材料重新计算请求范围。已被其他任务取得的源码直接复用，部分覆盖时只读取剩余区间；原始回执和阅读历史不改写。源码齐全而语义处理尚未执行时，报告显示“源码已取得，分析待处理”。

Surface 扩展保留已有 Activity 全局责任，只增补所选 Behavior、Fact 和 Surface。`activity_classes` 只表达研究相关性与阅读范围；Activity 变化必须通过 `target_ids` 显式选中对象，并附完整旧描述和实际来源。原始草稿和反证不丢弃，不能通过合并 unknowns 或局部替换伪造完整性。

## 产物续写与执行

模型回复、直接检查方案和 harness／observation 装配共用原任务续写。`plan=null` 的精确补读、部分设计和校验错误都保留在同一生成任务；补读不计作校验失败，未受理草稿不成为可执行计划。当前包附上新取得或缓存重附的源码；新增生产者、过滤者或绑定仍须显式重连范围。非检查对象的表示修复继续使用受限字段修复。

当前续写优先于无关复核、Surface 和新选题，受既有修复次数、停滞、总调用及时间预算限制。最后一次 Agent 调用接受合法产物后，不消耗 Agent 调用的本地执行可在其工具预算内继续。缺执行能力使用已有模型／来源审查 fallback 或明确延期；工具缺失、权限、超时及框架异常不交给 Agent 猜着修改目标。

直接检查接纳计划后，控制器把当前 AuditUnit 范围关联到制品并生成隔离实验。prerequisites 的条件只检查各自事件，也可只要求事件发生；property trigger 和 monitor 条件选择同一个结果事件，identity_fields 表达稳定操作身份。引用关系声明必要先后，不按列表位置给异步事件强加总顺序。每个结果分别关联实际前提；不唯一或字段缺失时保留原因，比较失败不会被适用条件或身份筛选掩盖。驱动与结束依据独立于被禁止的动作：同一操作的前提、处理完成和结果均有观测，零次非法动作才可能判为有限 holds。更复杂历史需模型或明确限制。

ModelDraft 使用原生 Properties，未完成核心不能注册为可搜索模型。核心完成可先做 SANY 和 TLC，再装配实际 harness、执行和校准；缺执行能力不抹掉模型结果。完整 Bundle 仍可直接接纳。自动性质生成只支持其已实现的共同表达，不能因 schema 接受 reference 就假定模型生成器支持它。

## 结果、暂停与恢复

当前执行状态由实际 CheckRun 决定。编译失败、外部超时、panic、解析残缺、普通测试失败和有归属的属性比较分别保留；非零退出不自动确认缺陷，也不要求先修好目标异常。同一执行在复核后由现有评估路径更新当前结果，Candidate 和报告只读取它；按执行和 checker 覆盖结果，不重复追加实验、证据或发现。完整的有限比较可使执行层有界完成；当前 ReviewIssue 仍阻止归因确认，而不抹掉机械比较。直接检查整体审阅一次：no_issue_found 不能同时携带当前反证，解释过的替代机制写入 rationale，独立边界写入 limitations，真实争议用带来源的 disputed/revision_needed 表达；更广前史不足不抹掉已经观察到的局部比较。

报告列出未完成单元、阶段、具体原因及剩余资源，并从已有 action/check、packet receipt 和读取计划 ID 按问题家族、前沿、AuditUnit、共同启动或 unknown 派生调用、执行和字符成本；每条记录只归属一次，缓存重附不算新增材料。新增评语不会自动重放同一拒绝稿；相关源码或范围实际变化才能支持后续调查。旧问题、版本、草稿、实际输入输出及失败均保留。

成本表按独立问题家族合并 Parent 和 child，并分别显示调用、工具执行、唯一新增源码和实际重复发送量。报告单列真正耗尽的调用、时间、材料或工具上限；合同与能力缺口保留原始候选和 gap，不改写成资源耗尽。字符不换算 token、价格或节省比例。

HashiCorp 模板将下一次比较起点设为 `activity_focus: [A1, A2]`、40 次 Agent 调用、240000 个唯一材料字符、4800 秒、4 个 AuditUnit、8 次实验、4 轮探索和 6 次模型检查；`context_chars=180000`、`action_timeout=600` 与 40 个材料区间保持不变。这是实验配置，不是全局默认或完成保证。与旧无重点运行比较时，重点与预算同时变化，不能称为仅预算对照。

恢复复用输入相同且已完成的昂贵动作；完成不明的执行保留未知并使用新工作副本。框架 revision 来自 resources/task-skills.json，与实际加载清单保持一致。异版归档只读，不承诺跨版本原地恢复，也不把离线受控结果归给原实验。

## 代码入口与保存

| 位置 | 职责 |
| --- | --- |
| core/types.py、proposals.py、ports.py | 领域记录、阶段回复与端口 |
| registry.py、adapters/ | 静态装配、Agent、工具、隔离执行及存储 |
| workflow/discovery.py、audit_spec.py、inquiry.py | 候选、共享理解、集中回流与调度 |
| workflow/agent_tasks.py、task_packet.py、materials.py | 共同续写、必要上下文与统一读取 |
| core/events.py、workflow/direct_checks.py、observations.py | 实际事件关联、直接检查和观察归因 |
| workflow/modeling.py、staged_model.py、artifacts.py | 模型接纳、分阶段执行与装配 |
| workflow/transactions.py、inputs.py | 语义修改事务和已有工具结果适用性 |
| reporting/chinese.py | 从记录导出人工报告及视图 |

新增普通目标优先使用 TargetConfig。新语言或工具仅在确需适配时实现已有端口，并由入口注册；后端不带目标特定的默认答案。运行时方法维护在 resources/skills，机械任务在 resources/tasks；清单引用必须真正加载，Markdown 链接不授权后端读文件。

state.json 是恢复记录；原始 Agent 回复、工具日志、实际语义修订独立保存。派生 graph、audit-progress 等视图供报告，不反向作为运行时输入。源区间只能在同一内容版本内连续拼接；缓存、当前附带、历史引用与语义解释是不同事实。必要材料仍超限时保留阻塞。
