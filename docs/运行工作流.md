# 运行工作流

## 理解与选择

默认读取实际仓库并恢复不完整但一致的 AuditSpec。声明索引、目录和方向摘要只供导航；当前语义判断需要实际源码。候选形成前即可使用 depth 阅读，普通背景扩展使用 breadth。每次取得、缓存重附及延期都有回执；源码区间并集与实际发送包分别计量。

候选按原 ID 继续，可解释关闭、证据不足延期、暂停父问题后分流，或形成有界义务。已有可执行单元优先；处置之后可继续同一库存的其他问题。合同不足和有反证不是靠重复阅读就能解决，连续无进展受原有次数及时间限制。

Parent 的更广后果仍未决时，已有来源、合同和独立 oracle 的局部关系可以作为 child fork；同一 Derivation 可同时建立 child 与 Obligation，Parent 保持 paused 且不丢失未知。child 的局部检查结论不覆盖 Parent。child AuditUnit 一旦 ready，现有调度优先执行它，再处理独立 enrichment 或 Surface。

描述性遗漏通过 descriptive_issues 进入已有 spec_refine。同区域待处理意见合并，在候选处置或检查后集中处理；独立补全不抢占当前检查。相同反馈在对象未变时不重新调用，实际新来源或新问题仍可调查。已被当前理解覆盖的意见可以用空 delta 结束，空更新不制造新的规格版本。

执行 pending inquiry 前会按当前材料重新计算请求范围。已被其他任务取得的源码直接复用，部分覆盖时只读取剩余区间；原始回执和阅读历史不改写。源码齐全而语义处理尚未执行时，报告显示“源码已取得，分析待处理”。

Surface 扩展保留已有 Activity 全局责任，只增补所选 Behavior、Fact 和 Surface。Activity 变化必须显式以其 ID 为焦点并提供完整原描述。原始草稿和反证不丢弃，不能通过合并 unknowns 或局部替换伪造完整性。

## 产物续写与执行

模型回复、直接检查方案和 harness／observation 装配共用原任务续写。类型、引用或表达错误保留原稿、具体错误、当前义务与所需源码，下一次返回同类型完整回复。源码足够但尚未写完时继续生成；上下文缺源使用共享读取入口，新增依赖仍走原有范围重连。非检查对象的表示修复继续使用受限字段修复。

当前续写优先于无关复核、Surface 和新选题，受既有修复次数、停滞、总调用及时间预算限制。最后一次 Agent 调用接受合法产物后，不消耗 Agent 调用的本地执行可在其工具预算内继续。缺执行能力使用已有模型／来源审查 fallback 或明确延期；工具缺失、权限、超时及框架异常不交给 Agent 猜着修改目标。

直接检查接纳计划后，控制器把当前 AuditUnit 范围关联到制品并生成隔离实验。prerequisites 的条件只检查各自事件，也可只要求事件发生；property trigger 和 monitor 条件选择同一个结果事件，identity_fields 表达稳定操作身份。引用关系声明必要先后，不按列表位置给异步事件强加总顺序。每个结果分别关联实际前提；不唯一或字段缺失时保留原因，比较失败不会被适用条件或身份筛选掩盖。更复杂历史需模型或明确限制。

ModelDraft 使用原生 Properties，未完成核心不能注册为可搜索模型。核心完成可先做 SANY 和 TLC，再装配实际 harness、执行和校准；缺执行能力不抹掉模型结果。完整 Bundle 仍可直接接纳。自动性质生成只支持其已实现的共同表达，不能因 schema 接受 reference 就假定模型生成器支持它。

## 结果、暂停与恢复

当前执行状态由实际 CheckRun 决定。编译失败、外部超时、panic、解析残缺、普通测试失败和有归属的属性比较分别保留；非零退出不自动确认缺陷，也不要求先修好目标异常。同一执行可在复核后重新解释，但按执行和 checker 覆盖当前结果，不重复追加实验、证据或发现。完整的有限比较可使本次有界检查完成；这不证明一般义务。直接检查整体审阅一次，真实争议仍须明确处理；更广前史不足不抹掉已经观察到的局部比较。

报告列出未完成单元、阶段、具体原因及剩余资源，不能只显示新选题预算不足。新增评语不会自动重放同一拒绝稿；相关源码或范围实际变化才能支持后续调查。旧问题、版本、草稿、实际输入输出及失败均保留。

恢复复用输入相同且已完成的昂贵动作；完成不明的执行保留未知并使用新工作副本。框架 revision 来自 resources/task-skills.json，与实际加载清单保持一致。异版归档只读，不承诺跨版本原地恢复，也不把离线受控结果归给原实验。

## 代码入口与保存

| 位置 | 职责 |
| --- | --- |
| core/types.py、proposals.py、ports.py | 领域记录、阶段回复与端口 |
| registry.py、adapters/ | 静态装配、Agent、工具、隔离执行及存储 |
| workflow/discovery.py、audit_spec.py、inquiry.py | 候选、共享理解、集中回流与调度 |
| workflow/agent_tasks.py、task_packet.py、materials.py | 共同续写、必要上下文与统一读取 |
| core/events.py、workflow/direct_checks.py、observations.py | 实际事件关联、直接检查和观察归因 |
| workflow/modeling.py、staged_model.py、artifacts.py | 模型接纳、分阶段执行与装配 |
| workflow/transactions.py、inputs.py | 语义修改事务和已有工具结果适用性 |
| reporting/chinese.py | 从记录导出人工报告及视图 |

新增普通目标优先使用 TargetConfig。新语言或工具仅在确需适配时实现已有端口，并由入口注册；后端不带目标特定的默认答案。运行时方法维护在 resources/skills，机械任务在 resources/tasks；清单引用必须真正加载，Markdown 链接不授权后端读文件。

state.json 是恢复记录；原始 Agent 回复、工具日志、实际语义修订独立保存。派生 graph、audit-progress 等视图供报告，不反向作为运行时输入。源区间只能在同一内容版本内连续拼接；缓存、当前附带、历史引用与语义解释是不同事实。必要材料仍超限时保留阻塞。
