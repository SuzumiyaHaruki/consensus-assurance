# 运行工作流

`audit-products-v62` 使用一条调查和执行路径。Codex 在授权源码快照中阅读、搜索，在草稿目录编辑；控制器校验完整文件，按操作身份受理，从干净副本执行并留存原始输出。

## 一份更新，三类责任

- Investigation 保存问题、假设、来源、当前处置、必要缺口和历史；有来源的局部问题可以立即开始，无需地图或完整义务。
- FixedExperiment 保存源码与配置依据、完整驱动及辅助文件、包落点、条件与前史、可选要求和统一比较记录。条件探索与正式检查共用执行路径。
- Interpretation 保存对具体来源和回执的解释、决定性事件索引、必要缺口的答复、反证及限制。它是可修正的意见，不能改写实际输出。

Behavior／Fact 是轻量共享知识：记录条件与来源，通过条目 ID、修订号和必要时的具体断言引用。Behavior 描述实际条件行为；Fact 描述其真正建立的条件性断言。修正保留旧版本和实际引用者，只挑战明确受影响的使用。独立新增和相似词汇不触发失效。

提交信封包含 `rationale`，其余 `sources / investigations / knowledge / gaps / interpretations / experiment / stop` 按需提供。一次可以保存解释、修正知识并请求一次新执行；多个测试和控制场景可共用这一执行。新问题或知识用可选 `@name` 在同批引用，控制器生成 ID、修订号和比较索引；已有对象使用显式 ID。`research.json` 提供最小示例和 schema 路径，无需先读完整 schema。

不存在 Unit、Claim／Binding／Relation 图、GraphPatch 或独立 Evidence／Finding 生命周期。已验证源码锚点嵌入实验依据；一个比较记录拥有事件、独立身份、准入关联、可选前件及断言，不再维护两套配对 ID。

## 修订、反馈与证据

解释错误而固定输入未变时，使用原来源和原回执修正解释，旧意见保留，无需造新引用或重跑。要求、驱动、比较或适用条件变化时，提交 `previous_id / revision_reason`，保留真实差异，并取得后继实验自己的执行。旧回执不能冒充后继执行。关联独立生产者回执时说明共同前史的兼容性，数字相同不证明同一历史。

必要缺口登记在所属调查下，可限定到一个实验及后继。按具体 gap ID 给出来源化或观测支持的答复；普通认可不清除缺口，局部子问题不自动解决父问题。当前结论、测量与工具状态分别展示；进程成功不能代替独立判据与完整见证。失败、超时、取消和缺失输出保留。仅完整违反见证之后的独立测试失败可能适用狭窄归因例外。

`research.json` 和短反馈给出当前问题、最近实际结果及位置、必要缺口、知识更正与剩余能力。完整历史位于 `state.json`、固定制品和回执。相同有效更新保留原始回复和成本，但不重复创建语义版本；没有相似度判定或重复次数停止策略。

完整文件先在副本预检，预检不计预算、不产生受理凭证。正式受理读取保存的实际字节。拒绝稿连同全部诊断交回同一会话；操作身份事务和回执恢复防止部分受理或重复执行。

## 资源与恢复

开放调查持续有用工作到时间／调用边界或真实中断。正式执行额度耗尽后仍可进行源码调查；局部暂停不结束整轮。只有预先配置的有限定向任务在必要工作完成后可以提前结束。没有发现、复核、修订或图对象配额。

每个新 run 使用独立原生会话，显式恢复才续接原会话。源码与可信指令只读、草稿可写、凭据隔离、目标执行隔离、构建输入保护及子进程清理保留原边界。服务拒绝是外部中断，不自动绕过或换会话重试。旧方法在写入、工具探测和模型调用前拒绝执行／恢复；保存的旧报告可以直接读取。

代码入口：`workflow/audit.py` 统一受理和执行，`experiments.py` 固定输入和有限观测，`knowledge.py` 问题、知识和解释，`research.py` 只读当前视图，`transactions.py` 原有操作身份事务。机械合同和实际加载路径由 `resources/task-skills.json` 指定。
