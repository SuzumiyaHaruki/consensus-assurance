可单独复核的中性轨迹：

```bash

  tests/integration/test_execution_evidence.py::test_bounded_retry_cycle_controls_and_historical_failures \
```

1. RetryQueue 从构造器和 enqueue 开始，真实执行四／六次正常 tick，保留 phase 前后值、完成计数和实际观测时长。reset 分支反复恢复同一待处理状态；相同采样下正常分支两次 tick 后完成。先保存坏关联版本，再保存后续收尾失败，最后独立执行修正版；修正版两个分支均可确认有界违反，对照为 holds，非空反证与限制不阻塞。零服务机会的另一版本保留条件性解释和必要 Gap，不能冒充活性结论。没有无限等待，也没有“永久阻塞”自证字段。
2. Worker 首先用供给状态探测，再经 begin/report 建立真实生产前史。过宽 Behavior r1 被调查、固定实验及解释明确引用；独立执行 protected 分支后，在原 id 上更正为“reporting 分支在 report 后放行，protected 分支需要 finish”的 r2。旧依据和回执仍可读，只有指明的三个使用位置被质疑；其他知识及独立调查不受牵连。
3. 精确重复更正只记成本、不产生 r3；下一短提示提供全局选择和已更正条目。随后可以处理独立的 authority/epoch 问题，也可以新建使用 r2 的局部 finish 问题；两者均没有强制父链接，不重开 session。测试只验证这种路径可用，不要求真实运行必须各做一个。

测试使用提供的判断和脚本化模型传输；RetryQueue 的目标回执来自真实 bwrap 隔离进程。它们验证状态、来源、执行与解释之间的接线，不能证明模型总会发现矛盾、正确理解活性或改善自主发现率。
