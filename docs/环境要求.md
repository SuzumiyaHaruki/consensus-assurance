# 环境、目标与开发

## 安装和工具

当前实现面向 Linux，Python 需要 3.10 或更新版本。Python 依赖以 requirements.txt、requirements-dev.txt 和 pyproject.toml 为准：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m pip check
```

Go、Rust/Cargo、Codex CLI 和 bubblewrap 是外部工具，不由 pip 安装。内置 TLA/TLC 链已退出，运行和回归无需 Java/JAR；工具链须满足目标及依赖的版本要求。Rust 声明定位使用 Tree-sitter Rust 语法库，Python 3.10 使用 tomli 读取 Cargo 清单，均列入项目依赖。Codex 通过本机版本、命令帮助和文件权限探针核验能力；默认沿用现有认证，显式 provider 使用指定环境变量，不自动切换后端。Agent 调用记录 CLI 版本、显式模型及推理强度、会话 ID、工具事件和可取得的 usage；缺失数据保持未知。

将实际工具目录加入 PATH；Codex 若装在用户目录，可用 `export PATH="$HOME/.local/bin:$PATH"`。所选工具的 bin 目录也须可见。本地工具和虚拟环境不提交。旧 `verifier_backend`、`tlc_jar`、`model_checks`、`reachability_checks`、`trigger_retries` 配置已不再支持，请从当前模板生成新配置；程序明确拒绝，不静默降级。

## 最小运行

从框架根目录显式指定目标。缺少目标时报告错误，不猜桌面路径或下载替代仓库：

```bash
.venv/bin/consensus-assurance inspect \
  --config configs/targets/etcd_raft.yaml --repo /实际路径/etcd-raft
.venv/bin/consensus-assurance estimate \
  --config configs/targets/etcd_raft.yaml --repo /实际路径/etcd-raft
.venv/bin/consensus-assurance doctor --config configs/targets/etcd_raft.yaml
```

inspect 保存只读快照，estimate 不发送源码，只显示Agent 调用及执行的预算上限；doctor 探测本机工具。它们不等于协议检查完成。真实运行需要材料发送和隔离执行授权；已获授权时生成本地配置：

```bash
sed -e 's/^allow_agent_materials: false$/allow_agent_materials: true/' \
    -e 's/^allow_experiments: false$/allow_experiments: true/' \
    configs/targets/etcd_raft.yaml > configs/targets/etcd_raft.run.yaml
.venv/bin/consensus-assurance run \
  --config configs/targets/etcd_raft.run.yaml --repo /实际路径/etcd-raft
```

权限覆盖 *.run.yaml 不提交。`activity_focus` 只改变自主阅读和选择取向，`--question` 仍用于具体定向调查；当前五个目标的 GPT 模板显式使用 astra / low。预算以所用 YAML 为准，不自动提高模型强度、调用或时长。`agent_turn_timeout` 管 Codex 单次连续调查（恢复时可用 `--agent-turn-timeout` 调整），`action_timeout` 管正式工具动作，二者均受剩余 `total_seconds` 限制。旧材料字符和 packet 配额已删除；旧本地 `.run.yaml` 如包含已删除字段，需要从当前模板重新生成，不会静默忽略。

扩大预算不会打开权限。提交的目标配置继续保持 `allow_agent_materials: false` 和 `allow_experiments: false`；只有明确获权后生成的本地 `*.run.yaml` 才能发送材料或执行目标实验。Agent 调用耗尽后，已经受理的本地工具产物仍可在剩余总时长和对应工具预算内执行、评估并写报告，不能借此新增 Agent 调用。

延长到 80 分钟时，在所选目标的本地配置中将 `budget.total_seconds` 改为 `4800`，其他额度按实际需要显式设置；无需再保留一套时长专用模板。先确保 `PATH` 中的 Go 满足目标 `go.mod`；正式执行使用 `GOTOOLCHAIN=local`，不会自动升级或下载。

`estimate` 只打印实际配置和计数口径，不实例化执行后端或发送模型请求。探索、失败重试和正式检查共享执行额度；Codex 回合内本地试跑不在该控制器计数中，但仍受原权限和总时限限制。`audit_units` 只约束入场，不保证后续执行／复核链可完成；执行额度耗尽后仍可保存有预算的源码反馈，复核额度耗尽则保留未复核结果。剩余次数从配置和 usage 派生，不自动扩容或兑换。旧运行配置不因修改模板而改变。

新运行写入独立 runs 目录。使用 `report --run /实际运行目录` 查看；`resume --run /实际运行目录` 只恢复同版本运行，保留精确 session ID，不以 `--last` 串联运行。可信传输故障支持显式新尝试，其范围见[运行工作流](运行工作流.md)；认证、拒绝、未知超时仍需人工处理，不自动换账号、模型或会话。可显式调整后续动作／Agent 单轮超时，已用总时间和调用数不重置。报告的 `timeout_limit` 区分单轮、目标动作与总时限。原始归档的保留及删除需要明确授权，当前索引见 [runs/README.md](../runs/README.md)。

## Codex 的显式模型提供方

仍使用同一个 `agent_backend: codex`。原生 GPT 配置省略 `codex_provider` 或设为 `null`，不改变现有调用路径。DeepSeek 使用单一 [deepseek.example.yaml](../configs/targets/deepseek.example.yaml)：请求 `deepseek-flash`、显式 `low`、官方 `https://api.deepseek.com` 和环境变量名 `DEEPSEEK_API_KEY`。它是通用 Go 示例；用于已有目标时，将其中的 `agent_model`、`agent_reasoning_effort`、`codex_provider` 整体复制到该目标的新本地 `*.run.yaml`，保留其执行后端、包／crate、工具与预算。目录路径相对 YAML 所在目录解析。示例两项授权均为 false，不自动发送源码或运行目标。

新建与精确 `exec resume <session>` 共用连接参数，均保留 `--ignore-user-config`；不读取个人配置来选服务，不修改 `~/.codex/config.toml` 或登录状态。仅支持 HTTPS、Responses 和环境变量认证；不接受密钥正文、任意 headers、shell 认证或附加 CLI 参数。自定义路径禁用 WebSocket 和 web search。缺少模型、密钥或可验证权限时停止；inspect／estimate／report 不需要真实密钥。更换 provider、endpoint、请求模型、推理档位、Codex 版本或目录字节需要新 run，恢复及已存动作结果复用前均核对；保留旧证据。

密钥只在 Codex 客户端环境中使用，不写入 YAML、命令参数、研究状态或日志；模型 shell 显式排除所选变量，正式目标仍用干净环境和禁网隔离。新 run 不记录或哈希密钥值，因此不能用运行记录辨认账号；更换凭据应重新确认访问授权，不能推断为相同账户。报告区分请求配置与实际服务端身份；本机 CLI JSONL 未提供可靠的服务端模型／版本字段，保持未记录。历史配置没有 provider 字段时也保持未记录，不从模型名推断认证入口。

2026-10-05 核对：[DeepSeek 手工 Codex 接入](https://api-docs.deepseek.com/quick_start/agent_integrations/codex/)、[模型别名](https://api-docs.deepseek.com/quick_start/pricing/)、[Responses 兼容说明](https://api-docs.deepseek.com/guides/responses_api/)、[Codex 配置参考](https://developers.openai.com/codex/config-reference/)。当前别名对应 V4.1 Flash，但不保证以后仍是同一权重版本。DeepSeek 无服务端会话存储，需要 Codex 恢复并发送客户端历史；developer 被当作 user，函数工具和 `apply_patch` 自定义工具受支持，其他内置工具被忽略；文档声明 text.format 支持，verbosity 不生效、reasoning summary 不生成。这些是接口文档结论，工具循环、最终 schema 与续接仍需实际验收，框架不自行翻译流或伪造历史。

## TargetConfig 与隔离边界

execution_backend 可选 none、go_module、cargo 或 python。没有执行后端仍可保存来源化研究问题，不能生成正式实现检查。当前真实Codex 工具会话要求 `allow_experiments: true`，因为本机 CLI 的终端能力不能保证“可任意读源码却绝不执行目标代码”。未授权执行时仅使用 inspect/estimate，不发送Codex 调查任务。新增普通 Go 目标使用现有后端，在 YAML 中指定 variant、可选 expected_module、analysis_roots、execution_package 和 harness_path；expected_module 校验 Go 的 go.mod，不用于 Rust。配置路径相对配置文件解析，目标路径由 --repo 或 repo_path 明确给出；无需为每个仓库写 adapter 或手册。

[Dragonboat 配置](../configs/targets/dragonboat.yaml) 对应官方稳定版 [v3.3.8](https://github.com/lni/dragonboat/releases/tag/v3.3.8)，模块为 `github.com/lni/dragonboat/v3`；已用 Go 1.23.5 验证离线隔离构建。预算为 40 分钟，模型为 astra / low。阅读范围覆盖全仓，默认执行包为根包 `dragonboat`；单次检查或探索可选择同一模块内的其他包，未预置候选问题或历史实验输入。启动时将兼容 Go 的 bin 目录与 `$HOME/.local/bin` 一起加入 PATH，避免沿用其他目标所需的工具链。

[EPaxos 配置](../configs/targets/swiftpaxos_epaxos.yaml) 使用 [imdea-software/swiftpaxos](https://github.com/imdea-software/swiftpaxos) 中的修订版 EPaxos，固定到 2026-08-17 的提交 `35c69365f1c7737a08e237bfbaf828ee68897080`。上游没有 release 或版本标签，不能称为官方稳定发布。本机完整仓库位于 `/home/nitro/Desktop/epaxos`，保持源码不改；阅读范围为 EPaxos、调用入口和公共支撑代码，默认执行包 `./epaxos`，复用通用 Go 后端。Go 1.25.8 已通过离线 bubblewrap 构建及实际消息编解码冒烟检查；上游该包没有现成测试，接入验证与协议正确性结论分开。配置沿用 astra / low、40 分钟、40 次 Agent 调用、16 次控制器执行，默认自主选题，不附带旧实验答案。运行时使用 `export PATH="/usr/local/go/bin:$HOME/.local/bin:$PATH"`，本地授权配置为 `swiftpaxos_epaxos.run.yaml`。该实现含实例恢复代码，源码注明移除了 checkpoint，构造器固定启用 thrifty；持久化写入不等于完整重启恢复，成员变化及恢复支持范围仍需依据实际调用链调查，不从其他 Paxos／Raft 实现迁入假设。

[OmniPaxos 配置](../configs/targets/omnipaxos.yaml) 对应 crates.io 的非预发布版本 [0.2.3](https://crates.io/crates/omnipaxos/0.2.3)，发布于 2026-09-24。官方仓库没有版本标签；发布包的 `.cargo_vcs_info.json` 指向提交 `827f304846ab0c5aa40910b6f6cdce1d4ddf8e12`。默认 crate 为 `omnipaxos`，全仓可读，不预置审计问题。配置为 astra / low、40 分钟、40 次 Agent 调用、16 次控制器执行；目标动作上限 1200 秒，Agent 单轮 900 秒，均受总期限约束。测试依赖包含 RocksDB，冷构建成本较高，不保证在一个短实验中完成多次正式检查。

Rust 使用通用 `cargo` 后端和已安装工具链。将实际工具链目录与 Codex 目录一起加入 PATH，例如 `export PATH="$HOME/.rustup/toolchains/1.94.1-x86_64-unknown-linux-gnu/bin:$HOME/.local/bin:$PATH"`；不会改变 rustup 全局默认或覆盖 Codex 注入的辅助目录。依赖预取须在独立源码副本执行 `cargo fetch`；本机 1.88 低于此次依赖解析中声明的 1.94.1 要求，因此另装 1.94.1。控制器只读挂载工具链和 Cargo 的 registry/git 缓存，不开放整个 Cargo 主目录或凭据，也不在实验中联网下载。

Rust 的 execution_package 表示一个包含 Cargo.toml 的具体 crate 目录。正式检查与探索共用位置解析，主文件固定为该 crate 下的 `tests/<配置文件名>.rs`；通过 `cargo test --locked --offline --manifest-path ... --test <文件名> --message-format=json -- --nocapture --test-threads=1` 运行单个生成测试目标。保留原清单、工具配置与已有锁文件字节；无锁工作区由控制器在隔离副本离线解析一次，将锁文件原值、来源、工具版本、环境和目标保存到 run 的 `build-inputs`，不写回源码。Agent 可按 `research.json` 导航读取，不能修改。后续动作和结果恢复先校验这份依据；锁、源码、工具或构建环境变化要求新 run，离线准备失败不降级下载。

具体 crate／集成测试目标没有可复用种子时，先按该目标的依赖规则作 `--no-run` 构建，再由 Cargo 清理所选 crate 的产物，留下依赖构建种子。每个动作将匹配种子复制／reflink 到自己的 `.execution/cargo-target`，重新构建并执行当前 harness；目标测试不挂载种子，测试数据和输出不回流。`research.json` 的 `build_inputs` 只读区分尚未准备、依据已固定、存在可尝试物化的种子、仅有历史准备记录以及最近准备失败／超时；未列出的目标不代表已准备，缓存存在也不代替执行时验证。移动归档或删除 `.execution` 后需重新准备，历史执行证据仍有效。固定沙箱路径维持原生构建路径一致；准备、复制和执行照常计入原总预算。

默认仅在当前 run 内复用种子。Cargo 配置可显式设置 `cargo_seed_cache_dir: /home/nitro/.cache/consensus-assurance/cargo-seeds`，在同一受控本机跨独立 run 复用；相对路径按配置文件目录解释。目录必须由控制器用户所有且权限为 `0700`（不存在时自动创建），不得使用符号链接或位于源码、runs、草稿及动作工作区内；非 Cargo 后端拒绝此参数。只发布中性 `--no-run` 构建并清理所选包后的依赖产物，不导入旧调查、harness 或执行结果，不向 Agent／目标开放共享写权限。

新 run 先建立自己的源码、锁和工具依据，再精确匹配源码内容与权限、workspace／目标、features、命令／环境及种子制作版本，校验共享产物字节后复制到 run 内。无条目或条目损坏时记录原因并按原流程冷准备；半成品不可命中，所有步骤仍受原期限限制。`build-inputs` 下的种子回执区分当前构建与外部中性来源，记录命中原因、校验／物化耗时和本 run 的日志入口；不把来源构建 ID 或费用计为当前执行。缓存删除不影响保留的依据与实际观察。

正常接入验收应分别核对具体 crate／集成测试目标；依赖 fetch、库编译或较轻 crate 的成功不代表另一重依赖目标已就绪。只有当前动作实际物化匹配种子才报告复用，Cargo 的 fresh／重建记录仍为实际依据。本地源码复制可能触发 Cargo 重建路径依赖，不手改指纹或时间戳来制造命中。切换 crate 或构建变体仍可能需要冷准备；不因此禁止选题或改变预算起算。

模型成本对照分开报告中性冷准备、共享种子校验／物化、当前目标进程与整个动作，固定源码、工具、features 和依赖；整个动作包含其子阶段，不重复相加。另行工程验收的首次制作成本也应单列，不能算作零成本热启动。

不额外开关 features；原依赖及 dev-dependencies 可能联合启用更多接口，解析摘要与实际 `compiler-artifact` 分开记录。集成测试通过公开 API 调用实现，不自动开放私有状态。Rust 声明定位仍只验证物理源码和 impl/trait 上下文，不证明 cfg 激活。超时也保留构建活动、测试启动和实际比较的区别；进程成功不替代前提、独立 oracle 或对应性复核。Cargo 复用语义见[构建缓存](https://doc.rust-lang.org/cargo/reference/build-cache.html)与[机器可读输出](https://doc.rust-lang.org/cargo/reference/external-tools.html)。

单次 Go 包覆盖在正式计划的 `harness.execution_package` 或探索提交的 `execution_package` 填一次。省略时保留 run 配置的包和主文件落点；显式选择如 `internal/core` 时规范化为 `./internal/core`，主文件落到该目录，复用已配置主文件的文件名。`submission.harness_path` 始终是草稿来源，`files` 的键始终是工作副本根目录下的目标路径，不额外加子包前缀。包声明由实际源码确定，可以使用合法的外部测试包。有效包在受理时写入 Harness，主文件落点固定在制品路径（探索保存在受理状态和动作输入）；命令、工具版本与落点留在 CheckRun。修订切包产生新制品、重新执行和复核，不转移旧确认。

每次仅执行一个已捕获模块内的现有包，禁止路径逃逸、通配模式、跨模块、工作区及依赖配置覆盖；不修改全局后端、不猜测并改写包声明，也不需要根测试嵌套启动 Go。Python 不支持 Go 包覆盖。历史根包启动器及原始证据保持原样。

Go 后端读取 `go test -json` 时按 Package/Test 所属流累积 Output 片段，再解析完整的 `CA_EVENT` 行；测试流与包级流不猜测拼接。残缺或非法事件保留日志位置并使相关比较未知。普通文本中的完整 `CA_EVENT` 仍直接支持。新 Go 动作的 `action_seconds` 包围 `execute_harness` 内的工作副本准备、测试安装、进程执行、结果解析与执行差异保存，不包含返回后的语义评估和外层源码完整性检查；Cargo 保留其适配器内准备／复制／执行区间，两者不是完全相同的成本范围。进程时间仍独立记录；恢复沿用旧动作时间，只有原始进程回执或旧记录缺失时保持未知，不用恢复耗时补齐。

安全快照保留构建所需文件，`readable_files` 再按 `analysis_roots` 限定可分析源码。Codex 只看到由这些文件生成的 `agent-source` 视图；完整快照留给可信 runner 装配正式执行。目标 AGENTS.md、SKILL.md、凭据样式及敏感内容被排除。最终关键引用仍要由控制器按路径、行范围和快照版本复核；机械定位不证明语义判断。

Go 依赖须已存在于用户模块缓存。实验使用 GOPROXY=off、GOSUMDB=off、GOTOOLCHAIN=local、GOWORK=off 和 -mod=readonly，不自动下载；准备依赖应在独立目标副本进行。后端用可信 argv 编译或执行 TestAssurance 前缀测试；全包编译只说明构建能力，不建立精确调度能力。controlled_schedule 是所需方法，不代表已有集群控制器。

Codex 使用文件权限配置：默认拒读磁盘，只开放 `agent-source` 和相关已保存证据的读取以及草稿写入；模型控制的命令禁网且不继承宿主密钥环境。发送模型任务前，在同一进程、版本和权限配置下实测可读、可写、拒写、拒读及禁网边界；成功结果仅在该进程和配置内缓存。失败或探针自身不能运行都不发送模型任务，也不占用 `agent_calls`。正式目标程序仍由 bubblewrap 在干净副本中运行，凭据与用户主目录被隔离；不可用时如实受阻，不降级为 workspace 模式。

## 开发验证

涉及目标实现的测试只在隔离副本执行，原目标和保留运行只读。使用已安装虚拟环境、把副本 src 放入 PYTHONPATH，可先运行相关短回归：

```bash
PYTHONPATH=src \
  /原框架路径/.venv/bin/python -m pytest -q \
  tests/integration/test_audit_products.py tests/integration/test_direct_checks.py tests/unit/test_codex_agent.py
```

只有变更范围或明确要求需要全量时，才在同一隔离环境运行 `python -m pytest -q`；通常先用聚焦回归覆盖修改合同。工具缺失、跳过、失败和未执行必须分别报告；不为回归自动下载环境或启动付费自主调查。Mock 仅模拟 Agent 回复，实际 runner 记录支持相应小目标的有限直接观察；预设输入、录制回复、真实工具执行和自主分析分开归因。历史目标定向工具只在另行请求时执行，不作为默认发现或必过条件。

## 本机 Codex 沙箱兼容

本机 `codex-cli 0.155.0-alpha.16` 遇到 nsfs 的非绝对 mount root 时，直接启动沙箱可能在执行命令之前失败。适配器仅在检测到这一 mountinfo 形式时，通过外层 bubblewrap 提供正常挂载视图，内层 Codex 文件权限和禁网仍生效；没有使用关闭沙箱参数。用户认证仍由现有 CLI 使用，不迁移凭据。

本次 canary 检查在用户缓存目录通过：源码、日志、已保存 checker 可读不可写；草稿可写；私有 canary 和网络被拒。本机同样的运行目录若放在 `/tmp` 下，会受到显式临时目录拒读规则影响，正向读控制失败；保持拒绝发送，不将这个启动问题算作“沙箱已正确拒读”。默认桌面仓库下的 runs 不受这个路径冲突影响。探针日志保留实际错误，不能用任意非零退出码证明安全。

Agent 可在运行持锁时调用研究索引给出的 `validate` 命令。权限额外只读开放实际解释器目录、安装依赖目录和受信任包目录；不开放完整工作区、原始 source 或其他运行。权限探针同时验证校验器可启动以及工具／证据拒写，失败时停止发送源码。预检不安装依赖、不探测外部工具、不执行目标，输出不是正式受理或证据。
