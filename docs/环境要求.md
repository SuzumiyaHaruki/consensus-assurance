# 环境、目标与开发

## 安装和工具

当前实现面向 Linux，Python 需要 3.10 或更新版本。Python 依赖以 requirements.txt、requirements-dev.txt 和 pyproject.toml 为准：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m pip check
```

Java/TLC、Go、Codex CLI 和 bubblewrap 是外部工具，不由 pip 安装。已有检查使用 Java 17、TLC 发布包 v1.7.4（工具报告 2.19）和 Go 1.25.8；目标工具链仍以其 go.mod 为准。Codex 通过本机版本、命令帮助和文件权限探针核验能力；真实调用沿用现有认证，不读取凭据或自动切换后端。原生调用记录 CLI 版本、显式模型及推理强度、会话 ID、工具事件和可取得的 usage；缺失数据保持未知。

将实际工具目录加入 PATH；Codex 若装在用户目录，可用 `export PATH="$HOME/.local/bin:$PATH"`。Java 和 Go 的 bin 目录也须可见。通过 `export TLC_JAR="/实际路径/tla2tools.jar"` 指定已准备的官方 JAR；本地 .tools 和虚拟环境不提交。

## 最小运行

从框架根目录显式指定目标。缺少目标时报告错误，不猜桌面路径或下载替代仓库：

```bash
.venv/bin/consensus-assurance inspect \
  --config configs/targets/swiftpaxos_paxos.yaml --repo /实际路径/swiftpaxos
.venv/bin/consensus-assurance estimate \
  --config configs/targets/swiftpaxos_paxos.yaml --repo /实际路径/swiftpaxos
.venv/bin/consensus-assurance doctor --config configs/targets/swiftpaxos_paxos.yaml
```

inspect 保存只读快照，estimate 不发送源码，只显示原生调用及执行的预算上限；doctor 探测本机工具。它们不等于协议检查完成。真实运行需要材料发送和隔离执行授权；已获授权时生成本地配置：

```bash
sed -e 's/^allow_agent_materials: false$/allow_agent_materials: true/' \
    -e 's/^allow_experiments: false$/allow_experiments: true/' \
    configs/targets/swiftpaxos_paxos.yaml > configs/targets/swiftpaxos_paxos.run.yaml
.venv/bin/consensus-assurance run \
  --config configs/targets/swiftpaxos_paxos.run.yaml --repo /实际路径/swiftpaxos
```

权限覆盖 *.run.yaml 不提交。`activity_focus` 只改变自主阅读和选择取向，`--question` 仍用于具体定向调查；Paxos 模板显式使用 medium，HashiCorp 模板显式使用 low。预算以所用 YAML 为准，不自动提高模型强度、调用或时长。`native_turn_timeout` 管 Codex 单次连续调查，`action_timeout` 管正式工具动作，二者均受剩余 `total_seconds` 限制。旧材料字符及 packet 预算不作用于原生路径。

扩大预算不会打开权限。提交的目标配置继续保持 `allow_agent_materials: false` 和 `allow_experiments: false`；只有明确获权后生成的本地 `*.run.yaml` 才能发送材料或执行目标实验。Agent 调用耗尽后，已经受理的本地工具产物仍可在剩余总时长和对应工具预算内执行、评估并写报告，不能借此新增 Agent 调用。

新运行写入独立 runs 目录。使用 `report --run /实际运行目录` 查看，使用 `resume --run /实际运行目录` 恢复同版本运行；可显式调整后续正式动作或原生 turn 的超时，但不重置已用预算。精确 session ID 用于继续，不以 `--last` 串联运行。退出码和测试通过都不能单独表示协议正确。原始归档的保留及删除需要明确授权，当前索引见 [runs/README.md](../runs/README.md)。

## TargetConfig 与隔离边界

execution_backend 可选 none、go_module 或 python。没有执行后端仍可阅读、形成问题和执行受支持的局部模型；直接实验及实现校准会说明缺口。新增普通 Go 目标使用现有后端，在 YAML 中指定 variant、可选 expected_module、analysis_roots、execution_package 和 harness_path。配置路径相对配置文件解析，目标路径由 --repo 或 repo_path 明确给出；无需为每个仓库写 adapter 或手册。

Go 后端读取 `go test -json` 时按 Package/Test 所属流累积 Output 片段，再解析完整的 `CA_EVENT` 行；测试流与包级流不猜测拼接。残缺或非法事件保留日志位置并使相关比较未知。普通文本中的完整 `CA_EVENT` 仍直接支持。

安全快照保留构建所需文件，`readable_files` 再按 `analysis_roots` 限定可分析源码。原生 Agent 只看到由这些文件生成的 `native-source` 视图；完整快照留给可信 runner 装配正式执行。目标 AGENTS.md、SKILL.md、凭据样式及敏感内容被排除。最终关键引用仍要由控制器按路径、行范围和快照版本复核；机械定位不证明语义判断。

Go 依赖须已存在于用户模块缓存。实验使用 GOPROXY=off、GOSUMDB=off、GOTOOLCHAIN=local 和 -mod=readonly，不自动下载；准备依赖应在独立目标副本进行。后端用可信 argv 编译或执行 TestAssurance 前缀测试；全包编译只说明构建能力，不建立精确调度能力。controlled_schedule 是所需方法，不代表已有集群控制器。

原生 Codex 使用文件权限配置：默认拒读磁盘，只开放 `native-source` 和相关已保存证据的读取以及草稿写入；模型控制的命令禁网且不继承宿主密钥环境。每次发送模型任务前，以本机沙箱命令实测可读、可写和拒读边界；失败则不发送。正式目标程序仍由 bubblewrap 在干净副本中运行，凭据与用户主目录被隔离；不可用时如实受阻，不降级为 workspace 模式。TLC 的本地初始化可能需要 socket，权限限制应报告工具错误。

## 开发验证

涉及目标实现的测试只在隔离副本执行，原目标和保留运行只读。使用已安装虚拟环境、把副本 src 放入 PYTHONPATH，可先运行相关短回归：

```bash
PYTHONPATH=src TLC_JAR=/实际路径/tla2tools.jar \
  /原框架路径/.venv/bin/python -m pytest -q \
  tests/integration/test_direct_checks.py tests/e2e/test_staged_models.py
```

只有变更范围或明确要求需要全量时，才在同一隔离环境运行 `python -m pytest -q`；通常先用聚焦回归覆盖修改合同。工具缺失、跳过、失败和未执行必须分别报告；不为回归自动下载环境或启动付费自主调查。Mock 仅模拟 Agent 回复，实际 runner/TLC 记录支持相应小目标或有限模型；预设输入、录制回复、真实工具执行和自主分析分开归因。历史目标定向工具只在另行请求时执行，不作为默认发现或必过条件。
