## Python 环境

从仓库根目录执行：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m pip check
.venv/bin/consensus-assurance --help
```

只安装运行环境时，将 `requirements-dev.txt` 换为 `requirements.txt`。这两个文件是安装入口，不是冻结全部传递依赖的锁文件；项目打包元数据仍在 `pyproject.toml`。

## 外部工具与本地依赖

将官方 TLC JAR 放在自选位置，使用绝对路径配置：

```bash
export TLC_JAR="/实际路径/tla2tools.jar"
.venv/bin/consensus-assurance doctor
```

本地已有的 `.tools/tla2tools.jar` 不随 Git 提交；新环境需要自行取得工具。模型搜索使用有限堆内存和单个 TLC worker。TLC 的本地 RMI 初始化可能需要创建本地 socket；若执行环境禁止该操作，会记录工具错误，不会把它算作模型反例。

Hashicorp Raft 实验需要目标依赖已存在于当前用户的 `~/go/pkg/mod` 缓存。运行时设置 `GOPROXY=off`、`GOSUMDB=off`、`GOTOOLCHAIN=local` 和 `-mod=readonly`，不自动下载依赖。需要预先准备模块时，应在独立目标副本中按其 `go.mod` 下载；不要修改用户原始目标。

默认 bubblewrap 模式只开放实验工作副本写入，并隐藏用户主目录和框架原始日志；当前保留网络命名空间，不能宣称网络隔离。缺失 bubblewrap 或系统不允许其操作时会报告受阻，不自动改用弱隔离。

## 不发送仓库材料的验收

在没有材料发送授权时，可运行以下本地检查：

```bash
TLC_JAR="$TLC_JAR" .venv/bin/python -m pytest -q
.venv/bin/consensus-assurance run --config examples/toy_protocol/config.yaml
.venv/bin/consensus-assurance run --config configs/targets/local_only.yaml
```

mock 回归不要求 Codex 登录；本地模式禁止创建真实 agent 材料请求。未配置 Java/TLC 时，依赖真实 TLC 的测试明确跳过。真实自主分析还需要现有 Codex 认证可用、后端可访问，并获得仓库材料发送授权；提交本框架到 GitHub 不等于授权发送分析对象材料。
