# 第三轮审计修订与验收

本轮以 `ce6ecb27a44ae162a45425a938b46704e4ae65d7` 为起点，结合用户审计报告与讨论增量修改，没有重建项目。本轮没有调用真实 Codex 分析目标，没有启动新的 HashiCorp 实验，也没有改写旧实验数据。

## 方法与本轮取舍

保留领域引导、实现为据的单一流程。目标可以保持“选举安全”或“快照恢复保持相应历史”这样的语义层级，一个目标对应多项义务；收紧的是一次模型和实验的范围。协议知识不替 agent 选择固定目标。

不以 prompt 行数作为验收标准。新增发现、建模、实验三份共享方法，按具体任务组合；目标、义务仍由当前材料驱动。没有建设参考 spec、本体、插件市场或多 agent 架构。

## 结论边界修复

| 问题 | 实现及限制 |
| --- | --- |
| 技术修复可把同名性质改成 TRUE | `workflow/modeling.py` 在纯校验中要求性质正文、共享性质描述、checker 归属及范围保持不变。实验编译修复仅能改 harness。行为模块语法修复可以继续；性质自身语法问题不在本轮自动判定语义等价，保留具体缺口进入后续语义调查。 |
| 多义务单元漏检查 | `AuditUnit` 保存逐义务执行引用、剩余义务和重验原因。`partial` 单元可再次调度，下一请求携带剩余义务；重复只检查旧项且无进展时阻塞并保留缺口。没有可执行下一步但仍有遗漏义务时明确报告未完成。完成指记录范围内的 checker 完成，不是义务整体证明。 |
| monitor 与 invariant 仅凭 ID 关联 | `adapters/verifiers/observable.py` 从受限 `ObservableProperty` 生成完整 Properties 模块。确认前核对监测触发条件、断言、投影、共享描述和保存的 Bundle；任意 TLA+ 性质仍可检查，但不能凭任意 monitor 自动升级。 |
| 跨事件义务无法表达 | 增加 `stable_support`：按实际参与者/上下文比较有效支持对象。完整观测历史必须与实际事件对应；事件遗漏、身份缺失仍不能确认。适用条件由当前实现依据提供，不是所有协议都必须“永不改变支持”。 |
| 如实记录插桩就被绝对阻断 | 保留变化事实，并提供定位到 harness 行的 `ObservationChange`。本轮仅对 Python 中受限的实际事件 print/json.dumps 语句做独立语法核对，要求绑定和理由。修改状态、无法核对、Go 插桩等仍受限制；不宣称解决一般插桩等价、并发时序扰动或恶意观测真实性证明。 |
| 反例后不能新增监测 | `ReplayPlan` 可提交新的 observation 和 monitors；保留行为、性质和 shared description。生成新制品版本，并要求该新实验重新校准。 |
| F2 标记过期后没有后续任务 | 通过模型已有 graph_versions 纳入关系版本依赖；受影响已完成单元重新进入 pending，旧结果保留需重验状态。F3 的旧范围历史不因范围扩展直接变成失效；F4 不触发模型搜索全局失效。 |

自动确认仍要求原有条件：真实执行及快照/制品关联、合法性和适用性依据、确实达到的关联前提、足够观测和当前实验校准。共享描述连接 checker 与 monitor，但并不证明描述本身就是正确的规范；有冲突或未决依据仍不确认。

## 生成、上下文和修复

所有阶段的补读请求共享 `ReadRequest(file, start_line, end_line, reason)`。Discovery、BuildReply、Feedback 不再各自用开放字典表达读取动作。

`workflow/agent_tasks.py` 管理 agent 调用；`output_repair.py` 处理有限字段替换。完整原对象保存在 `repair-original.json`。修复请求只携带报错位置、相应字段和可容纳的完整相关片段，返回 JSON pointer/value_json 替换列表；未报告路径和重复路径会被拒绝。框架合入原对象后再次验证全部内容。修补计划、原对象路径和已用次数进入检查点，恢复不丢弃修补计划。

这里没有截断原对象再要求“保留整个图”。不可解析 JSON、无法定位的语义错误、单个出错字段过大时会保存原文并给出具体阻塞，不猜测缺失部分；这不是通用 JSON 编辑器。某些语义问题本来就不适合格式修补。

Build 与 Feedback 增加无副作用校验，再进入制品写入或实际语义修改。F3/F1/技术任务组合 build 工具接口和共享方法；重放/F4/归因组合实验方法。diagnose 直接携带原模型反例输出，F1 携带真实校准输出。日志超长仍明确标注截取范围，日志截取不等于截断待修补的数据对象。

## 模型提交与职责整理

模型写入使用已有 generation action ID，写临时目录和 commit.json 后原子改名。文件完整但状态尚未登记时，通过同一 action 恢复同一个模型 ID/version；不完整临时文件保留为未完成尝试，再重建同一提交。已登记模型不会重复追加。恢复发现输入不同或文件损坏会明确阻塞。

这项提交记录解决的是“v1 已写入、state.json 未登记”的具体进程中断窗口。单靠 Git、版本号或普通文件名无法判断目录属于哪次已完成生成。复用既有 action ID 和已有摘要，不新增另一套身份 hash。这里只承诺控制器中断恢复，没有新增跨文件系统或断电持久事务保证。离线直接调用 save_bundle 的旧样例接口若不提供 action，不获得 Engine 的自动提交恢复。

保留现有组合入口，按已发生的职责问题抽取：

- `workflow/discovery.py`：发现、补读和增量图更新。
- `workflow/modeling.py`：纯模型受理、技术修复边界、义务进度。
- `workflow/investigation.py`：调查输入和反馈/重放校验。
- `core/events.py`：通用字段读取与事件关联；TLC/执行 adapter 不再从 observations 工作流反向取这些工具函数。
- `adapters/verifiers/tla_syntax.py`：TLA 工具语法保护。
- `workflow/artifacts.py`：纯校验与制品提交是不同函数。

没有机械搬空 core/proposals，也没有引入多层基类。Engine 仍拥有串行状态机、预算和动作持久化；不是宣称已经完成所有架构解耦。

## 当前可用接口

支持自动对应时，Bundle 设置 `properties: GENERATE_FROM_OBSERVABLE_PROPERTIES`，提供 `observable_properties`、匹配的 `checkers` 与 projection。框架产生 Properties.tla；monitor.property 引用同一描述。标量描述表达“trigger 成立时 assertion 成立”；历史描述比较同一身份/上下文的对象。任意自写性质模块不满足此对应规则时保持模型层或对应关系待确认。

当前示例只解释 schema：`trigger = state.completed == true`，`assertion = state.ready == true`；这不是默认发现清单。静态和动态 agent 指令保持英文，引用的中文路径或代码材料原样保留。
