## 完成范围与证据边界

- 继续使用同一个 Engine，没有第二个执行引擎。新增的是 DirectCheckPlan/Reply、DirectCheckArtifact 和一个 focused QuestionReply，不是新的协议规范图。
- AuditQuestion 增加 disposition、preferred_check、requests。新真实自主单元必须填写；旧数据可加载，旧阶段不直接恢复到新语义。FRAMEWORK_REVISION 与资源 manifest 均为 `question-checks-v1`。
- 当前问题决定 source_review、直接测试、受控调度或原模型路径。已解释疑点退出当前检查，但不证明整个义务；缺材料先走现有 depth 读取，保留 receipt、未满足范围和当前任务身份。
- 直接检查先保存计划、harness、输入版本和生成操作身份，再调用原 run_experiment、隔离执行器、CA_EVENT、前提关联与事件监视器。Finding 明确区分 model_id/direct_check_id，只能选择当前单元的 obligation。实际违反还需适用性、合法前史、源码版本、观测和 oracle 对应审查；随后单独进行后果分析，不自动提升 Goal。
- direct_check 有明确的 oracle 审查类别，不伪装成 model。未完成审查、未决反证、缺字段、未命中前提、工具/编译失败和协议改动都不能确认违反。普通 technical/F4 修复保留范围和 oracle；语义变化走现有 F2，依赖扩展走现有 ScopeUpdate/F3。
- ConstraintSource.source_ids 只放实际材料 ID，binding_ids 单列且限定已选绑定；引用材料必须覆盖绑定行为范围和内容版本。纯引用修复只允许改这两个字段，不能把 code_observation 改成 assumption 绕过验证。诊断直接附选中绑定、范围、anchor 和 associations。
- 默认审查集合是 Goal、Obligation、Unit，以及存在时的 checker/oracle。Binding/Relation 的定位仍由程序校验，语义使用随 Unit/Obligation 复核；明确争议仍进入定向复核。减少的是重复定位认证，不是证据或语义真实性条件。
- selected_unit 不依赖 target_ids 的闭包碰巧带入，始终显式携带当前版本、question、code_uses 和 scope。图对象从 state 附加；源码才通过 reading service 获取。

## 剩余限制与下一次实验

- direct 自动判定目前限定于有明确共享描述的 event_assertion；不支持的历史/时序属性保留 gap 或 typed local_model fallback。独立 oracle 和合法执行仍需有来源的对应审查。
- 审查是解释实际证据，不是独立正确性投票。缺前提、缺观测、未完成审查或旧 oracle 争议都不能通过重生成 harness 自动消除。
- 有限 passing direct test 只留下作用域明确的 implementation_test 证据；模型反例仍不是实现缺陷；Goal 后果必须单独处理。
- 旧 F3 整包本身仍超过上限，必须先解决有界子问题，不能声称所有历史上下文已自动压缩到上限内。
- 本轮没有证明真实 LLM 会稳定选择最短路径，也没有发现或确认 HashiCorp 缺陷。

建议在用户另行授权后，用同一目标快照、无 supplied goal、原 20 calls/2400 秒预算进行新运行。先确认 Codex 路径/认证、Go/隔离器及 TLC 工具；使用新 framework revision，不恢复旧阶段。重点观察 typed disposition、首次实际验证前调用数、selected dependency 读取和反证处理；不以必须产出 TLA 或必须发现缺陷作为成功条件。
