# 审计方法

先理解实现，再提出规范问题。七类责任是 A1 决议形成与推进、A2 执行权与协议上下文切换、A3 副本恢复与重新同步、A4 配置与参与者变更、A5 决议应用、A6 历史与恢复证据生命周期、A7 客户端操作语义。它们不是顺序算法或互斥代码分区；静态成员、逐实例权威、外部应用和调用方注入的存储都是合法差异。

首轮从目录与声明抽取分散小样本。每类记录 applicable、externalized、not_applicable 或 unknown，给出源码、边界或缺失材料。恢复接口所有权和选择方式，区分支持、启用和当前使用；不默认配置一定由 flag 选择。

Behavior 分开记录合法前史与实现 guard。Fact 区分语义与变量表示，并记录生产者、消费者、身份、有效上下文、失效/重新解释、持久化及恢复。沿事实依赖分析跨活动干扰，不枚举所有活动组合。已有保护解释疑点后应收敛，未解释的反证仍保留。

Obligation 必须说明检查 establishment、preservation、consumption、recovery 或 cross_activity_handoff 中哪个关系；Goal 解释系统后果。不为覆盖七类机械生成七个目标，不预设 Raft 性质、PreVote 或 leader 退位规则。

反向覆盖把重要入口分类为 mapped、externalized、infrastructure、deferred 或 UNCLASSIFIED_PROTOCOL_RESPONSIBILITY。普通 unknown 是库存，不是自动任务；高后果未分类、最低覆盖缺口、选中问题的决定性缺口才触发有预算的分析。完成一个检查后重新评估后果、可验证性及其他方向的欠缺，不强制轮询。

优先选择能区分疑点的最小可靠检查：语义不清先读源码；一个可控执行和可靠 oracle 足够则直接测试；实际可控的顺序问题用受控调度；大量合法交错用局部 TLC。模型行为来自代码，性质来自义务。有限测试或模型结果不能证明整个活动。

历史 ABCD/Responsibility 视图已退役；历史运行只可查看或离线导入，不跨 framework revision 恢复。七类覆盖是当前已发现实现面的理解账本，不是所有正确性要求的完整分母，也没有数学完备性证明。

已被问题引用的 Fact 不原地改义：保留旧 Fact 与来源，先加入有依据的修订 Fact，再通过现有 F2 `audit_question` 字段变更接回原单元。这样描述性规格更新不会偷偷改掉已接受的规范关系。
