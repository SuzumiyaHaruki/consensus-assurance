# 审计方法

本项目使用 Codex 调查 CFT 共识实现。稳定的方法是选择性理解、因果调查和证据驱动修正；控制器承担结构、执行和证据边界，模型决定阅读顺序、调查粒度和下一步。当前运行时方法为 `audit-products-v60`，以实际加载清单为准。

## 整体与局部共同推进

共识形成／推进与上下文／权限切换是互补的阅读主线。注意值如何获得支持、何时提交／完成，以及旧工作在任期、领导权、成员资格或恢复边界之后如何处理。其他 Activity 为这些关系提供实现依据，不是执行阶段，也不是局部问题入场时必须填写的标签。

可以在全局地图缺失或不完整时保存有来源的问题、阅读、探索，或者同时提交义务和完整检查。一个问题最少说明具体不确定性及捕获源码依据；后来通过 ID 更新相关字段。明确的源码解释可以结束局部疑点，无需补一个形式性测试。选择另一个问题不会自动暂停或关闭已有问题。

Behavior 记录实际条件行为，Fact 记录它建立的事实，Obligation 说明有适用依据的应有责任。地图是可选导航，引用时校验对象和版本，不要求唯一主要 Fact 或总览证书。粒度应能区分影响调查的分支、持久化与发布、通知与完成、对象身份、成员资格及上下文变化。

## 因果调查与证据范围

对当前结论，需要回答三个相互依赖的问题：适用的源码合同或协议责任是什么；必要输入、状态和身份如何在一个允许的执行中产生；未修改实现实际做了什么，这个观测为何回答当前命题。它们不是三阶段表单，缺失项本身可以成为调查对象。

优先调用实际构造器、提案／消息生产者、存储和处理器，通过环境控制延迟、投递、计时、断连、允许的存储失败或重启。优先复用真实初始化前缀和目标测试工具；核对这些工具没有跳过待验证条件。持久快照仅能替代其合法来源和保留状态支持的前史，不能替代在途消息、请求身份或活跃工作。不能仅因序号相同而拼接两段不同历史。

合成状态、内部处理器、内存传输和局部接口测试仍有用途，必须保留哪些决定性条件由测试提供。合法局部调用者合同也可以直接许可输入，不必为每个局部缺陷构造集群。故障模型需要具体说明：允许的存储失败不同于修改已持久值；传输合同保证的 FIFO 不能以“延迟”名义任意重排。

发现异常后，选择能改变当前判断的缺失环节：追踪特殊状态的实际生产者，检查局部函数外围的准入／串行化／重置保护，观测同一操作承诺的终点。应用效果需要实际 Apply／读状态，条目存在或支持计数不是同义替代。活性调查需说明继续工作的所有者和允许调度，有限等待本身不能证明永久停滞。

## 结果与修正

进程成功、实际观测和语义解释分别保存。正式检查固定源码、义务、判据、驱动、执行包／crate、版本及原始输出；必要前提未到达、身份不匹配或终点缺失时，即使程序成功退出也不能得出违反或满足。非零退出保留；仅当具体完成见证与独立失败的关系得到复核时，才可能保留范围内结果。

内部复核不是独立审计投票。判断“对应性无问题”前应说明适用条件及其测试、实际生产者／调用者或观测历史依据；有来源的局部合同也可以许可输入。当前结论依赖的未解决前提不能通过一句 `no_issue_found` 或“独立范围”消失。更广未测后果则不抹去已独立建立的局部结果。最终缺陷有效性、CFT 相关性、去重和论文评分由人工离线判断。

执行后的任何驱动、判据或义务修订都走同一个后继路径，保存前驱、原因和实际差异，重新执行并复核。旧文件和输出不覆盖，旧争议只有得到指向具体证据的解决记录才关闭。地图新增独立知识无需给无关旧对象写影响声明；改变已使用前提时记录有来源的保留理由或受影响问题，并保留旧依据。同一 Fact 名称不等于结论依赖。

一份交接可以同时携带结果解释、相关知识更新和下一项就绪工作，最多请求一次新目标执行。后续调用直接获得上一操作状态、结果位置与已知缺口，同一原生会话继续阅读和修正，不反复灌入全图。相邻重复交接只作提示，不处罚、不强迫造检查。

开放运行持续有用调查到总时间／调用边界或真实中断；正式执行额度耗尽后仍可进行有预算的源码工作。只有用户预设的有限定向任务能提前完成。到期保存已有工作，不再追加付费总结。新实验使用独立会话，不读取历史发现或本轮开发材料；目标源码只读，执行仅在隔离副本进行。
