# 以义务和证据为产物的 CFT 审计

核心术语只有 Activity、Behavior、Fact、Obligation、AuditQuestion、Evidence。实现理解帮助发现问题；审计结果是有边界的义务结论和证据，不是七类都标为理解完成。

```text
Target Profile：实际所有权、配置与边界
        ↓
七类 Activity 广度与反向源码表面核对
        ↓
描述性 discovery：实际 Behavior → 产生/消费 Fact；保留 unknown
        ↕ spec_refine：按来源拆分、补充和纠正描述对象
受理不完整但一致的实现理解
        ↓
derive：一个主要 Obligation → 一个 Fact 生命周期
        ↓
主动查找已有保护 → 有界 AuditQuestion
        ↓
source review / direct test / controlled schedule / local model
        ↓
Evidence → 有界结论与限制 → 回填理解 → 下一条高价值义务
        ↓
Consensus Audit Report：义务、证据、未决问题和限制
```

七类并列坐标分别关注决定形成与推进、权威和协议上下文转换、副本恢复与追赶、配置和参与者变化、决定应用、历史和恢复证据生命周期、客户端操作语义。它们不是流程阶段或互斥代码分区，也不构成数学完备性声明。无法归类的重要表面保留 UNCLASSIFIED_PROTOCOL_RESPONSIBILITY。

Behavior 是一个执行所有者在具体触发和上下文中的局部处理。不同 actor 或建立不同语义结果的分支先拆分。Fact 是指定身份和上下文中已建立的断言；观察、通知、请求转换与转换完成不能合并成一个“可能完成”的事实。生产者或消费者未知可以接受，但必须显式记录，不能跳过尚未理解的中间建立步骤。

Behavior 的 produces_fact_ids/consumes_fact_ids 是唯一权威边。反向索引和跨 Activity 关系由控制器派生，不再维护 Handoff 对象。ConsensusAuditSpec 仅包含 version、target_profile、activities、behaviors、facts、surfaces；Activity 不填事实清单或成熟度评分。

Obligation 是唯一正确性要求，可有其他义务作为依赖。AuditQuestion.importance 解释系统后果；当前单元只检查一个主要义务、一个主要事实及 establishment/preservation/consumption/recovery 中一种生命周期关系。上下文可以包含多个相关行为，不把整个协议正常链揉进一个问题。

字段修复只负责表示问题。理解错误通过 spec_refine 重整对象，旧草稿保留；已受理问题引用的事实 meaning、identity 或 validity_context 改变，需要 F2 和显式问题重连。缺失来源和矛盾不能接受，明确记录的未知和外部依赖可以接受。调用完成不表示问题已解决。

优先执行已有的可靠检查，然后解决选中问题的决定性证据缺口和高后果未映射表面；普通 unknown 不自动产生无限补读任务。当前已知高价值义务有证据、已由保护解释或明确延期，并且没有悄悄忽略高后果表面时，才允许结束当前工作。预算耗尽也可以停止，未完成事项必须可见。

直接测试保留实际源码隔离执行、版本绑定、合法前史、身份/上下文关联、独立 oracle 和可观察适用性。TLA+ 保留代码决定行为、义务决定性质、可达性、语法/搜索/校准/回放区分。有限测试通过或 TLC holds 都不是实现证明；局部义务违反不能自动升级为更广泛义务违反。
