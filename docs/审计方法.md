# 审计方法

研究路线是先分解、先理解，再形成问题：从实际源码恢复 Activity、Behavior、Fact 和未展开的 Surface，选择 Candidate，调查后形成有来源的 Obligation 与有界 AuditUnit，最后用实际检查及 Evidence 限定结论。七类描述不是完备性证明，候选数量也不是全系统覆盖率。

## 概念与分解

七类 Activity 关注决定推进、权威与协议上下文、副本恢复、配置参与者、决定应用、历史证据生命周期、客户端语义。它们是并列责任坐标，不是固定流程阶段或互斥代码分区。重要但无法归类的表面显式保留。

Activity 保存全局责任摘要。Behavior 描述一个执行所有者在具体触发、上下文及分支中的行为；异步所有者和建立不同结果的分支应分开。Fact 描述带身份、有效上下文和来源的实现事实，不把请求、通知、建立和消费混为一谈。Behavior 的产生／消费关系是唯一声明，反向索引由控制器派生；未知生产者和消费者可以保留。

Surface 是阅读入口。局部扩展优先补充 Behavior、Fact 和 Surface；当前包未附带某段源码，不表示全局尚未理解它，也不能据此覆盖 Activity。全局责任确需纠正时，针对完整旧描述及实际来源修订。共享理解允许纠错，候选假设、模型初态和测试期待不能自动回流为 Fact。

## 候选、义务与范围

AuditQuestion 写明直接检查关系、必要前提、停止观察的位置、已有保护及排除的更广后果；importance 解释系统后果。初选比较真实备选，续查沿原 candidate_id；分流保留父问题和未决项。关闭一个假设不封住同一 Fact 的其他问题，一次升级不封住整版规格。没有可操作问题可以有限停止，不为满足配额制造义务。

Obligation 是所选合同和范围内的正确性要求。代码观察、规范期待、测试断言和分析假设分别归因；代码行为不能单独证明应有行为。形成义务不要求预先手工证明反例，但不能把缺字段、不保证完成或重复消息自动当作缺陷。

领域知识只提示调查方向。不能把唯一 leader、全局轮次、线性日志、固定多数派、隐含本地支持或统一 quorum 公式当作所有 CFT 的共性。实际支持单位、身份、上下文与故障责任由目标材料建立。

## 检查与有限结论

直接检查在隔离副本调用实际目标，观察独立结果并与真实输入比较。先决事件、操作身份与结果各司其职；关联字段不得就是待检查是否保持的值。关联不唯一、字段缺失或引用无法解释时保留未知。跨上下文检查不默认要求新旧上下文相等。

模型行为来自实际代码，性质来自有来源的义务；保留相关保护、锁、错误路径及中断边界，不把待查性质放进初态或动作 guard 排除反例。条件入口只能支持其局部问题；原义务需要的先前支持、决定和后续后果，必须分别有同一合法历史的见证。

保存草稿、形成可搜索模型、SANY 解析成功、TLC 有限搜索、真实轨迹校准及实现确认是不同事实。模型反例、兼容轨迹或一次局部字段比较不能单独证明共识分歧。自然语言合同、来源归属及解释也不能由引用和类型校验自动证明。

properties/outcome 保留实际观察，limitations 保留适用范围、未决合同、输入合法性和反证，confirmed 才表示所选义务范围内的确认。执行状态来自实际 CheckRun，不让计划中的“尚未执行”长期替代它。实现与要求的差异是调查对象；要求来源之间的矛盾才是结论依据的争议。执行完毕不会消除真实反证，有限通过也不证明整体正确。

## 修订与来源

F1 修改模型行为、映射或环境；F2 有据修订性质及适用含义；F3 扩展真实生产者、过滤者或支持边界；F4 修复实验前提。普通技术修复保留已受理的性质和范围，编码纠正仍需实际复查与对应性审阅。未受理产物可以在原任务续写，但不能借此悄悄换义务。

直接检查作为整体审阅当前义务、调用、前提和 oracle，不增加逐对象串行审批。无问题意见是暂定判断，不能当作第二份独立证明；mock、录制回复和小模型检查验证框架机制，不替代新的真实自主调查。运行记录负责保存具体版本、假设、失败与未完成工作。
