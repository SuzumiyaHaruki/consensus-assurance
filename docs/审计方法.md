# 审计方法

研究路线是先讲通具体实现的两条核心主线及其连接，再持续集中调查。从源码恢复 Activity、Behavior、Fact 和未展开的 Surface，在这个理解中选择 Candidate，形成有来源的 Obligation 与有界 AuditUnit，用实际检查及 Evidence 限定结论，并把理解增量带回地图。两个核心维度与五类支撑不是完备性证明，候选数量也不是全系统覆盖率。

## 概念与分解

Candidate 是有源码依据、值得调查的问题，保存保护、未知和方向变化；Obligation 是在明确适用条件下实现应满足的正确性责任，形成它不表示已确认缺陷；Check 是针对要求的一次具体检查设计；Evidence 是实际执行或观测及其归因。源码解释、暂停和有限检查未见违反都是有效研究结果。

要求尽量表达对象、上下文和适用前提下的关系；固定节点名称、操作 ID、测得的 term/index 和等待时间通常属于 Check。真正决定责任适用性的数量、部署模式或故障条件仍保留在 Claim／Scope。小场景不把规范缩成固定输入输出；参数化表述也不代表全局证明。同一要求可增加原范围内的场景，只有独立可判断的另一要求才需要另立问题。

A1“共识形成与推进”研究形成决定和合法推进所需的合格支持；A2“上下文／权威转换”研究有效上下文及权威的取得、转换、失效。A3–A7 分别提供恢复同步、配置参与资格、决定应用、历史持久化和客户端契约等支撑。它们描述关系，不是固定流程阶段或互斥代码分区。唯一机器角色映射位于 `core/types.py::ACTIVITY_ROLES`。

初始概览不依赖 `activity_focus`：从代表性操作进入实现，追到支持的产生、身份和资格、聚合与决定条件，再追到记录、传播、应用或公开完成；同时解释上下文如何取得、改变和失效，旧请求、回复、未决支持及已成立决定如何处理。必要的成员资格、历史、恢复及完成机制此时就要读，不统一后置；沿调用者与被调用者双向追踪，并比较重要拒绝、过期、重试和异步路径。

这些解释及其 Behavior／Fact／来源引用统一放在 AuditSpec 的 `core_overview`，区分 `core_gaps` 与 `open_details`，给出 `incomplete/usable/blocked` 状态和理由。部分地图和早期疑点可以保存，但 A2 只有对象初始化、权威转换仍未解释时，默认下一步是补主干，不能因接口差异容易测试就开始连续正式检查。两条主干及连接已可解释，某个外部调用方的细节未读，则可保留未知并进入局部调查。引用和状态一致性由控制器校验，解释是否充分仍是分析判断，不是机器证明。

只有用户显式配置的 `directed_question` 可以采用与该问题相称的局部边界。概览与首个 Candidate 可同次提交，不强制增加模型轮次。概览可用后，每题只需通过来源化 Behavior 和 Fact 说明至少一个核心关系；只贴标签仍不足。`activity_focus` 只选本次子方向，不免除初始双主线理解。principal Fact 的直接邻居与前史、上下文、后果支撑分别记录，后者写入 `supporting_behavior_ids`，不伪造直接边。

Activity 保存全局责任摘要。Behavior 描述一个执行所有者在具体触发、上下文及分支中的行为；异步所有者和建立不同结果的分支应分开。Fact 描述带身份、有效上下文和来源的实现事实，不把请求、通知、建立和消费混为一谈。Behavior 的产生／消费关系是唯一声明，反向索引由控制器派生；未知生产者和消费者可以保留。

Surface 是阅读入口。未映射入口可以先凭来源导航成为下一项补读，而无需伪造 Behavior 或 Fact；这仍不构成规范判断。局部扩展优先补充 Behavior、Fact 和 Surface；阅读相关的 Activity 标签不授予全局改写权限。全局责任确需纠正时，显式选中该 Activity，以完整旧描述及实际来源修订。共享理解允许纠错，候选假设、模型初态和测试期待不能自动回流为 Fact。

## 候选、义务与范围

AuditQuestion 写明直接检查关系、必要前提、停止观察的位置、已有保护及排除的更广后果；importance 解释系统后果。初选比较真实备选，续查沿原 candidate_id；分流保留父问题和未决项。关闭一个假设不封住同一 Fact 的其他问题，一次升级不封住整版规格。没有可操作问题可以有限停止，不为满足配额制造义务。

活动 Candidate 可以在尚未解决时暂停：回复必须说明当前边际判别价值为何低于另一条有来源的方向，并保存恢复所需的具体判别条件。暂停不等于解释、证据受阻或 fork；恢复继续原 ID、问题、保护、未知、材料和回执，改写理由不会重置已用预算或停滞记录。

自然交接只保存新增回答、理解变化和下一判别，沿原记录引用已有论证。小型有来源的研究增量可先通过独立 feedback 正式保存并进入下一轮；后续问题使用新关系时再补充正式地图，不能替代初始双主线理解。可复用的源码知识回到地图，条件化实验结论留在证据中；当前未知与恢复条件由有来源的反馈更新，旧问题保留在历史里。随后比较少数真实方向的价值、已有保护、未知、可行性及可能结果的影响，不按标签轮转或穷举组合。共享 Fact、lifecycle、context 或显式父子关系不意味着共享失败次数或关闭状态。

分别保留五类缺口：规范适用性、实际 producer、合法初始化前缀、同一历史／故障合法性和观察终点。生产者／消费者或接口边界已有实际来源、规范依据和独立 oracle 时，可以先形成局部 Obligation，再由直接测试、受控调度或局部模型调查可达性。合法输入经真实实现产生的构造测试可以建立有限历史，不要求由模型搜索发现；直接赋值关键协议状态只提供条件化前提。

共识安全性优先，活性判断需要明确环境、调度或时限前提。有独立依据的相关实现语义问题可以在其范围内完成，不强迫证明更广共识后果，也不自动确认最初怀疑的原因。已确认 P 后选择原因或后果 Q，可建立关联新问题；不把 P 降回未完成，也不沿父子关系复制结论。结论对象与证据完整性分开：严重猜测可能只是线索，局部合同违反也可能证据充分。问题处置后回到当前地图和已有前沿继续选题，不以一个局部结果代替整次调查。

后续判别分别交代要求的来源与适用范围、受控输入下 consumer 实际执行、输入的真实 producer 与同一身份／上下文／合法前史、以及实际到达的内部或外部终点。调用链和可构造字段只提供阅读线索；分别跑过两个片段不等于同一历史可达。故障条件须有接口或适配器依据。局部结果完成后，优先选能减少关键未知的一项 producer、前史或后果关系；缺合同或执行能力时明确暂停。

从 Parent Candidate 分出的 child 保留 Parent 原问题、来源、反证和未知；fork 表示另立一个可验证关系，不是悄悄缩小或解决 Parent。child 完成后，后续选题从既有 Candidate—Obligation—Unit—Check—Evidence 关联取得实际结果、范围和当前阻塞；这些结果服务 Parent 的下一步判别，但不自动传播为 Parent 结论。needs_specific_evidence 表示 Parent 及当前识别的有意义局部关系都缺少可归因检查所需的规范或适用依据，不再仅表示最终后果尚未证明。

child 若承担 Parent 的必要判别，其实验前提必须能对应 Parent 的适用合同；不同前提下暴露的 provider 问题先保留为局部结果。已有 Parent 承接同一后续判别时，后果处置只投影结果和边界，不再建立等价的 spec_refine 路径。

首个 Obligation 前允许有来源地收敛当前问题，原始线索留在历史；形成义务和审阅结果时说明实际回答的是哪一部分。Obligation 是所选合同和范围内的正确性要求。代码观察、规范期待、测试断言和分析假设分别归因；代码行为不能单独证明应有行为。形成义务不要求预先手工证明反例，但不能把缺字段、不保证完成或重复消息自动当作缺陷。

领域知识只提示调查方向。不能把唯一 leader、全局轮次、线性日志、固定多数派、隐含本地支持或统一 quorum 公式当作所有 CFT 的共性。实际支持单位、身份、上下文与故障责任由目标材料建立。

## 检查与有限结论

直接检查在隔离副本调用实际目标，观察独立结果并与真实输入比较。方案继承已受理 AuditUnit 范围，具体输入只是该范围内的实例。前提条件只约束所属事件，trigger 选择结果事件，identity_fields 关联同一次操作，结果比较独立完成；关联字段和适用条件不得用正在检查的值过滤反例。实验完成不能依赖被禁止的动作，合规拒绝路径也须有独立的完成和结果观测。空轨迹、关联不唯一、字段缺失或超时保留未知。跨上下文检查不默认要求新旧上下文相等。

模型是可选的最小历史探索工具，默认不探测 Java/TLC。形成义务前可归属 Candidate 或 Surface，不伪造 claim；形成义务后 checker 明确归属。模型行为来自实际代码，性质单独保存在 Properties；保留相关保护、锁、错误路径及中断边界，不把待查性质放进初态或动作 guard 排除反例。条件入口只能支持其局部问题；原义务需要的先前支持、决定和后续后果，必须分别有同一合法历史的见证。

保存草稿、形成可搜索模型、SANY 解析成功、TLC 有限搜索、真实轨迹校准及实现确认是不同事实。模型反例、兼容轨迹或一次局部字段比较不能单独证明共识分歧。自然语言合同、来源归属及解释也不能由引用和类型校验自动证明。

有效见证与整体覆盖分别判定：先判断独立适用性，再匹配身份和必要前史，最后判断 alias 条件和完整结果。同一见证关键缺失、关联歧义或潜在全局解析丢失阻止确认；确定独立的另一操作未完成不抹掉已有见证，但 Unit 保持 partial。

properties/outcome 保留实际观察；有来源且仍挑战本次判断的问题由 ReviewIssue 形成当前归因阻塞，明确排除的变体与更广后果形成范围边界，已经解释的替代机制留在复核论证中。limitations 不创建当前 issue，也不自动变成下一步待办。机器读到 false 不会因复核缺失改写成“未观察”；当前确认层级、阻塞和适用范围由同一次评估更新，再由 Candidate 与报告投影。执行状态来自实际 CheckRun，不让计划中的“尚未执行”长期替代它。总览只维护机制与重要连接；报告标明地图描述的提出版本，并另列当前要求、结果和待复核，不按关键词清空机制未知。实现与要求的差异是调查对象；要求来源之间的矛盾才是结论依据的争议。执行完毕不会消除真实反证，有限通过也不证明整体正确。

## 修订与来源

F1 由已有 model 产品修订行为、映射或环境；F2 有据修订性质、规范适用含义或故障／配置范围；F3 在保留命题的前提下展开、重连依赖；F4 修复实验前提。普通修订可更换履行同一责任的驱动，用新来源解释被替换的旧前提，保持要求、oracle、身份和必要因果关系。ScopeUpdate 的实际写集校验决定 F2/F3 边界，不能仅凭字段名含 scope 选择 F3。

选检查入口时，沿实际接口确定调用、串行化、存储、应用和完成责任。若许可明确属于另一个入口，比较补齐当前入口的对应解释、直接使用许可明确的入口与低成本探索；不默认偏好高层接口，也不要求遍历所有变体。源码保护足以解释怀疑时可直接处置；需要判别真实生产者或调度时再执行。稳定关系回地图，单次观察留在执行与反馈，下一题复用已有认识。

已受理 DirectCheck 的 checker 错译由原 issue 指向旧计划，在原 unit 中提交受限的编码纠正，保存新计划和真实新执行，再做定向复核。原计划、日志、评估与争议保留；仅谓词变动和伴随观测输入适配分别记录。必要条件“成功则具备合格支持”不能写成“成功当且仅当具备支持”：合规支持下暂未成功，不构成同一资格安全性违反。

直接检查必需一次当前版本的整体对应性复核；有具体适用性或分解争议时才补相应实质回答，不增加逐对象审批。固定输入中的 conflicts 进入已有 ReviewIssue／IssueResolution 链，条件有准确来源与归属。更换驱动的受理不解决争议，新执行和针对性回答缺一不可；新来源足以解释同版输入时无需故意重写测试。处置只对回答版本及其后继有效，旧执行不会因新驱动合法而变合法；共享规范争议按真实依赖传播，checker 同名不建立依赖。无问题意见仍是暂定判断，mock 和小型测试只验证框架能力。

## 持续调查的行为评价

机械回归检查停止权限、引用和明确矛盾，不能证明 Agent 会正确判断信息价值。v31 的 etcd 归档保留其实际确认和有限检查结果；它不是 v32 或 v33 的自主续查验证。驱动修订链的工程回归也不等于该归档实际走过修订链。

小型定向评价方案（尚未执行）：复用测试中的协议无关实例目标，公开清楚的合同及双主线地图。准备一个已完成的局部解释／检查、一项依赖不可得外部合同的暂停，以及一个授权快照内可通过生产者或消费者读取获得新认识的方向。初始记录明确标为人工评价设定，不冒充 Agent 自主发现或历史实验。用一次新的 Codex 会话读取这一上下文和当前方法，允许自行选步或提出停止，不在提示中指定正确问题或预填 actionable。预算上限 5 分钟、3 次 Agent 调用、1 次隔离探索；真实调用需要单独授权，本轮仅落实工程回归。

保存原始选择、依据、同源预检及正式诊断；观察局部结果是否保留、暂停是否局部、是否获得有用增量，以及拒绝后改变了动作还是只改表达。错误判断同样留档，一次成功不代表永久保证。成本从既有 action、CheckRun、submission 日志离线读取，预检内修改与正式退稿分开；工具耗时不再叠加进 Agent 墙钟，缺 usage 不记为零，语义不明的累计 usage 不求和计费。之后如另行授权自然运行，固定方法版本，从全新目标快照开始，不导入本定向问题或旧实验答案；任何真实服务安全拒绝按原机制终止。
