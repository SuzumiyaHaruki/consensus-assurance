# 审计方法

首要目标是在授权范围内寻找并验证 CFT 实现偏离适用责任的行为与历史。先讲通两条核心主线及其连接，再用 Activity／Behavior／Fact／Surface 组织 Candidate 调查，以有依据的 Obligation、实际检查和复核获得反例或排除依据。理解、保护分析、负结果和知识回流服务搜索；完成检查、覆盖 guard 或耗尽预算不替代发现效果，也没有每轮发现配额。

## 概念与分解

Candidate 是有源码依据、值得调查的问题；可以继续调查尚未明确的要求、保护或合法前史，保存未知和方向变化；Obligation 是在明确适用条件下实现应满足的正确性责任，形成它不表示已确认缺陷；Check 是针对要求的一次具体检查设计；Evidence 是实际执行或观测及其归因。源码解释可结束具体怀疑；负结果要区分排除仍合理的解释与执行确认已解释的保护，保留独立前提，不推广为整个机制的保证。

要求尽量表达对象、上下文和适用前提下的关系；固定节点名称、操作 ID、测得的 term/index 和等待时间通常属于 Check。真正决定责任适用性的数量、部署模式或故障条件仍保留在 Claim／Scope。小场景不把规范缩成固定输入输出；参数化表述也不代表全局证明。同一要求可增加原范围内的场景，只有独立可判断的另一要求才需要另立问题。

A1“共识形成与推进”研究形成决定和合法推进所需的合格支持；A2“上下文／权威转换”研究有效上下文及权威的取得、转换、失效。A3–A7 分别提供恢复同步、配置参与资格、决定应用、历史持久化和客户端契约等支撑。它们描述关系，不是固定流程阶段或互斥代码分区。唯一机器角色映射位于 `core/types.py::ACTIVITY_ROLES`。

初始概览不依赖 `activity_focus`：从代表性操作进入实现，追到支持的产生、身份和资格、聚合与决定条件，再追到记录、传播、应用或公开完成；同时解释上下文如何取得、改变和失效，旧请求、回复、未决支持及已成立决定如何处理。必要的成员资格、历史、恢复及完成机制此时就要读，不统一后置；沿调用者与被调用者双向追踪，并比较重要拒绝、过期、重试和异步路径。

这些解释及其 Behavior／Fact／来源引用统一放在 AuditSpec 的 `core_overview`，区分 `core_gaps` 与 `open_details`，给出 `incomplete/usable/blocked` 状态和理由。部分地图和早期疑点可以保存，但 A2 只有对象初始化、权威转换仍未解释时，默认下一步是补主干，不能因接口差异容易测试就开始连续正式检查。两条主干及连接已可解释，某个外部调用方的细节未读，则可保留未知并进入局部调查。引用和状态一致性由控制器校验，解释是否充分仍是分析判断，不是机器证明。

只有用户显式配置的 `directed_question` 可以采用与该问题相称的局部边界。概览与首个 Candidate 可同次提交，不强制增加模型轮次。概览可用后，每题只需通过来源化 Behavior 和 Fact 说明至少一个核心关系；只贴标签仍不足。`activity_focus` 只选本次子方向，不免除初始双主线理解。principal Fact 的直接邻居与前史、上下文、后果支撑分别记录，后者写入 `supporting_behavior_ids`，不伪造直接边。

Activity 保存全局责任摘要。Behavior 保存执行所有者、触发、生产者保护、回退和通知等条件—效果关系。Fact 的 meaning／identity／validity_context 只描述实际成立的断言，不附带某个 Candidate 的全部解释。补充生产者保护时优先更新 Behavior，替换已回答的原问，保留独立未知与 Fact 原定义；真实改变有效上下文仍须声明影响，explained 不豁免新 challenge。产生／消费关系是唯一声明，反向索引由控制器派生。Candidate／反馈保存局部处置，Scope 保存未测范围，CheckRun／assessment 保存执行进度；不重复写入共享未知。

已读关系应保存条件与效果的对应：共同更新不能概括成所有入口都保证共同通知或完成。使用现有 trigger、important_branches、writes、external_effects、async_boundaries 与 validity_context；能清楚表达则保留同一 Behavior，所有者或完成含义无法共存时才最小细分，不复制同义 Fact。追踪 guard 输入由谁、何时建立，区分内部记账与外部完成；外层分派、准入、串行化和 reset 也可能提供条件，不能只因本地 Fact 缺字段就制造疑点。缺少直接动作时继续查共同调度或替代消费者，不能从不对称直接判违规。引用校验只证明结构合法，不证明抽象保真。

已读且相关的关系进入正常地图回流，未读路径保留未知；不要求每个 Behavior 有边或每个分支有对象。纠正过强概括时，用 challenges 指向实际依赖它的 Candidate；旧要求和观察未受影响才用 preserves。保留历史版本，独立结果不无故重做。概览可用与局部疑点可以同时成立，已读反常关系可以先保存为 Surface。

Surface 是阅读入口。未映射入口可以先凭来源导航成为下一项补读，而无需伪造 Behavior 或 Fact；这仍不构成规范判断。局部扩展优先补充 Behavior、Fact 和 Surface；阅读相关的 Activity 标签不授予全局改写权限。全局责任确需纠正时，显式选中该 Activity，以完整旧描述及实际来源修订。共享理解允许纠错，候选假设、测试初始化和期待不能自动回流为 Fact。

## 候选、义务与范围

AuditQuestion 用现有问题、反证、未知和 trigger_rationale 说明：什么关系未被解释、保护已经回答什么、下一步区分什么。importance 描述可能后果；“尚未测试”本身不是选题理由，unknowns 为空也不否定前期调查已建立的检查价值。源码机制足以解释且无重要执行未知时，用 explained／反馈换题；所有权、时序、上下文或生产前提仍未明时继续调查它。要求与适用范围进入 Claim／Scope，检查记录历史和终点；续查沿原 candidate_id，分流保留父问题。关闭一个假设不封住同一 Fact 的其他问题，一次升级不封住整版规格。开放运行持续到控制器时间／调用边界或真实中断；暂未选出完整检查时继续较小的有价值研究，不为消耗预算制造义务或空转。

活动 Candidate 可以在尚未解决时暂停：回复必须说明当前边际判别价值为何低于另一条有来源的方向，并保存恢复所需的具体判别条件。暂停不等于解释、证据受阻或 fork；恢复继续原 ID、问题、保护、未知、材料和回执，改写理由不会重置已用预算或停滞记录。

自然交接用 feedback 精确引用被回答的 Candidate、Behavior、Fact 或 `surface:<entry_point>` 及支持材料／执行，保存有条件的答案和独立缺口。下一项本来就在更新相关 Behavior／Fact／概览，或其 Candidate 依赖该认识的实质产品，同时替换已回答的原句、移出过期执行／复核提醒；保留真实未知、适用条件和历史。`map_handoffs` 只导航，`understanding` 不证明更新或解决，同 Fact 不传播结论。ReviewSubmission 只交反馈，后续使用已有带地图产品；source_ids 引用 Material，执行身份留在反馈与制品。question_updates 更新候选未知。阅读／探索仍可沿轻量交接继续，无变化不建版本，临近截止保存必要认识，不另开清理回合或扫描无关全图。

分别保留五类缺口：规范适用性、实际 producer、合法初始化前缀、同一历史／故障合法性和观察终点。生产者／消费者或接口边界已有实际来源、规范依据和独立 oracle 时，可以先形成局部 Obligation，再由直接测试或受控调度调查可达性。合法输入经真实实现产生的构造测试可以建立有限历史；直接赋值关键协议状态只提供条件化前提。

共识安全性优先；进展调查区分有来源的数值／事件期限、实现承担的自动继续责任和调用者须提供的后续工作。没有数值期限不等于没有继续责任，有限等待也不证明无穷停滞；推导须核对调度、队列、定时器、回调和其他触发，恢复刺激不替代责任来源。资格、唤醒或关联责任有独立依据与实际观察时可局部完成，不强迫证明更广后果。决定性观察须分清活动对象、复制、缓存与调用者状态，报告值错误不自动变成活动策略变化。已确认 P 后的原因／后果 Q 独立调查，不降级 P 或复制结论；处置后继续比较前沿。

后续判别分别交代要求的来源与适用范围、受控输入下 consumer 实际执行、输入的真实 producer 与同一身份／上下文／合法前史、以及实际到达的内部或外部终点。调用链和可构造字段只提供阅读线索；分别跑过两个片段不等于同一历史可达。故障条件须有接口或适配器依据。局部结果完成后，优先选能减少关键未知的一项 producer、前史或后果关系；缺合同或执行能力时明确暂停。

从 Parent Candidate 分出的 child 保留 Parent 原问题、来源、反证和未知；fork 表示另立一个可验证关系，不是悄悄缩小或解决 Parent。child 完成后，后续选题从既有 Candidate—Obligation—Unit—Check—Evidence 关联取得实际结果、范围和当前阻塞；这些结果服务 Parent 的下一步判别，但不自动传播为 Parent 结论。needs_specific_evidence 保存当前问题的具体判别缺口；缺规范可以查合同，缺前史可以探索，已有保护足以解释时可处置。它不要求先证明所有局部问题都不能检查，也不把最终后果门槛提前施加到 Candidate。

child 若承担 Parent 的必要判别，其实验前提必须能对应 Parent 的适用合同；不同前提下暴露的 provider 问题先保留为局部结果。已有 Parent 承接同一后续判别时，后果处置只投影结果和边界，不再建立等价的 spec_refine 路径。

首个 Obligation 前允许有来源地收敛当前问题，原始线索留在历史；形成义务和审阅结果时说明实际回答的是哪一部分。Obligation 是所选合同和范围内的正确性要求。代码观察、规范期待、测试断言和分析假设分别归因；代码行为不能单独证明应有行为。形成义务不要求预先手工证明反例，但不能把缺字段、不保证完成或重复消息自动当作缺陷。

领域知识只提示调查方向。不能把唯一 leader、全局轮次、线性日志、固定多数派、隐含本地支持或统一 quorum 公式当作所有 CFT 的共性。实际支持单位、身份、上下文与故障责任由目标材料建立。

## 检查与有限结论

直接检查在隔离副本调用实际目标，观察独立结果并与真实输入比较。方案继承已受理 AuditUnit 范围，具体输入只是实例。复用 harness 前核对入口和调用者许可，不能为方便排除原问题允许的重叠，也不能因宽松顺序产生差异就认定合法。从探索转为检查时核对原判别仍在；强化前提而消除它的测试须作为不同范围或子问题，不能用 holds 解释原题。正式 Monitor 回答独立实现责任；初始化、观察有效性及驱动履约用前提、控制或诊断表示，保留真正独立的辅助判别。前提条件只约束所属事件，trigger 选择结果事件，identity_fields 关联同一次操作，结果比较独立完成；关联字段和适用条件不得用正在检查的值过滤反例。实验完成不能依赖被禁止的动作，合规拒绝路径也须有独立的完成和结果观测。空轨迹、关联不唯一、字段缺失或超时保留未知。跨上下文检查不默认要求新旧上下文相等。

检查使用真实代码与独立 oracle，保留相关保护、锁、错误路径及中断边界。条件入口只能支持其局部问题；所需先前支持、决定和后续结果须有同一合法历史的实际见证。新版本不提供 TLA/TLC、模型空间穷举、活性搜索或模型—实现校准；自然语言及公式可以帮助推理，但不能充当搜索 Evidence。保存草稿、实际运行、事件比较和对应性复核是不同事实。

有效见证与整体覆盖分别判定：先判断独立适用性，再匹配身份和必要前史，最后判断 alias 条件和完整结果。同一见证关键缺失、关联歧义或潜在全局解析丢失阻止确认；确定独立的另一操作未完成不抹掉已有见证，但 Unit 保持 partial。

properties/outcome 保留实际观察；有来源且仍挑战本次判断的问题由 ReviewIssue 形成当前归因阻塞，明确排除的变体与更广后果形成范围边界，已经解释的替代机制留在复核论证中。limitations 不创建当前 issue，也不自动变成下一步待办。机器读到 false 不会因复核缺失改写成“未观察”。执行、观察完整性、对应性意见和当前阻塞分别取自 CheckRun／assessment；reviewed_complete=false 不能推出复核没做，也不能抹掉其他完整见证已支持的确认。报告按 Claim 同行呈现结果与进度，保留无义务候选、未执行义务和独立未知。总览维护机制与重要连接，地图原登记标明版本，不按关键词清空未知。实现与要求的差异是调查对象；要求来源之间的矛盾才是依据争议。执行完毕不会消除真实反证，有限通过不证明整体正确。

## 修订与来源

F2 有据修订性质、规范适用含义或故障／配置范围；F3 在保留命题的前提下展开、重连依赖；F4 修复实验前提。普通技术修复先保持观察事件、身份、谓词和前提，只修失败原因；不强制增加旧版复核或顺手改编码。新制品仍须实际执行与当前对应性复核。确需替换驱动前提时引用具体旧 issue 和来源，保持要求与 oracle；原争议不因新执行自动解决。ScopeUpdate 的实际写集校验决定 F2/F3 边界，不能仅凭字段名含 scope 选择 F3。

选检查入口时，沿实际接口确定调用、串行化、存储、应用和完成责任。若许可明确属于另一个入口，比较补齐当前入口的对应解释、直接使用许可明确的入口与低成本探索；不默认偏好高层接口，也不要求遍历所有变体。源码保护足以解释怀疑时可直接处置；需要判别真实生产者或调度时再执行。稳定关系回地图，单次观察留在执行与反馈，下一题复用已有认识。

已受理 DirectCheck 的 checker 错译由原 issue 指向旧计划，在原 unit 中提交受限的编码纠正，保存新计划和真实新执行，再做定向复核。原计划、日志、评估与争议保留；仅谓词变动和伴随观测输入适配分别记录。必要条件“成功则具备合格支持”不能写成“成功当且仅当具备支持”：合规支持下暂未成功，不构成同一资格安全性违反。

直接检查必需一次当前版本的整体对应性复核；有具体适用性或分解争议时才补相应实质回答，不增加逐对象审批。固定输入中的 conflicts 进入已有 ReviewIssue／IssueResolution 链，条件有准确来源与归属。更换驱动的受理不解决争议，新执行和针对性回答缺一不可；新来源足以解释同版输入时无需故意重写测试。处置只对回答版本及其后继有效，旧执行不会因新驱动合法而变合法；共享规范争议按真实依赖传播，checker 同名不建立依赖。无问题意见仍是暂定判断，mock 和小型测试只验证框架能力。

| 调度和可用性 | 三节点 Tick，CheckQuorum=true；40 tick，两个 follower 各记录 40 个心跳回复，队列为零 | 只对 1、2 Tick，未启用 CheckQuorum；1、2 满足两侧多数，pump 每轮排空可用工作，最多 300 轮 |
| 有限输出 | tick 10 清除目标；tick 40 仍 joint，applied=commit=last=3、无退出条目；控制退出到 4，后续提案恢复到 5 | tick 10 清除目标，tick 30 仍 joint、applied=commit=last=3；无转移控制到 4，后续应用到 5 |
| 观察路径 | 直接读取活动 raft/tracker/log，并计数实际退出条目 | ApplyConfChange 返回 true，但 Status.Config.AutoLeave 显示 false；独立固定检查将差异定位到 Config.Clone，不能据此说活动策略丢失 |
| 其他触发与推导 | 复核论证应用响应／快照才触发 appliedTo，超时只清字段，空 Ready 和稳定心跳不产生新应用；成功转移、新选举及新提案属于另一条件 | 已观察后续应用可恢复，但未为这个隔离／降级调度提交固定 AutoLeave 义务、对应性复核或完整可重复后缀论证 |

门槛差异在于：旧轮把有限输出与源码无继续触发的论证结合，当前轮仍要求进一步建立进展责任。后者不能仅因“无数值期限”封闭调查；前者也不是仅凭等待 40 tick 确认。真实场景差异包括降级／移除、转移目标、丢包范围、CheckQuorum 和 tick 对象。当前探索没有穷尽隔离节点恢复、并发来源或全部计时状态；有限字段相等不足以证明闭环。上述差异不构成对旧限定历史的新反证，也不授权把当前暂停改为确认。状态复制缺陷另有独立责任和新执行，不借用 AutoLeave 活性结论。

通用离线正反例人工核对（不是 Agent 评价）：自动任务暂时拒绝后仍有独立重试队列时，短窗口未完成不能报缺失触发；在已履行调用者义务、排空工作且相关队列／定时／回调均无重试的约定条件下，可调查源码支持的继续责任，仍须区分有限观察与可重复性推导；合同明确要求调用者稍后重试时，未重试而不完成不支持实现违反。现有通用执行／timeout 回归验证记录边界，不宣称脚本证明了模型的无穷执行推理。

冻结交付按实际提交、manifest `audit-products-v44` 与运行时加载字节核对。报告仍为一个只读生成器：主表四列、完整结果一次判断，欠账明确显示；保留决定性假设和执行替代，排除范围与历史交接转为原记录导航。未新增持久字段、产品、配置模式或依赖。第三目标准备另行确认固定版本、执行包、调用者责任、离线依赖与构建、隔离和事件保留；工具链准备与新会话自主审计分别授权和计预算，不预置缺陷答案。
