# CA harness：设计与修订依据

更新日期：2026-10-13。核对工作树：`refactor/evidence-first-audit`，基于已提交并推送的 `f89a8f5f`，本轮方法为 `audit-products-v74`。

本文保存此前讨论形成的设计、当前实现边界及最近实验带来的修订依据，供后续实现与复核共同维护。它是人类设计文档，不是新增运行时指令或验收门禁。运行时方法仍以 [task-skills.json](../src/consensus_assurance/resources/task-skills.json)、system、skills 和 tasks 为准。本文中的历史案例只用于离线开发分析，不注入新的自主实验。

## 1. 目标与职责

CA 的目标是提高模型提出的独立 CFT 共识缺陷主张的真实性、价值和证据质量，同时支持深入探索、证伪、纠错和持续发现。代码量、检查次数、知识条目数量和运行时长均不能替代这一目标。

我们开发的是使用原生 Agent 的共识审计方法。读取、搜索、上下文管理、源码调查和草稿构造交给 Agent；CA 保存研究结构，提供可靠的执行、证据关联和反馈边界。避免重新实现 Agent 框架。

职责分为三类：

| 承担者 | 应承担的工作 | 不能据此宣称的保证 |
| --- | --- | --- |
| 模型 | 发现疑点，判断责任与前提，构造区分性调查，解释证据，修正认识和分配研究资源 | 有完整文字或通过结构校验就已正确理解合同、可达性和因果关系 |
| CA | 执行隔离，版本与对象关联，原始证据保留，预算执行，已登记依赖与缺口处理，当前反馈 | 仅凭源码位置、字段完整、测试通过或比较结果就证明语义成立 |
| 人工离线复核 | 确认最终缺陷有效性、CFT 相关性、独立根因与实际价值 | 把历史核验答案提供给下一次自主发现 |

强模型和弱模型使用同一职责划分。模型能力提高后，可减少解释性引导；权限、历史只读、执行隔离、证据身份和预算等事实边界仍然保留。不能用不断增加表单和流程代替语义推理。

## 2. 三层能力与九个维度

| 层次 | 维度 | 设计落点 |
| --- | --- | --- |
| 发现有价值的问题 | 问题发现能力 | 从实际决定、已受理责任和跨路径条件差异形成有来源的怀疑 |
| 发现有价值的问题 | 正确性责任判断 | 区分规范、实现行为、测试预期与假设，辨别调用者、环境和内部生产者的责任 |
| 建立可靠的证据 | 可达性 | 由合法初始化、真实生产者和兼容前史建立关键前提；保留不能完成的部分 |
| 建立可靠的证据 | 观测有效性 | 追踪实际对象、身份、原始操作数、回调及完成点，识别观测缺失 |
| 建立可靠的证据 | 因果判别能力 | 用实际路径、反证和有区分力的对照判断竞争性解释 |
| 维持持续研究 | 研究终止性 | 局部问题可以确认、否定、收窄或暂停，明确剩余边界 |
| 维持持续研究 | 错误修复能力 | 新证据改变旧前提时，修正原问题和明确依赖它的解释，保留旧证据 |
| 维持持续研究 | 持续调查能力 | 从条件化的已知解释返回整体关系，选择仍有价值的不确定性 |
| 维持持续研究 | 独立性与研究收益 | 区分同根因深化与新问题，按预期信息收益安排工作 |

这些维度是设计与评价角度，不是九个必经阶段或每轮必填字段。一个短的源码调查也可以同时完成其中多项。

## 3. 问题发现：从决议及其依据出发

以两条互补的调查主线（investigation axes）组织正确性问题：

| 调查主线 | 关注的关系 |
| --- | --- |
| 决议形成与推进（Decision formation and progress） | 各节点如何形成相容的决议，已受理责任如何继续推进、完成或交接 |
| 上下文有效性与权威转换（Context validity and authority transitions） | 决策依据在何种上下文中有效，决策权威的取得、转移或失效如何影响既有依据和待办责任 |

五类支撑机制（supporting mechanisms）是恢复与重新同步、配置与参与资格、决议应用与消费、历史与持久化、客户端合同与完成语义。它们覆盖成员变更及当前资格、状态机应用及其他决议消费、持久化及依据重建、调用区间及完成责任。主线提出正确性关系，机制用于追踪落实这些关系的实现责任；二者交织，支撑机制也可以直接决定安全性，不表示重要性较低或研究阶段。全局理解与局部调查相互推进，不以读完整个仓库或形成完整地图为前提。

一个有效起点可以是已经产生的决定，也可以是已经受理但尚未完成、取消或交接的责任。例如：接受提案、确认日志、推进提交、应用状态、返回结果、安装配置、转移权限或完成恢复。失去待办责任可能表现为停滞，未必出现一次错误的决定。

沿实际关系追踪：谁产生依据，谁消费依据，哪种允许发生的真实事件会改变其适用条件，决定是否仍有依据、待办责任是否仍能延续。重点利用共识性质检查：

- 同一逻辑位置、对象或已确认历史，是否在不同合法路径上得到不兼容的决定。
- 用于授权决定的任期、成员资格、配置、上下文和历史是否仍然适用。
- 确认、持久保存、提交、应用和对外完成之间是否存在遗漏或错误对应。
- 重启、恢复、配置变化和异步回调是否保留必要的顺序、身份与未完成工作。
- 已受理责任在正常允许的推进机会下，是否存在无修复出口的阻塞机制。

上述关系帮助提出怀疑，不自动证明缺陷。例如两个入口存在不同保护，只说明值得追踪；保护可能由调用者或更外层代码承担。

使用已有 Investigation 的 question、hypothesis、discriminator 表达问题、暂定解释和下一项能改变判断的阅读或观察。没有必要先把假设写成一个已确定的正式义务。记录可以简短，不要求重抄完整历史。

负面结果形成条件化理解：某项保护在已研究的条件下解释了行为。仍有具体机制支持的未观测后果应继续调查，不能随局部否定一起排除。条件变化、不同生产者、恢复入口或权限切换后的待办工作仍可以产生新问题；负面结论不成为整个模块的永久排除名单，未覆盖分支本身也不构成缺陷假设。

## 4. 责任、前史和证据

### 4.1 先辨别当前主张所需的责任

同一事实在不同责任下含义不同。观测到错误返回、选举失败或启动失败，并不足以单独说明违反了适用合同。

区分来源中的保证、概率描述、推荐用法、明确禁止、实现保护和测试中的一个成功场景。存在回退实现不自动承诺所有输入都能回退；某次返回成功的测试不自动建立所有执行中的强完成保证。源码与注释发生分歧时，应调查适用范围和实际调用关系，不按文字优先级机械裁决。

明确必要前提由谁建立。调用者违反明确限制时，不能把产生的异常直接提升为合法使用下的缺陷；目标内部生产者在合法外部使用中破坏消费者前提时，责任仍可属于目标。缺少明确禁止同样不能单独证明输入获得许可。

当关键反证否定一个必要前提，在原 Investigation 下提交后续 Interpretation，修订当前主张或范围，必要时撤回；若维持主张，说明反证为何不适用。把反证放入 counterevidence 或 limitations 不会自动完成这个工作。不能仅因有反证就否决一个已有独立依据的局部问题。扩大下游危害范围所需的研究，不自动成为局部主张成立的必要前提。

### 4.2 可达性是当前主张的前提，不是统一部署规模

优先复用真实构造器、正常生产者和目标测试工具，用允许的延迟、调度、消息投递、故障和重启控制关键条件。单进程多个实际实例可以建立有效历史；也允许有独立合同依据的局部检查。

状态注入和内部处理器调用可以用于探索。要形成相应缺陷主张，关键供给状态需要真实前史、实际生产者或独立适用的局部合同支持。缺失部分继续调查或保留为必要缺口，不以批准、修辞或换一个更局部的终点消除。

故障模型属于前提。一次返回错误且没有完成的写入，与已经确认保存的数据后来被删除，具有不同的责任边界。旧快照的字节可以读取，也不等于它和现有日志足以恢复当前历史。相同编号不能证明两段历史兼容。

### 4.3 观测需要到达宣称的对象和完成点

观测链应能从真实运行对象追到回调、实际返回值或状态采样，再到原始操作数和比较。观测冲突时，先核对计算与采样；阅读实现及已有输出可能已经足以区分解释，无须扩大场景。重复出现说明可复现，不自动证明测量语义正确。观测未知、未完成和实际错误是不同情况：超时不能转换为空错误，未采样到不能转换成不存在，读取第一个对象不能代替读取被主张的指定对象。

有限采样的否定结果保持其时间与覆盖范围；零次检测不能直接推出事件不存在或发生率上界，必要时核对观察器能否检测相关转换。输出时间、采样次数和实际协议事件时间也应区分。接口返回成功、日志已保存、状态机应用完成按实际合同分别解释。

控制器校验已声明事件的身份、依赖、解析、完成状态和比较。任意测试代码是否真的测量了某种协议语义，仍需追踪实际计算与源代码。不能通过布尔字段禁令、工具白名单或关键词扫描取得这种保证。

### 4.4 对照服务于竞争性解释

对照由具体争议决定。例如同样错误作用于另一类请求、同一路径使用合法输入、变更可疑条件后重新观察，或核对实际对象与存储内容。对照也可以来自决定性的源码关系，不设置两次测试等配额。

每次深化应解决一个实际未决点：前提是否成立、结果是否来自所称对象、哪个机制导致后果、后果是否跨越已观察边界。同根因多种后果可以提高价值和可信度，仍按一个根因计算独立发现。

## 5. 具体证据、模型判断和人工核验

执行状态、输入保护、比较结果、关联事件、必要缺口和解释各自表达具体事实，不再压缩成 `confirmed` 或 `reviewed_complete` 综合标签。缺少固定 requirement 的探索回执仍能支持来源化解释；固定比较仍保留身份、前提关联和完整性诊断，实际失败不能变成完整执行。一个完整局部见证与另一项独立未完成工作可以并存；非零退出的狭窄独立失败归属继续保留具体比较、事件及日志位置。

Interpretation.conclusion 描述证据解释，defect_claim 保存模型当前明确提出、否定或保留未决的缺陷主张。异常预测的 holds 可以支持缺陷解释，违反某个比较也可能来自不适用的前提；两者不能自动推导真实缺陷。控制器不判断任意合同的语义。人工离线核验评价最终有效性、独立根因和价值，不能代替运行中的研究与纠错。

新实验研究记录和报告使用英文，直接展示 Investigation.question 与 Interpretation.rationale，不再生成独立的中文标题或摘要。最新 Interpretation 是整个问题的当前解释：在已有 rationale 中说明证据或源码理解改变了什么，保留仍适用的发现、反证与边界；新增回执不能把它缩成最后一次执行的小结。更强的后果需要相应依据，新的源码理解也可以复用旧回执，不强制新增实验。详细前史引用已有记录，不要求每轮重抄。每次解释必须显式填写 defect_claim，允许 null 表示没有当前缺陷判断；省略会得到普通类型诊断，不静默删除或继承旧主张。当前反证与限制只由 Interpretation 维护，未执行实验时也可保存源码解释；Investigation 不再维护另一份同义字段。新证据改变原假设或判别条件时，在同次提交中更新原 Investigation；报告如实展示登记的判别条件，不自动认定它仍是下一步。

解释、责任理解或适用性判断可在原问题下修正并引用旧回执，无需形式性重跑。改变 requirement、驱动、适用条件或比较时，仍需明确后继、实际差异和新执行，不能事后改写固定依据。历史运行和原始报告保持只读，不迁移旧字段。

## 6. 持续研究与纠错

### 6.1 局部收尾与开放运行

局部问题可以得到答案或暂停。开放运行仍按总时间、模型回合和正式执行预算继续有价值的研究；只有预设有限定向任务可以提前完成。该原则不要求制造新问题、强制执行实验、增加形式性知识或重复结束语。

下一步可选工作包括：回答一个必要缺口、检验当前解释的脆弱前提、把局部因果链延伸到真正终点，或者根据已知条件返回两条调查主线选择独立关系。优先选成本较低、能够改变当前解释的阅读或观察；若缺少合法生产者或相容历史，就补这一依据，不以估计症状发生率代替处理必要前提。剩余时间少时，解释现成回执、修正已有认识、短的源码追踪或保留清楚的判别点也有价值。

控制器负责提供真实剩余资源与既有对象位置，模型负责选择工作。当前操作相关问题的反馈完整保留最新解释的反证与限制；全局重选仍用有限摘要导航，完整记录可按 ID 从 research.json、state.json 读取，不复制全历史或自动恢复旧解释。已有按开放缺口及最近更新选取问题的规则不变。无变化反馈说明旧内容已受理及本轮成本，不重复整套方法；无变化不代表整体完成，不设置重复阈值、处罚、会话重置或自动提前结束。

时间反馈应当区分总预算剩余量、单回合可用时长和限制来源。现有字段提供这些数值，v68已在原说明中澄清：timeout_limit 表示哪个上限裁剪了本回合，不表示该上限已经耗尽；正的 timeout_seconds 仍是可使用的时间。v72允许明确的单回合截止在预算内继续原生同一会话：保留超时回执和草稿，不受理未完成提交，下一回合正常计费并重新经过既有输入／权限检查。缺少会话身份、会话不一致、服务或权限错误、取消仍停止；总时间与调用预算不延长，不另设重试计数或调度器。总预算到期时保存产物并停止，不要求额外收尾调用。

### 6.2 理解通过预测、使用与修正积累

调查主线和支撑机制引导源码阅读；Behavior 描述实际条件行为，Fact 说明它对哪个对象和上下文建立了什么。这些概念连接研究方向与条件化理解，不是必须逐级提交的产品流水线。没有 Fact 或派生引用本身不能判定研究失败。

可复用知识记录条件、来源、实际观察和明确版本。只有后来选择工作、解释结果或修正认识时实际用到它，才表现出累积作用；仅增加条目不能代表理解加深。源码调查形成负面结果同样有价值。

派生知识使用已有 KnowledgeUse 引用 entry_id、revision 和所依赖的 assertion。知识修正保留旧版本，沿记录的直接或间接引用找到终端 Investigation、FixedExperiment、Interpretation，包括仍引用旧版根知识的使用者；模型通过 changed_premise 与 affected_uses 指出实质影响，进入原调查已有的 gap／answer 路径。补报影响无需人为改动正文；完全重复的修订仍去重。

Interpretation.answers 将指定缺口映射到 explanation 与 resolved：前者记录具体来源或观察，后者显式声明是否解决。resolved=false 保存部分进展或重新打开旧缺口，true 才声明解决；省略该 ID 保留前次答案。控制器按适用历史计算当前状态，不把有文字自动当作解决，也不判断说明在语义上是否充分。旧解释和执行保持不变。

依赖维护不会自动判定语义影响，也不会全量作废后代。替代支持、未改变的条件和不相干用途保留。若某个派生条目本身需要修正，更新其原 ID；不能只新增相反认识，让旧结论保持原样。解释修订可以复用未变输入的回执。

当前系统只能沿已登记的依赖传播影响。后来发现遗漏的依赖，可直接在受影响调查下登记具体必要缺口，不必先补造知识图；不能靠文字相似度推断影响，不恢复独立 Claim/Binding/Relation 图、知识审批或推理调度器。

## 7. 高内聚、低耦合的实现归属

| 模块／所有者 | 责任 | 修改边界 |
| --- | --- | --- |
| Investigation | 问题、假设、判别方向、处置、暂停条件、必要缺口和历史 | 新证据修正原问题；不重复维护解释的反证与限制 |
| FixedExperiment 与执行适配器 | 确切输入、可选要求、比较、隔离执行及回执 | 保护输入和来源；不推断任意规范含义 |
| Interpretation | 证据归属、解释、缺口回答、反证、范围及缺陷主张 | 与机械比较分开，保留历史 |
| workflow/knowledge.py | 知识版本、明确使用与受影响调查定位 | 依赖算法只在此处；不新建调度职责 |
| workflow/research.py | 从权威记录派生当前视图、纠错位置和重新选题反馈 | 只读投影；不建立第二套研究状态 |

## 8. v67 HashiCorp 实验带来的归因修正

离线样本：[2026-10-12_21-19-58 运行](../runs/2026-10-12_21-19-58-hashicorp_raft-real-run/report.md)。运行60分钟、57回合、11次目标执行，4个模型缺陷主张。以下是本次复核判断，不改写原运行。

### 8.1 持续性：模型时间误读与反馈接口不足共同作用

第23回合分配900秒，timeout_limit 为 agent_turn_timeout；第24回合分配814.877秒，限制来源首次变成 total_seconds，模型即宣称到了总时间边界。第25回合仍有756秒，第31回合仍有440秒，均继续使用“到期收尾”的解释。

这一时间对应关系支持一个具体假设：模型把“受总预算约束”误读为“总预算已耗尽”。它不是字段数值传错，也没有证据表明宿主重复返回旧action。现有说明详细解释时间戳和保存时点，却未直接澄清限制来源不等于耗尽状态。这不是唯一已证实原因：第9回合尚有约35分钟时模型已泛称时间紧张，第17回合也提前提到到期。完整历史stdin未归档，当前代码传递路径与本轮回执一致，但不能据此还原每轮提示的原始字节。

模型随后主动重交原submission。55次受理中有27次无变化；末段第31–56回合连续26次重复，最后实质提交到停止约7分21秒。去重保持了历史正确，但没有改变研究行为。已有每轮剩余预算与重选提示，故问题不能简单归结为“系统没有要求继续”。

系统可承担的最小改进是消除时间反馈歧义，并在现有无变化反馈中针对已发生的重复作简短行动引导。模型仍须根据真实剩余时间选择有价值的问题，不能保证单改措辞就一定恢复调查。保持单会话和现有预算，不增加重复计数终止、自动换题或硬性阶段。

### 8.2 责任判断：已有规则没有被正确应用

领导权转移问题把“目标很可能当选”和正常场景测试提升为“nil 必然保证目标已经接管”。快照问题把“存在由新到旧尝试的分支”提升为“存在旧快照就必须启动成功”。这些推导主要是模型的语义错误；运行方法已经区分实际行为与规范、接口受理与输入许可、反证与必要前提。

四个调查均未登记必要 gap，故本次没有发现已登记 gap 被绕过的功能漏洞。控制器能保护已登记的前提和引用，无法仅凭源码位置判断模型是否提出了正确的义务。若要求控制器自动发现这些语义问题，会重复实现一个领域推理者，并可能错误压制合法局部研究。

当时存在确认标签驱动形式升级的现象：快照第二版补 requirement、responsibility、锚点等说明，驱动与比较不变，修订理由明确是获得 fixed-witness confirmed。v70 退出该综合标签，保留具体证据和限制；已有缺陷解释可引用探索回执，不能以填满字段代替检验规范前提。

很多counterevidence写成“有人可能认为”的假想反驳。已有的弱保证措辞和恢复前提应作为实际相反材料直接限制主张，而不只由模型替对立意见作辩论。针对责任的疑问，需要合同和允许历史来回答；换一种方式触发相同症状，通常只排除了一个触发解释。

应将领导权转移的审查重点收窄到不适格目标仍触发转移及短暂领导权扰动，并核对该局部接口责任；快照保留真实panic，继续调查自动恢复与错误处理责任。原地Restore也不能仅凭一条警告判非法，官方测试同时覆盖原地和新集群恢复；判断仍需结合具体历史。

### 8.3 纠错能力：有实质成功，也有尚未使用的机制

配置写失败调查最初认为后续配置变更会永久被阻塞。实际结果推翻了这一部分，模型修正原调查，继而验证新任期Noop占位、错误配置进入快照及下一次配置日志，并补普通命令写失败对照。这是一条有证据增量的纠错和深化路径，应保留其自由调查能力。

7条知识全部为Behavior revision 1，派生依赖为空。前4条随实质研究产生，后3条在模型宣称到期后提取；其中末尾2条没有后续使用。早期错误前提是在首次创建对应知识前修正的，没有证据表明当时应该修改旧Knowledge却漏改。缺少知识修订或Fact不能单独认定为框架缺陷，本轮只是没有实际使用派生纠错路径。

实际需要改进的是知识条件的准确性：末尾正常转移知识将一次成功对照写成普遍完成保证；快照知识将“选中位于空洞之前的快照”扩大成“只有最新快照可用才可启动”。前者目前没有使用者，不能声称已向下游传播。快照问题的hypothesis还保留“没有执行、没有主张”的过期措辞，而最新解释已有执行和主张。现有同次合并更新即可修正这些条目，不需要强制造Fact、知识升版配额或新状态机。

### 8.4 观测错误：不能以形式见证代替测量核对

生成驱动中的等待函数可能返回(nil, false)，部分调用忽略完成标志；领导权驱动用遍历所得首个Leader推断指定目标是否曾领导，并以采样次数乘sleep时长描述领导空窗。这些是模型构造与复核的不足。

本次配置核心见证有直接错误返回和后续日志内容支撑，未被上述潜在超时分支推翻；领导权机理也有实际拒票日志与源码支持，但采样与时间表述应收窄。若这些分支实际成为决定性证据，完整JSON事件仍可能表达错误测量，控制器不能靠解析成功发现它。

优先落实既有“追踪实际对象、完成与原始操作数”要求，按具体异常核查驱动。不能因此新增通用测试框架、禁止所有派生布尔值或给目标函数建立调用白名单。
