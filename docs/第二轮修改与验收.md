## 同一行为在不同契约下的判定

被测样例通过实际回调发出 `returned` 响应事件，再更新 persisted 状态。这里的“响应”是样例 API 的回调事件，不宣称它等于生产 RPC 或 `execute()` 函数退出。事件状态来自被测代码，未由 harness 输出预期轨迹。

内存配置只检查接受保证，不因为缺少更强保证而判错；持久化配置的明确承诺被真实字段显示违反，不能仅因行为是有意编写而称为优化。冲突材料保留未决。部分观测对应好坏两种隐藏状态时，模型兼容和模型反例不合成为实现反例。

另有代码派生义务回归：不要求文档写明每条义务，但要求实际生产/消费绑定、推导和适用条件，仍保留候选身份与缺口。

## 反馈、恢复与权限

- F1 修正实际行为解释后重新校准，检查器保持；无关模型的结果不全部失效。
- F2 用实际旧/新主张及依据修改相应语义版本，旧判断进入 graph_history；冲突分支记录 unresolved，不自动采纳弱保证。
- F3 旧范围内的历史结果保留，加入新代码不证明边界保证成立。
- F4 只改实验。实际测试经历初始 replay → 前提 not_reached → F4 → 新 replay → 前提 matched → 再次性质判定/归因；mock 来源最终仍不能确认实现缺陷。
- 测试在动作开始、动作结果落盘和重放计划保存等位置模拟中断，恢复保留原模型与反例，继续相应动作；结果未知会明示并预算内重试。
- 关闭实验权限后不执行目标能力测试和重放；只保留工具版本等不执行目标代码的探测。
- 技术修复得到真实错误文本和明确截断元数据；编译/导入失败、非法输出、TLC 语法、缺工具、超时不强行归为语义反馈。
