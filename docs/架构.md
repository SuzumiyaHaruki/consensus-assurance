# 框架与八步流程

最终任务书的中心对象是 G（目标）、O（义务）、C（实现绑定）、M（局部模型）。`core/types.py` 保存这些对象与执行、校准、证据、发现、审计单元和修订记录；`core/proposals.py` 定义 agent 输出。后者不允许 agent 直接创建“已确认实现违反”。

| 步骤 | 代码 | 实际行为 |
| --- | --- | --- |
| ① 理解与能力探测 | `workflow/materials.py`、实现 adapter | 建立快照和符号目录，分段读取资料；实际执行已有测试探测，不把工具安装当作精确调度能力 |
| ② G—O—C 关系 | `workflow/graph.py`、英文 discover 任务 | 校验来源、代码范围和对象引用，建立可修订关系 |
| ③ 选择与边界 | `select_unit`、`expand_unit` | 优先检查尚未解释的上游依赖，记录所引用关系和绑定；F3 必须增加具体内容 |
| ④ 生成产物 | `workflow/artifacts.py` | 接受生成的行为、检查器和实验，校验后保存新版本；无通用固定投票目标 |
| ⑤ 真实轨迹校准 | `adapters/verifiers/trace.py` | 解析实际 stdout 事件，直接投影到 Obs，在同一行为模型上搜索完整观测序列可达性 |
| ⑥ 模型搜索 | `adapters/verifiers/tlc.py` | 调用真实 TLC，区分反例、有限搜索完成和工具错误，记录工具报告状态数/深度 |
| ⑦ 实验 | `adapters/runners/experiment.py` | 在新副本写入生成 harness，以 adapter 组织的 argv 运行，保留原始事件与前提顺序 |
| ⑧ 归因反馈 | `workflow/feedback.py`、`workflow/engine.py` | 校验修订对象与证据，生成新范围或产物，标记旧结果需重验 |

`consensus/inquiry.py` 只提供跨协议的支持来源、接受条件和历史约束调查结构。协议包是有出处的候选知识；实现 adapter 只识别目标、组织构建和实验命令、描述已探测能力。模型和 harness 默认由运行时 agent 生成。

核心和工作流不导入具体插件，入口 `registry.py` 装配。源码扫描、artifact 路径组织、普通进程执行属于共享技术层，与具体协议状态无关。

## 关系怎样实际改变执行

依赖方向为“消费义务 → 提供边界保证的义务/绑定”。存在尚未检查的上游审计单元时优先选择它；已有具体绑定时直接扩展；尚未读取上游代码时，F3 记录关联缺口，通过 catalogue 和 ReadingPlan 有预算地读取真实片段，增量加入 binding/relation，再生成新范围。不会对所有边自动传播 `supported`。

非 Raft 夹具的初始范围只包含 `counter.step`，关系声明输入依赖 `normalize_limit`。第一次搜索结束后仍有边界缺口，框架据关系生成新单元，加入实际输入代码，再生成模型和观测、重新运行实验和校准。测试还会删除/增加依赖边，断言被选择的单元发生变化。

## 行为与性质分离

`Behavior.tla` 定义 `Init`、`Next`、`vars`、`Obs`；`Properties.tla` 引用行为并定义待检查性质。框架生成配置，不接受 agent 返回任意执行命令、状态过滤约束或宿主语言覆盖模块。

这些结构检查不能证明抽象忠实性，也无法完全判断某个等价表达式是否隐含假定了待检查性质。必须结合代码来源、关键约束记录和实际校准解释结果。

## 可执行轨迹校准

实验输出 `CA_EVENT` 加 JSON；Go `-json` 输出先取真实 `Output` 字段，再解析事件。原始日志保持不变，投影另存文件。

TLC 在行为状态上增加 `cursor` 和有限 `internalSteps`：每次消费下一个真实观测，或者执行 Obs 不变的内部动作；只有显式允许时接受重复观测的停顿。不会跳过不匹配的真实事件。缺少必需字段、事件或足够观测时结论不确定。

校准故意检查 `TraceNotAccepted`：其反例是“完整观测序列可达”的见证，表示有限轨迹兼容；完整搜索无此反例表示当前投影及内部步数限制下不兼容。校准阶段不把义务性质作为约束，因此可解释真实违规行为。

## F1—F4

| 类型 | 允许变化 | 校验及执行去向 |
| --- | --- | --- |
| F1 | 行为、观测或环境解释 | 检查器文本、性质名和主张引用保持；生成新模型并重校准 |
| F2 | 有新材料依据的目标/义务关系 | 记录旧/新判断、推导及适用性依据；用版本化增量 patch 更新，不按来源文件种类判断权威 |
| F3 | 具体依赖范围 | 关系必须来自当前范围，加入义务或绑定；重新生成模型/观测，不拼接通过结论 |
| F4 | harness 与实验前提 | 模型、性质、范围和观测均不得顺手改变；新实验版本实际重放并检查同一操作/参与者/上下文的条件关系 |

工具语法错误走独立有限修复，不归因成 F1；认证、额度、超时和工具缺失保留各自状态。

## 状态与版本

执行状态、模型结果、校准状态、主张评估和发现层级分开。旧制品使用新目录保留；JSON 检查点原子替换，历史版本和事件另存。串行运行采用文件锁避免两个控制器同时恢复同一运行。

内容摘要仅解决具体输入身份问题：同一 Git 提交下的未提交代码、无 Git 的副本以及被修改的模型/观测不能仅用提交号区分。主键或版本号只能给对象命名，无法确认文件是否被外部修改；事务解决写入一致性，类型和普通行为测试也不能追溯当时输入。这里使用 SHA-256 记录实际内容；它不是批准门槛、冻结规范或整体正确性校验。

## 第二轮的语义依据与性质归属

默认只提供通用 inquiry，`protocol: none`。协议身份可正常识别，知识可用于提出方向，但不能代替实现适用性证据。`Grounding` 在 Claim/Relation 中分别记录行为材料、职责依据、代码绑定、推导、适用条件、未决、冲突与替代机制。文档、测试、接口、代码的分类只帮助检索，不能自动赋予规范权威。

代码生产者/消费者之间的职责可以导出候选义务；无直接期待材料时需有生产与消费绑定及明确推导。字段完整不是语义正确性的证明，争议和缺口保留。F2 不能只凭失败或“优化”放宽性质，必须针对真实旧/新主张给出可引用依据，并保留旧版本。

`Bundle.checkers` 用每个 `{invariant, claim_id, scope}` 明确映射。旧单主张资源可以无歧义兼容，多主张旧列表必须显式迁移。TLC 反例只归属于被报告且实际配置的 invariant，同行其他性质记录 unknown；完整有限搜索成功只支持实际配置的 checker。Finding 不再使用模型首个 claim 代替归属。

## 定向读取与增量关系

`targeted_gap` 和 `reading_history` 记录任务所属义务、原缺口、实际请求、新增片段。材料预算按累计字符与片段计，`unread_ranges` 保留文件内未读部分。GraphPatch 保留其他对象，并要求被替换对象的 expected_versions；`graph_history` 保存旧内容。F3 不借道 F2 改写义务，也不因加入代码就确认边界保证。

完整授权执行副本与可发给 agent 的片段分开：安全允许的二进制/构建资源仍复制并记录摘要，但不作为文本材料发送。adapter 可提供 required_inputs 与 symbol_hints。必要输入被安全过滤排除时明确停止，不声称执行了完整原实现。

## 实际事件性质判定

投影可以来自 state、事件字段或 metadata。前提使用有限 eq/ne 比较、早先事件别名引用和严格先后关系，不执行任意表达式。不同操作的同名事件不能拼成一个反例。

`workflow/observations.py` 支持在指定事件上直接评价充分观测的标量断言，例如响应时 `state.persisted == true`。缺失字段返回 unknown，不从隐藏模型状态补值。实现级确认还要求实际执行版本一致、该实验校准兼容、关联前提命中、监测绑定与适用性充分、合法性条件在观测执行中成立且无未决争议。只确认被监测的 G 或 O，不沿图传播。

首次反例实验走普通 replay_plan；只有实测前提未达到才进入 F4。重放后再次校准、评价监测器并归因，不固定以不确定结束。mock 和变异不能确认为原实现缺陷，受控原样例可记录自身的实现级义务违反。

## 轻量恢复与适用性

每次实际动作前记录 PendingAction，再写 input.json；返回后先保存 result.json，才推进 next_action。恢复复用已落盘结果，继续原模型/反例的动作。执行结果不明的中断保留 outcome_unknown，在预算内以新副本重试相同阶段，不虚构完成。

F1 影响本单元模型解释；F2 影响引用被修改语义/绑定的模型；F3 标为 historical_scope，不删除或改写原搜索结果；F4 只新建实验和校准。外部修改单个模型制品仅使相关模型结果需重验。完整快照/配置无法安全关联时停止并保留历史。


历史第三轮规则与取舍见 [第三轮审计修订与验收](第三轮审计修订与验收.md)：包括受限共享性质监测、跨事件历史、局部输出修补、逐义务进度及模型提交恢复。当前接口及验收以当前代码和第五轮说明为准。


第三轮将发现/补读、模型受理、调查上下文、agent 字段修补分别抽出到 workflow 的 discovery、modeling、investigation、agent_tasks/output_repair。通用事件函数在 core/events，TLA 语法和共享谓词生成在 adapters/verifiers。Engine 保留串行调度和检查点，不引入多 agent 或新存储平台。模型提交复用既有生成动作标识，先生成完整目录再登记，恢复复用同一模型版本。


第四轮增加职责探索和语义复核任务队列，具体调度、F2 语义对象修订及限制见 [第四轮覆盖与语义复核](第四轮覆盖与语义复核.md)。第三轮说明仍对应局部证据链机制；当前默认流程不再以一次 discovery 的清单作为全部分析边界。

## 第五轮：语义写入、执行输入与未决问题

`mutations.write_set` 从实际字段 diff 计算变更，覆盖 Claim、Binding、Relation、Unit。F2 的 `changes` 必须双向完整匹配；review 修订只能写本任务对象。普通 patch 可以增加候选，但不能改既有语义。`validate_patch` 和反馈校验在副本完成；`transactions.commit_graph` 用已有动作/执行 ID 保存状态 delta，校验后一次性采用，并可在中断后幂等恢复。模型的原有 commit manifest 保留。

模型搜索输入包含实际 Behavior、Properties、TLC 配置、常量、约束、检查范围以及引用的主张、关系、绑定和单元版本。`search_fingerprint` 专门防止同名 checker 的新谓词被旧执行充数。Git 或主键没有记录“哪次执行检查了哪个谓词”；版本号本身也不能判断 harness-only 修改是否影响搜索。仅 harness 改动不影响搜索指纹，但仍须建立 `reused_from` 指向原执行的显式记录。实现确认继续检查完整实验/观测制品关联。这个指纹不是用户批准门槛。

选择器先确定真正需要检查的生产者单元，再安排相应版本的复核。未审、争议和预算受阻分别保留；可做探索性建模，但记录具体未决对象及禁止升级的限制。SemanticReview 是一次回复，ReviewIssue 才记录后续问题；通过显式 resolves/supersedes 关联解决或完整替代旧意见，部分复核不能清除其余问题。

AuditQuestion 与可选 CoveragePoint 记录检查的意义及实际建立、保持、使用或恢复路径。未分配给单元的重要 handoff 会进入探索队列。任务拿到关联材料闭包和简要全局索引；已读但未带入上下文的材料可以重新请求，不能因此伪称新增读取。尚未纳入的真实代码仍沿 catalogue/ReadingPlan 补读。

`VerifierBackend.reachability` 支持有限状态触发谓词。在 TLC 后端中检查其否定不变量；辅助反例仅证明触发可达，无反例表示该有限行为下不可达，未完成保持 unknown。原始安全 checker 结果、触发覆盖与实现校准分别记录。确认 O 违反后有有界 consequence 处置：补读、建立关联单元、补偿候选或有理由暂缓；没有目标事件的观测不会升级为 G 违反。

## 第六轮：关联诊断与修复会话

`core/diagnostics.py` 定义稳定代码、候选版本、相关 ID、字段路径、材料和允许处理类型；`graph_diagnostics.py` 按身份/材料、定位、关联依赖收集独立问题。图验证在提交前完成，嵌套 patch 的修复指针按对象 ID 转到当前候选的位置。未分类语义问题保留完整候选并停止机械修补。

`locations.py` 使用 Python AST 和有限 Go 声明/分隔符索引，不执行目标源码。声明、接口成员与显式 callsite 锚点引用实际已读材料；callsite 只确认调用语法位置，不宣称已解析被调用者。内部行为片段可以不包含声明。`Binding.associations` 是唯一权威职责关联，旧 claim_id 单归属显式导入；只读单归属访问器用于历史调用者，多归属不得依赖它。单元的 `code_uses` 另行说明检查或背景用途，外部支撑必须沿本单元选中的 boundary/depends_all/conditional_on 有向链，并记录未验证保证。

`agent_tasks.py` 管调用和修复会话，`output_repair.py` 管授权指针、合并与上下文，`repair_policy.py` 防止机械定位变更改写行为范围。修复输出自身错误只影响 patch；每轮完整重验候选，重新构造相关上下文。会话和原始文件在 `repair-sessions/`，外层暂停存在 InquiryTask 中，局部暂停存在 deferred_units 中。任务总次数、问题重复失败、循环和全局预算分别计数。

`action_identity.py` 对比已保存的逻辑输入、inquiry、finding、响应 schema 和候选版本。调度剩余时间不是语义输入；源码、模型、权限、配置和材料的变化仍受检查。控制器格式标记变更或缺失时要求独立迁移子运行，不覆盖历史失败结果。

`EncodingRevision` 表达相同语义下的性质编码修正，保留前后模型和来源，不能改变行为、常量、范围及共享性质描述，也不能把 checker 改成常量 TRUE。新编码需要实际重验与对应性复核。新模型任务可显式授权解决旧 issue，保留旧坏模型的原判断；仅更换 harness、无关模型或未执行版本不能解除争议。

覆盖有四种不同记录：交接分配、单点状态可达、带 identity 的同一历史有序可达、实际违反见证的事件关联。序列可达性由辅助状态 progress/owner 编码，复用真实 TLC；它不约束原行为、不把不同路径拼成一次交互。模型层可以检查 G，即使实现监测还不完整；实现确认另行要求与真实违反事件同一标识/上下文的充分见证。

## 第七轮：复核契约、任务包与读取账本

`review_contract.py` 是类别/aspect/具体问题的唯一政策来源。`task_packet.py` 组装局部文件元数据、复核契约和实际发送 receipt；`reviews.py` 按对象材料闭包及依赖版本判断复核适用性。任务对象在 target_objects 中完整出现时，不在分类列表重复；binding 的 excerpt 用精确来源位置替代。材料永久保存在 state，重附加按 inquiry/unit 身份隔离。

`materials.preflight → plan_read → execute_read` 统一读取路径。预检不改变材料；执行使用已有事务保存逐项取得、缓存、延期状态及预算。部分取得允许记录，但必需范围未满足时仍处于读取阶段。区间并集计唯一字符和片段，记录对广度/深度的预留；单次 prompt 上限与全局调用数独立。

`agent_tasks.ask` 在各回复类型的语义校验前统一核验读取计划，并沿既有候选修复会话处理类型化诊断。新增 aspect 是 agent 明确输出的补充，不是框架重命名。`Engine.check_triggers` 对同输入的未知结果做有限技术重试，保留每次结果，完整不可达不会自动重试。

## 第八轮：范围接回与有限继续

`scope_updates.py` 复用 F3 的范围语义：从实际 diff 生成提案，保护原 goal/O、问题与故障/配置范围。普通 GraphPatch 的既有对象写限制不删除；受理时将变化编成候选新节点和一个有 previous_id 的新单元，经完整图校验后一次事务接回来源、复核与 build。事件/覆盖表达变化先做 ScopeAssessment，语义变化保留为 F2/调查待办。建模前后使用同一入口，不创建占位模型。

`expand_unit` 对明确选择的有向依赖取有限闭包，排序无关。绑定关联的其他义务保留为背景或待办，不自动纳入 checked obligations。已经纳入代码但仍未知的保证进入复核/限制，不反复执行无新增内容的 F3。

复核政策按 target/aspect 的版本和实际源范围复用已有判断；变化与旧问题仍可触发审查。IssueResolution 明确回应某个旧问题，scope_limitations 仅记录独立边界，不能解除未验证的当前依赖。新材料不能靠更换 ID 消除旧问题。

`task_packet` 提供紧凑索引和任务材料闭包，用共享源码视图保留重叠片段的完整内容及原引用。超限后按目标或概览职责有限拆分，父任务等待全部子任务实际完成；不可安全拆分的对象继续受阻。预算在真实后端准入时消耗，准备失败不算完成一次探索。范围提案和读取 receipt 的关联用于记录连接率，不作系统正确性覆盖率。
