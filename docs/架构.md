# 实现与验证架构

研究路线保持为 Activity → Surface 阅读 → Behavior / Fact → Candidate → 局部 Obligation → 测试或模型检查 → 修订。领域知识只提示问题，实际源码决定模型行为，适用合同决定检查要求。

核心类型和端口由入口组装为工作流；ExecutionBackend 可选，HashiCorp 与 SwiftPaxos 使用共同 Go 工具链后端。目标差异在 YAML 中声明，不进入发现算法。运行时方法在 resources/skills，机械任务合同在 resources/tasks，task-skills.json 决定实际加载资源与框架版本。

ConsensusAuditSpec 保留 target_profile、七类 Activity、Behavior、Fact 和 Surface。Behavior 的 produces_fact_ids/consumes_fact_ids 是唯一声明，反向关系为派生索引。规格受理版本保存在 audit-spec/vN.json，当前版本由 state.json 引用；未受理草稿和原始回复独立保留。

Candidate 的身份是控制器给出的 ID。继续和恢复必须引用 candidate_id；分流引用父 ID 和理由，父问题及其来源、反证、未决条件保留。控制器不比较自然语言是否等价，也不把来源集合变化当成新证据。工作包提供候选摘要，帮助分析者避免重复调查。

同对象的待处理独立补全把意见附加到已有任务 diagnostics。任务执行时读取最新 AuditSpec；不保存完整对象副本用于去重。requires_recheck 关联当前候选，独立补全不会因同对象或带诊断而升级为当前判断的前提。

材料读取只有一个入口：路径和区间校验后，在材料预算内返回取得、缓存、延期回执，再保存当前状态。读取不进入 commit_graph；图修改仍使用现有提交事务及操作 ID。材料获取与 prompt 发送分别计量，不按读取计划次数收费。

直接检查的 ObservableProperty 唯一保存 trigger、assertion 和 identity_fields；EventMonitor 只引用 checker_id 并描述事件、来源与适用条件。计划在接纳边界验证，执行从保存计划读取输入。制品 ID、源码版本、实际输入输出与语义版本记录来源；不在各层重新 hash 同一制品。

直接检查整体审阅当前义务、调用、前提、观测及判断规则，不等待逐对象方面记录。字段差异保留在 properties/outcome，适用性、人工输入和未查前史保留在 limitations；confirmed 是有限范围内的最终结论。观察缺失、关联失败或执行不明确仍为 unknown。panic 保留退出码和原始栈，归属未定。

模型路径保留 TLC 搜索输入身份、共同性质、实际校准、触达和后果判断的区别；模型反例不能单独确认真实违反。F1–F4 沿用现有边界，改实验不能暗改性质。

checkpoint 保存一份当前 state.json 和简短事件；原始 Agent 输入输出、工具日志和真正的语义修订历史独立保留。graph.json、audit-spec.json、audit-progress.json、plan.json 和 materials.json 在结束或报告时导出，不供运行时反向读取。

恢复只复用已完成节点，未确认完成的执行保留未知并在新隔离副本重试。旧框架运行只读；不承诺跨版本续跑、任意内部中断点精确恢复，或外部改写运行目录后仍可复用。已有历史文件和失败记录不删除。
