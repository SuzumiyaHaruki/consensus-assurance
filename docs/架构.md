# 架构与模块职责

系统采用一条领域引导、实现为据的流程。默认输入仓库，不预选 bug 或性质。职责认识、语义复核和局部验证交替进行；目标决定意义，义务决定重点，实际代码决定模型，实际证据限定结论。

## 模块边界

| 目录/模块 | 职责 |
| --- | --- |
| `core/types.py`、`core/proposals.py` | 主张、来源、映射、模型、执行、证据、调查与结构化提案；agent 不能直接生成已确认缺陷。 |
| `ports/interfaces.py` | 实现、agent、验证工具的可替换接口。 |
| `registry.py` | 配置装配；核心工作流不导入特定实现插件。 |
| `workflow/engine.py` | 单机串行调度、动作身份、预算和检查点。 |
| `inquiry.py`、`review_contract.py`、`reviews.py` | 职责探索、按实际单元版本复核、问题及后续处置。 |
| `materials.py`、`sources.py`、`task_packet.py` | 真实读取、唯一范围核算、相关材料闭包、实际发送 receipt。 |
| `graph.py`、`scope_updates.py`、`mutations.py`、`transactions.py` | 图一致性、实际写集合、受控范围接回和原子采用。 |
| `agent_tasks.py`、`output_repair.py`、`repair_policy.py` | 有限调用、结构化诊断、保全修复、会话恢复和修订边界。 |
| `modeling.py`、`artifacts.py`、`investigation.py`、`observations.py` | 模型受理、执行覆盖、反例调查、实际观测判定。 |
| `adapters/` | 进程执行、持久化、Codex CLI、TLC 及工具结果解析。 |
| `plugins/` | 可选协议知识与独立实现适配；不返回默认目标答案。 |
| `resources/`、`reporting/` | 英文运行时方法和中文报告。 |

协议特定的状态、消息和参数不是通用类型的必填字段。知识包提供有出处的候选方向，不把当前代码行为自动解释成规范；实现适配器负责构建和观测条件。

## 关系、代码与范围

Claim 表示目标、义务或假设。Relation 区分共同依赖、可替代机制、条件、支撑和边界，并保留来源、推导及待确认项。循环边不形成自我证明；子义务局部通过不自动使目标通过。

Binding 的物理位置由文件、内容版本、声明锚点与行为范围定位，行号不是跨版本身份。`associations` 是职责关联的权威来源，`code_uses` 单独解释本单元直接检查、输入背景或外部支撑的用途。外部保证需选定有向依赖，不按全图任意连通放行；纳入背景不等于验证其全部职责。

AuditQuestion、CoveragePoint 和职责交接记录帮助选题与扩展。未分配的重要 handoff 可形成探索任务。源码不足允许补读；材料已取得但当前包未提供时可以重附加。只有实际相关范围进入模型，不把完整文件阅读当作所有行为已覆盖。

## 模型、工具与证据

ModelCore 分开 Behavior 与 Properties，checker 显式关联主张和范围。动作依据源码中的中断点、状态所有权、消息/操作身份和故障契约。`context_analysis` 连接代码、变量、动作、checker 与实际触发配置；上下文不是全局轮屏障。

TLC 无反例只支持实际配置和有限模型。多 invariant 早停时只归属已违反的 checker，其余未完成保持未知。同历史可达性见证不是协议反例。轨迹校准仅说明模型存在解释有限观测的路径；实现确认需要合法执行、达到前提、足够关联观测及适用性质，不能从模型反例与轨迹兼容直接推出。

执行状态、主张评估和调查阶段独立表示。mock、录制输入、模型证据与实现证据分别标记，缺工具、超时、额度耗尽不变成通过。

## 修订与恢复

F1 修行为/映射/环境解释；F2 修属性或契约判断；F3 扩展实现范围；F4 修未达到前提的实验。无模型时也允许有依据的 ScopeUpdate。实际字段 diff 决定修改权限，既有语义对象受 F2 写集合和版本限制；新草稿的定位表示纠正仍需完整重验。

图操作使用现有动作身份原子采用；模型通过完整制品目录及提交记录登记。失败、旧模型与旧范围结果保留，变化仅影响相关适用性和重验任务。动作恢复比较逻辑任务及稳定输入，不能消费其他 finding 或 review 的结果。

搜索输入指纹用于防止同名 checker 的新行为或谓词复用旧结果。它覆盖实际模型、性质、配置、代码及语义版本；harness-only 改动可显式复用不依赖它的模型搜索，实际实现确认仍检查完整实验输入。该记录不是审批门槛。

预算、问题解除和来源规则见 [运行工作流](运行工作流.md)，能力边界见 [限制](限制.md)。


## 当前工作集与阶段产物

`workflow/task_view.py` 从当前 G/O/C、选定关系、未解决意见及显式问题解除记录投影建模输入。保留相关反证，包括旧模型链上尚未解决的 checker 争议；不发送整份复核档案。正面意见不能覆盖未解决反证。档案仍在原 state/history/agent 中，视图不写回旧判断。

`sources.source_views` 是连续同版本源码合并入口，定位和发送池共用。`locations.location_evidence` 给出声明身份、窄行为范围和原始片段来源；开放函数前缀不冒充完整函数边界。`review_contract` 继续是复核方面政策的唯一来源；`SemanticRevision` 将局部复核的 F2 schema 与未来模型/实验结构分离。

`ModelDraft` 与完整 `Bundle` 共用 ModelCore 和已有 artifact commit。模型阶段只写实际已有文件，不生成空 harness；`pending_work` 记录缺少组件。`workflow/staged_model.py` 管组件续行，Engine 只选择这些阶段。缺核心行为依据时保存草稿但不执行；只缺实验装配时可以 SANY 检查和未校准的模型搜索。补齐 harness/observation 后保存关联版本，依语义输入核对显式复用搜索，实际实验和校准各自执行。模型搜索身份不依赖 harness，实现确认仍依赖真实实验输入。
