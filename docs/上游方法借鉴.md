| 核对的上游路径 | 本项目采用的方法 | 明确调整 |
| --- | --- | --- |
| `skills/code_analysis/SKILL.md`、`guide.md` | 短入口、阶段输入输出、建模 brief | 不要求历史 issue 配额或多个 agent；问题不以疑似 bug 为前提。 |
| `skills/code_analysis/references/distributed-analysis.md` | 从执行结构、持久化边界和独立循环解释交错 | 不引入 HashiCorp 示例答案，不将故障种类当必填清单。 |

| `skills/spec_generation/references/trace-spec-pattern.md` | 真实事件字段与状态对应，保留观测不足 | 沿用本项目受控校准后端，不复制上游宿主读取命令或执行权限。 |

本项目正式技能位于 `src/consensus_assurance/resources/skills/`。`resources/task-skills.json` 是唯一任务路由表；控制器读取清单内容，真实拼入请求并在 packet receipt 记录路径和清单版本。后端不自行跟随 Markdown 链接；当前未启用 Codex 原生技能发现或额外文件读取权限。


本轮另行阅读固定 ref 的 `references/modeling-brief-format.md`、`src/specula/skill_refs.py` 和 `src/specula/output_index.py`，核对阶段写出和参考加载方式。采用“档案与下一阶段工作输入分开”“先保存有用模型，后衔接实验”“检查实际 cfg”的组织思路。本项目继续内联加载可信资源，不复制原生技能安装、巨大 pipeline、宿主读取或输出扫描代码；上游类别 A/B 与本项目 A/B/C/D 职责视角不同。新增职责/行为参考依据本次任务要求和本项目接口独立编写，不是上游文档翻译或段落复制。
