## 成本与 Specula 口径

本轮独立查看了 [Specula v2 §5.3 与 Table 5](https://arxiv.org/html/2607.25333v2)。§5.3 给出的 48 个系统端到端时长为 1.43–9.86 小时，中位数 3.69 小时；Table 5 列 Autobahn、CometBFT、libspdm、MongoDB、sofa-jraft，没有 HashiCorp 专属行。因此不能据此确认“HashiCorp 2–3 小时”，也不能拿本系统 26 分钟早停推算最终耗时或宣称更快。代码、信息、后端、硬件和停止条件均未做可比对照。

探索/复核计数定义为实际准入后端的逻辑 InquiryTask；同一任务的补读/修复仍受总 agent_calls 限制。局部 ScopeAssessment 也占 semantic_reviews。未发送包只有准备失败和实际准备时间，不退款掩盖已发送失败。字符/字节上限不等于 provider token 上限；没有 token/缓存/费用字段时不捏造数据。

首次图、scope 采纳/ready、有效 Bundle、模型登记、模型工具启动、完整搜索、校准和实现证据的时间来自本次检查点/执行记录；scope-ready 指本次有限复核条件，不是协议证明。源码取得到接回的连接率只针对明确标记需要 scope 接回的已完成读取计划，不与整个系统覆盖率混同。

## 剩余边界

1. 没有新的真实 Codex/HashiCorp 自主运行。本轮的真实工具成功不证明真实后端下一次会提出正确、完整且可执行的模型。
2. 自然语言细化判断、问题解释和独立限制的真实性仍需出处与后续证据；结构检查不能识别所有同义重命名或证明语义等价。
3. 混合语义提案保存为 F2/调查待办，不部分提交。F2 改变版本后，旧 scope 提案须匹配新版本或重新提出，不自动重放过期提案。
4. 分包只在能保持必要闭包时进行；单个过大的相关对象/材料仍可能受阻。更小读取计划需明确请求和理由，不自动裁剪必要范围或提高额度。
5. Go 定位器仍是有限索引，未实现完整类型系统。当前新增解析只覆盖实测问题，没有扩大到任意 Go 语法保证。
6. 原 G_recovery 的捕获、存储、压缩、恢复和安装不是一个已覆盖整体；原目标/义务集合也不是完整性证明。活性、存储断电契约和未探索职责仍明确未覆盖。
