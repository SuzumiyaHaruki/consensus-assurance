# 测试与打包

项目回归分为单元、集成与端到端测试。mock 只替换 agent 响应，不关闭图校验、来源约束或执行权限；真实 TLC 测试用 `real` 标记，缺工具时明确跳过。

```bash
.venv/bin/python -m pytest -q tests/unit
TLC_JAR="$PWD/.tools/tla2tools.jar" .venv/bin/python -m pytest -q
env -u TLC_JAR .venv/bin/python -m pytest -q
```

Java/TLC 可能需要本机 socket；禁止该能力的环境会产生工具错误，不应被当作协议反例。按执行环境要求授权必要的本机能力，不能修改结果解析器把错误改成通过。

## 回归来源

- `examples/toy_protocol` 和机制夹具是预设的框架测试，不是生产实现发现。
- `tests/fixtures/recorded_repair` 保存少量已公开历史回复和状态摘录，来源见其 provenance.json。测试不依赖 runs 中的完整旧目录；摘录不用于默认 discovery。
- 正例、模型反例、触发见证、轨迹兼容、实际违反及缺工具分别断言；一个阶段完成不能替代下一阶段。
- 测试只使用临时目录或隔离副本，不修改原始分析仓库，不调用真实付费 agent。

## 安装资源检查

使用独立、没有旧构建缓存的源码副本构建 wheel，在项目目录外安装并检查 CLI、全部任务路由、技能引用及输出 schema：

```bash
.venv/bin/python -m pip wheel --no-deps --no-build-isolation --wheel-dir /tmp/consensus-wheel .
.venv/bin/python -m pip install --no-deps --target /tmp/consensus-installed /tmp/consensus-wheel/*.whl
cd /tmp
PYTHONPATH=/tmp/consensus-installed /tmp/consensus-installed/bin/consensus-assurance --help
```

应核对 wheel 不包含 runs、旧模板、凭据或本地权限覆盖。新模板内容必须通过实际 renderer 检查，不能只检查扩展名或全文件 ASCII。

## 盘点与清理

`scripts/project_inventory.py <输出.json> [源码根目录]` 分列生产 Python、测试、技能、文档和运行制品，并列出最大模块的静态调用表达式。物理字节/行数不是 token 或费用，运行制品不算代码体积。

清理 runs 前检查活动锁，保留指定归档；若回归引用旧运行，先迁移最小、明确标记的录制输入。Git 中已存在的历史记录仍可从对应提交读取，不通过重写历史做空间清理。


## 当前工作集和分阶段模型

新增测试入口为 `tests/unit/test_worksets.py`、`test_source_partition.py`、`test_current_conditions.py`，以及 `tests/integration/test_model_components.py`、`tests/e2e/test_staged_models.py`。使用真实项目类型和控制器；只有规划回复用明确标记的合成 responder，TLC/源码读取/隔离 harness/校准真实执行。当前验收记录和命令见 [工作集与阶段产物](工作集与阶段产物.md)。

离线工作集重建使用 `scripts/replay_worksets.py`，明确指定保留 run，输出到独立新目录，不调用 agent。它不等于重新发现目标。完整运行时模板由唯一 manifest 加载；`HarnessReply` 和复核修订 schema 的独立安装检查应在项目外目录执行。
