# 扩展接入

核心和工作流只依赖通用类型及接口。通过 `registry.py` 的静态注册表和配置装配，不需要插件市场或第二条分析流程。

## 实现适配器

实现 `ports/interfaces.py` 的 `ImplementationAdapter`：识别仓库、组织工具版本/测试命令、提供 harness 类型和文件名、构建与观测条件。命令由 adapter 生成 argv，不执行 agent 返回的任意 shell 文本。

`required_inputs(repo)` 声明构建必需资源，`symbol_hints(file, lines)` 可提供真实符号线索。通用层负责安全过滤、快照和材料来源；不能因为某资源不适合发送就静默删除执行必需文件。目标发现、义务和模型由通用工作流产生，adapter 不预置答案。

加入 `registry.IMPLEMENTATIONS` 后，通过配置选择实现；目标语言不能成为 core 的必填字段。

## 协议知识

协议包的 `knowledge()` 返回有出处的术语、候选关系和调查方法，注册到 `KNOWLEDGE`。默认 `protocol: none`，显式选择其他包只增加参考材料，不表示候选性质已适用。知识包不依赖 Codex，也不把具体 quorum 公式或消息类型固定到核心。

## Agent 后端与技能

实现 `probe` 和 `analyze`，输入为英文任务和阶段 schema，输出实际 CheckRun 及经过校验的提案。保存原始输出、实际能力版本和错误；不可用时不得自动切换收费渠道或调用隐藏 mock。

Codex 后端通过本地帮助探测支持的参数，沿用已有认证，不读取凭据。严格 wire schema 把开放字典编码为 key/value_json 条目，回传后恢复；不能为通过 schema 而清空非空参数。

维护方法时修改 `resources/skills/`，机械任务在 `resources/prompts/`，唯一加载路由为 `resources/task-skills.json`。控制器真正发送引用文本并保存加载 receipt；不假定独立调用记得前一任务或能打开本地链接。

结构化修复采用 OutputRepair；替换、来源请求、保全拆分与显式草稿范围提案各自保留来源和限制。坏 patch 不能替代原候选。修改既有判断仍经过实际 diff、ScopeUpdate/F2 及事务验证。

## 验证后端与观测

实现 `probe`、`check`、`calibrate` 及适用时的 `reachability`，注册到 `VERIFIERS`。执行状态与语义结果分开；不支持的检查必须报告未知或缺失，不能标为成功。轨迹校准需要可执行语义，不用 agent 评分替代。

checker 显式关联主张和范围。observation 的 model_field/raw_field/source 支持标量状态、事件和元数据投影。扩展监测性质时同时实现共享谓词生成、实际事件判定和工具正反例，不能因为 monitor 的 checker_id 相同就自动确认实现违反。

Binding.associations 与 unit.code_uses 分别记录职责和本单元用途。新语言需要可验证的定位支持；不能用注释中的任意词绕过符号身份。上下文方法和触发配置沿同一模型入口使用，不强制不同协议都有同样 round 或故障种类。

## 扩展验收

分别测试 mock 流程、预设模型、录制回复、真实工具和真实自主分析。保留权限关闭、缺工具、非法输出、范围变化、证据过期及恢复测试；新协议样例只能证明接入机制，不能宣传为多个生产协议均已验证。测试方法见 [测试与打包](测试.md)。
