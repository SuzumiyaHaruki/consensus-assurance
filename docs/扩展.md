# 扩展接入

核心和工作流只依赖通用类型及接口。通过 `registry.py` 的静态注册表和配置装配，不需要插件市场或第二条分析流程。

## 可选执行后端与目标配置

AgentBackend 适配 Codex/Mock 的调用与结构化输出；ExecutionBackend 只适配工具链执行。本轮仅维护 Codex，没有新增 Claude。静态注册表为 AGENTS、VERIFIERS、EXECUTION_BACKENDS、KNOWLEDGE。

`execution_backend` 选择 `none`（默认）、`go_module` 或 `python`。无执行后端仍可快照、导航、发现、候选来源审查及 ModelDraft/TLC；只有直接执行或实现校准明确受阻。后端不识别目标仓库、不提供符号提示、不预置性质；通用 catalogue 仍从可读源码提取声明线索。

新 Go 目标只需配置 `target.expected_module`（可选身份断言）、`variant`、`analysis_roots`、`execution_package`、`harness_path`，并显式传入 `--repo` 或 `repo_path`。HashiCorp 已使用通用 Go 后端，Toy 使用 Python 后端；不再维护一仓库一 Python adapter。命令仍由可信后端组成 argv，agent 不能提交任意 shell。

Go 后端使用离线依赖缓存和工作区内 GOCACHE。编译探测 `go test -json -run '^$' ./...` 只建立 package_build 能力，即使仓库没有测试也不会被误判为协议测试通过。harness 在配置的目录使用实际源码包声明，以 TestAssurance 前缀选择；precise_schedule_replay 仍不可用。

`Snapshot.files` 保留全部安全构建文件；`readable_files` 是其经过 analysis_roots 再收缩的源码证据范围。配置不能重新开放敏感文件。兄弟算法目录留在构建副本中，但 catalogue、初始材料与精确读取均不可越过可读边界。根 README/main/run 文件提供导航，不授权读取兄弟实现。

## 协议知识

协议包的 `knowledge()` 返回有出处的术语、候选关系和调查方法，注册到 `KNOWLEDGE`。默认 `protocol: none`，显式选择其他包只增加参考材料，不表示候选性质已适用。知识包不依赖 Codex，也不把具体 quorum 公式或消息类型固定到核心。

## Agent 后端与技能

实现 `probe` 和 `analyze`，输入为英文任务和阶段 schema，输出实际 CheckRun 及经过校验的提案。保存原始输出、实际能力版本和错误；不可用时不得自动切换收费渠道或调用隐藏 mock。

Codex 后端通过本地帮助探测支持的参数，沿用已有认证，不读取凭据。严格 wire schema 把开放字典编码为 key/value_json 条目，回传后恢复；不能为通过 schema 而清空非空参数。

维护方法时修改 `resources/skills/`，机械任务在 `resources/tasks/`，唯一加载路由为 `resources/task-skills.json`。控制器真正发送引用文本并保存加载 receipt；不假定独立调用记得前一任务或能打开本地链接。

结构化修复采用 OutputRepair；替换、来源请求、保全拆分与显式草稿范围提案各自保留来源和限制。坏 patch 不能替代原候选。修改既有判断仍经过实际 diff、ScopeUpdate/F2 及事务验证。

## 验证后端与观测

实现 `probe`、`check`、`calibrate` 及适用时的 `reachability`，注册到 `VERIFIERS`。执行状态与语义结果分开；不支持的检查必须报告未知或缺失，不能标为成功。轨迹校准需要可执行语义，不用 agent 评分替代。

checker 显式关联主张和范围。observation 的 model_field/raw_field/source 支持标量状态、事件和元数据投影。扩展监测性质时同时实现共享谓词生成、实际事件判定和工具正反例，不能因为 monitor 的 checker_id 相同就自动确认实现违反。

Binding.associations 记录职责关联；单元选择代码位置，额外上下文由选定的真实依赖路径解释。直接关联不需要依赖边。新语言需要可验证的定位支持；不能用注释中的任意词绕过符号身份。上下文方法和触发配置沿同一模型入口使用，不强制不同协议都有同样 round 或故障种类。

## 扩展验收

分别测试 mock 流程、预设模型、录制回复、真实工具和真实自主分析。保留权限关闭、缺工具、非法输出、范围变化、证据过期及恢复测试；新协议样例只能证明接入机制，不能宣传为多个生产协议均已验证。测试方法见 [测试与打包](测试.md)。
